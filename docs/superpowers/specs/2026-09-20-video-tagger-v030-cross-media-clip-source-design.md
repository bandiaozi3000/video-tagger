# 跨媒体片段来源（同系列借片段）— 设计规格

- 日期：2026-09-20
- 状态：**已批准**（用户 2026-09-20「看你建议」）；执行计划见 `docs/superpowers/plans/2026-09-20-video-tagger-v030-cross-media-clip-source-plan.md`
- 定稿决策：白名单 `主线故事/番外篇/前传/续集/剧场版/角色出演/同一世界观`（**去掉「其他」**）；0 片段的关联条目不列出；成片显示来源行（仅借来的）；来源切换放片段面板顶部
- 起因：用户问「假如我想把和某部作品关联的片段加入能实现吗？比如番剧 XX，片段我想加入的 XX OVA 里的某一部分」

## 1. 需求与实测依据

### 1.1 用户诉求

推荐位放的是《番剧 XX》，但想用的片段来自它的 **OVA**（在 Bangumi 上是**另一个条目**，因此在本库里是**另一个媒体**）。

### 1.2 实测（DB 查询，2026-09-20）

以《草莓棉花糖》为例：

| 媒体 | 类型 | 片段数 |
|---|---|---|
| 6917 草莓棉花糖（TV 2005，12 集） | 本体 | **0**（每集 0） |
| 6648 草莓棉花糖 OVA 第2期 | 独立媒体 | **1** |
| 6672 OVA 第1期 / 6649 OVA 3卷 / 6323·6324 Encore | 独立媒体 | 0 |

`external_work.relations_json` 里 **6917 的 21 条关联**中，两条「番外篇」**能反查到本地媒体**：

```
番外篇  草莓棉花糖 OVA 第1期 → 本地 media#6672
番外篇  草莓棉花糖 OVA 第2期 → 本地 media#6648
（其余 19 条是 广播剧/角色歌/游戏/片头片尾曲/书籍 → 与"借片段"无关）
```

全库 **124/125** 个媒体有 `relations_json`，媒体详情页已在用（`app.js` 的 `meta.relations`）。

### 1.3 场景划分（本期范围）

| 场景 | 说明 | 本期 |
|---|---|---|
| A | OVA 是本体媒体的一个 **episode** | **已支持**（片段面板直接选） |
| **B** | OVA 是**独立媒体**，与本体有视频类关联 | **本期做** |
| C | 完全不相关作品的片段 | **不做**（卡片资料与片段对不上，统计/年份/集数会失真） |

## 2. 非目标

- 不做「任意跨媒体挂片段」（场景 C）；来源必须过**视频类关联白名单**。
- 不做「一个卡片位挂多个媒体」（系列合并/编组）——那是另一个量级的改动，本期用「借片段」覆盖同一诉求。
- 不改推荐清单的媒体集合语义：被借条目的媒体**不进 `ids`**、不出现在片单里，只作为**片段来源**。

## 3. 现状约束（为什么现在做不到）

```
① 编辑器片段面板只列 /api/clips/media/{mediaId}                       （看不到别的条目）
② RecommendClipSourceService.loadClips(:251) 只查 listByMedia(mediaId)  （借不到）
③ RecommendClipSourceService:88 硬校验「片段不存在或不属于所选媒体」    （会被拒）
```

## 4. 数据模型（草稿契约，向后兼容）

`mediaClips[key]`：

```jsonc
{
  "order": [181, 902],          // 顺序语义不变
  "badge": { ... },
  "sources": { "902": 6648 }    // 新增，可选：clipId → 来源 mediaId（缺省 = 本体）
}
```

- 判定：`sources[clipId]` 缺失或 == 本体 mediaId → 本体片段；否则为借来的片段。
- **旧草稿、旧模板、旧预设一律无此字段 → 行为与今天完全一致**（默认本体）。
- 编辑器保存/套用模板时原样带 `sources`。

## 5. 后端改动

### 5.1 新端点 `GET /api/media/{id}/related`

返回**本地存在且有片段**的同系列条目：

```json
[{ "mediaId": 6648, "title": "草莓棉花糖 OVA 第2期", "relationType": "番外篇", "year": 2007, "clipCount": 1 }]
```

- 数据：`external_work.relations_json`（已有解析能力：`MetadataRelationRecord`）+ `external_id → media_id` 反查。
- **视频类关系白名单**（常量，可调）：`主线故事 / 番外篇 / 前传 / 续集 / 剧场版 / 角色出演 / 其他`；
  过滤掉 `片头曲 / 片尾曲 / 广播剧 / 角色歌 / 插曲 / 原声集 / 游戏 / 书籍 / 画集` 等。
- 自引用（关联到自己）过滤；同一 `external_id` 命中多个本地行时取第一个。
- 实现放 Java 侧解析（不用 MySQL `JSON_TABLE`）——**兼容 SQLite 轨道**。

### 5.2 `RecommendClipSourceService`

- `loadClips`：本体 `listByMedia` 找不到时，按 `sources[clipId]` 指定媒体再查一次；仍没有 → 记 missing。
- 校验三段，错误文案要能区分：
  | 情况 | 文案 |
  |---|---|
  | 库里没有这个片段 | `片段不存在` |
  | 有，但没 `sources` 且不属于本体 | `片段不存在或不属于所选媒体`（保留旧文案） |
  | 有 `sources`，但来源与本体**没有视频类关联** | `片段 #N 与《本体标题》没有视频类关联` |
- `PreparedClip` 增加 `sourceMediaId` / `sourceTitle`（供视图与编辑器角标）。
- 物化：借来的片段走**同一条** `prepareOne`（裁剪/重编码到会话目录），无额外逻辑。
- 校验需要"本体与来源是否有视频类关联"→ 复用 5.1 的解析（抽成一个可缓存的纯函数）。

### 5.3 `RecommendService.buildRenderInput`

- 片段视图新增 `sourceTitle`（**仅当** `sourceMediaId != 本体`），例如 `"sourceTitle": "草莓棉花糖 OVA 第2期"`。
- 其它字段（`episodeNo`/`durationMs`/`hasAudio`…）取**片段自身**的行，不受来源影响。

## 6. 渲染侧（Remotion）

**核心省力点**：借来的片段被放进**卡片媒体的 `clips` 数组**里，于是

- `cinema/plan.ts:200`、`scene-plan.ts:111` 的 `media.clips.find(...)` **天然命中** →
  **不需要全局片段索引改造**；
- 片段幕时长仍取 `clip.durationMs`（片段自身的长度）→ 不需改；
- `stats.clips` 计数不变。

需要动的只有**显示**：

- `ClipShot` 信息卡（`cinema/scenes.tsx`）：`EP.xx · 时长` 那行追加 `来源：{sourceTitle}`，**仅借来的片段显示**；
- 章节模板 `ClipScene` 同理（同一字段，保持两套模板一致）。

## 7. 编辑器改动

1. **片段面板顶部加来源切换**：`来源 [本体 N] [同系列 M]`；`M=0` 时置灰并提示「关联条目还没进库 / 还没打片段」。
2. **同系列页**：按 `relationType` 分组 → 条目（标题·年份·片段数）→ 片段（集号/标签/备注）+「加入」。
   - 加入 = 写 `order` + `sources[clipId] = sourceMediaId`。
3. **角标**：片段列表与胶片条卡上标 `来源：X`（`labelOf` 追加短名）。
4. **移除**：沿用同一套 `✕`（`withoutClip`）→ 同步删掉 `sources[clipId]`。
5. **缺失复用**：借来的片段被删 → 现有「素材缺失」链路（卡上 `✕ 移除` + 右栏置顶列表）直接可用，提示里带上来源名。
6. 来源标题在刷新后仍需可见 → 对"含借用片段的媒体"各调一次 `GET /api/media/{id}/related`（个位数请求）。

## 8. 边界与错误

- 关联条目本地没有 / 有 media 但 0 片段 → 不进列表（`clipCount=0` 可显示但置灰，二选一，倾向**不进列表 + 提示计数**）。
- 借来的片段事后被删 → 走「素材缺失」，不静默。
- 关系白名单太窄导致找不到条目 → 列表底部给一行提示 + 「去素材库看关联」的引导（不复用素材库的关联 UI，只给文字指引）。
- 同一 `external_id` 命中多个本地 media → 取第一个（可后续改）。
- 模板/预设导入导出：`sources` 随 `mediaClips` 走，无需额外处理。

## 9. 验收口径

- **Java 单测**：`loadClips` 借片段命中；三种拒绝文案；`related` 的白名单过滤与自引用过滤（MockMvc + mock service）。
- **TS 单测**：借来片段的标签/角标拼接；`plan` 里借片段幕时长 = 片段自身 `durationMs`。
- **端到端手测**：草莓棉花糖 → 加入 OVA 第2期那个片段 → 预览里出现该片段幕、ClipShot 显示来源 → 导出成片正常、清单统计不变。
- **回归**：不借片段时，`render-input.json` 与今天逐字节一致（旧草稿快照对比）。

## 10. 风险与回滚

| 风险 | 处置 |
|---|---|
| 契约加键影响别的消费者 | 只加可选键；桌面轨道已冻结（不读该键） |
| 关系白名单过窄 → 用户找不到 | 白名单做成常量 + 列表给"为什么没列出来"的提示 |
| 借片段的素材准备失败（来源素材缺失） | 走既有 `missing` 机制，不新增失败模式 |
| 回滚 | 去掉 UI 入口即可：后端忽略 `sources` = 旧行为（保留兼容代码） |

## 11. 交付顺序（批准后写进执行计划）

1. 后端：`related` 端点 + `loadClips` 借片段 + 校验 + `sourceTitle` 透传（含单测）
2. 编辑器：来源切换 + 角标 + 移除联动
3. 渲染：`ClipShot` / `ClipScene` 来源行
4. 文档：`docs/rules.md` 契约说明 + 工作日志
