# Video Tagger 双图封面设计总结（缩略图 + 详情大图 + 悬浮预览）

- 日期：2026-08-03
- 状态：确认实施（用户直接拍板，无待确认项）
- 关联文档：实施计划 `plans/2026-08-03-video-tagger-dual-cover-plan.md`
- 前情：v0.4 片段截帧封面（320px 缩略图）、v0.5 详情页。本次把片段封面拆成**两张图**：列表缩略图 + 悬浮/详情大图。

## 1. 背景与定位

v0.4/v0.5 后片段只有一张 320px 缩略图，悬浮/详情页放大后画质不足。用户要求：

- **每片段存两张图**：缩略图 + 详情大图。
- 列表展示缩略图（现状左侧缩略图横排不变）。
- **鼠标悬浮缩略图 → 弹出详情大图预览**。
- 片段详情页的大图用详情图。

定位延续「工具 + 练手」：纯展示增强，canvas 一次画两档，成本极低。

## 2. 已确认决策

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 缩略图规格 | 维持 320px 宽 JPEG 0.7（现状）。 |
| 2 | 详情大图规格 | **min(videoWidth, 1280) 宽 JPEG 0.75**；悬浮预览 ~360px 展示 + 详情页 hero，1280 足够锐利。 |
| 3 | 存储 | `clip/{clipId}.jpg`（缩略）+ `clip/{clipId}-xl.jpg`（详情），`clips.detail_cover_path` 可空列（V7）。 |
| 4 | 悬浮预览 | 全局悬浮层，锚定在缩略图右侧展示详情大图；**无详情图时回退缩略图**（历史数据无详情图，属预期）。 |
| 5 | 详情页 | 片段详情 hero 用 `detailCoverPath || coverPath`。 |
| 6 | 生命周期 | 删片段时两张图一并删除。 |
| 7 | 范围 | 片段卡片（`.cc-thumb`）；集/番剧封面暂不做双图（后续可按同样命名模式扩展）。 |

## 3. 数据模型变更

```sql
-- V7__detail_cover.sql
ALTER TABLE clips ADD COLUMN detail_cover_path VARCHAR(512) NULL;
```

## 4. 传输链路

- 扩展 `captureFrames(video)` 一次 `drawImage` 两档 → `{ thumb: dataUrl, detail: dataUrl }`。
- `SaveClipRequest` 增 `detailCoverDataUrl`（`@Size(max=900_000)`，1280px base64 约 200KB，留余量）。
- 后端：缩略 + 详情两个 data URL 各自解码落盘；**任一步失败降级**（缩略失败 → 两图皆无；详情失败 → 仅有缩略），不反噬保存。

## 5. 前端悬浮预览

```
[缩略图 128px]  ← mouseenter
     │
     ▼
┌────────────────┐
│  详情大图预览    │  （锚定在缩略图右侧，越界自动左移）
└────────────────┘
```

- 全局 `#vt-hover-preview` 悬浮层（fixed），`mouseenter` 设图显形、`mouseleave` 隐藏。
- 详情图懒加载（首悬浮才拉取）。

## 6. 风险与注意点

1. **历史数据无详情图**：旧片段 `detailCoverPath` 为空 → 悬浮回退缩略图，属预期非 bug，不做回填（无视频源）。
2. **payload 体积**：保存请求从 ~40KB 涨到 ~250KB（缩略+详情 base64），个人工具 + 本地后端可接受；上限校验防畸形。
3. **存储增长**：每片段缩略 ~30KB + 详情 ~150KB，千片段 ~180MB，本地磁盘可接受。
4. **悬浮层 z-index**：须高于卡片与弹窗，低于打标浮层（2147483647），取 2147483646 附近。

## 7. 范围界定（YAGNI）

本期不做：详情图回填/重生成、图片懒加载缓存淘汰、集/番剧双图、悬浮跟随光标移动。
