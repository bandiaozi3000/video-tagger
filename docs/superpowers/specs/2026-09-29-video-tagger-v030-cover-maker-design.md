- 日期：2026-09-29

- 相关：设计探索过程见 `.tmp/v3 ~ v7` 的 mockup 与本文附录（原指向的 `docs/rules.md` 规则节已于 2026-10-02 删除，见 git `769ed56`）

## 1. 目标与非目标

### 目标
**把已选片段的「片段封面」拼成一张 16:9 投稿封面**（1920×1080），附带标题/副标题，用于 B 站 / YouTube 投稿。

- 素材来源：**片段已有的封面图**（`covers/clip/{clipId}-xl.jpg`），用户**勾选**参与拼版的片段
- 文字：**只有标题 + 副标题**两级，别的文字一律不加（用户明确要求）
- 版式：V3/V4/V5 三轮探索出的 **22 套版式全支持**（见 §4）
- 文字位置：**可选**（九宫位置 + 对齐 + 安全区自动校验，见 §5）
- 常用模板：可把「版式 + 文字参数」存成自己的常用模板复用（见 §9）

### 非目标（本期不做）
- 不做视频封面 / GIF 封面
- 不做 3:4 竖版（抖音/小红书）——预留但不在本期
- 不做抠图（破格出血的精确版）——本期用蒙版近似，见 §4 T14
- 不改动现有媒体封面 / 集封面 / 片段封面的取值链（§「媒体封面取值链」保持不变）

## 2. 术语

| 术语 | 含义 |
|---|---|
| **片段封面** | `covers/clip/{clipId}.jpg`（缩略图）与 `-xl.jpg`（大图）。工坊**只用 `-xl`** |
| **版式（切法）** | 帧在画布上的排布结构，22 套，编号 `T01`~`T22` |
| **文字处理** | 文字的加工方式：普通压底 / **R8 双层重影** / 竖排 / 色带横贯 / 图片填充 / 挖空 |
| **位置** | 文字块在画布上的锚点（九宫）+ 自由偏移 + 对齐 |
| **常用模板** | 用户保存的一套参数组合（版式 + 文字处理 + 位置 + 字号…），可一键复用 |

## 3. 用户流程（**入口形态已定稿**：与「导出清单」合并成一个按钮）

### 3.1 UI 形态

**入口**：推荐编辑器「候选库」pane 工具栏右侧那个按钮（现在叫 `📋 导出清单`）——**对外仍是同一个按钮**，标签改成 `📋 导出`（或 `📋 清单 / 封面`，见 §12-1）。

```
点按钮 → 弹窗（vt-overlay + vt-panel，沿用现有弹窗骨架）
   ┌─────────────────────────────────────────────┐
   │ [ 📋 导出清单 ] [ 🖼 设置封面 ]   ← 顶部两个 tab │
   ├─────────────────────────────────────────────┤
   │  选中 tab 的内容                              │
   └─────────────────────────────────────────────┘
```

- **tab 1「📋 导出清单」= 现有内容原样搬进 tab**（`ExportListDialog` 的取数/勾选/预览/复制/下载逻辑不动，只把它从"独占弹窗"降级为"弹窗里的一个 tab"）
- **tab 2「🖼 设置封面」= 新增**（本规格的主体）
- 弹窗宽度按 tab 自适应：清单 tab 保持现宽；**封面 tab 用宽版（~1280px）**，内部三栏 =
  **左：参数**（版式 / 文字 / 位置 / 处理）· **中：预览**（1920 缩放的 16:9 画布）· **右：素材**（片段勾选）
- 封面 tab 右下角 = **主按钮「导出封面」**（把当前预览落盘、入库、给下载入口），次要动作「存为常用模板」
- 关闭弹窗 = 放弃未导出的参数（是否随草稿记住见 §12-7）

### 3.2 封面 tab 内的操作顺序

```
① 素材：默认预勾「当前草稿已挂载的片段」（= config.mediaClips，即「已选」里挂过的）
   └ 片段列表：封面缩略图 + 片段名 + 所属媒体 + 勾选状态；支持搜索 / 按媒体筛选
   └ 可在 tab 内继续加选（复用片段搜索接口），跨媒体不限
② 版式：22 套缩略图墙（§4）；也可点「按所选张数自动选」
③ 文字：标题 / 副标题（**默认带出草稿的 title / subtitle**，可手改）
   └ 改草稿后**不自动重出**已生成的封面，需手动点「重新生成」
④ 参数：位置（九宫）/ 对齐 / 字号 / 处理（默认 R8 双层重影，偏移 4px）
   └ 命中危险位时给出提示 + 「回到安全位」按钮（§5 安全区校验）
⑤ 预览：改参数即时重出预览（预览可用低分辨率快渲；点「导出封面」才出 1920×1080 成品）
⑥ 导出封面：落盘 covers/make/{id}.jpg + 入库 → 弹「下载」入口
```

**为什么这样切**：素材（`config.mediaClips`）与文字（`config.title/subtitle`）**本来就在这个编辑器里**，所以封面不另起页面、不另拉一套数据，直接复用当前草稿的上下文；用户实际操作路径也就短了一步。

**其它入口**（可选，非必须）：片段详情 / 媒体详情里加「去设置封面」→ 打开推荐编辑器并预勾这些片段。

- `按张数自动选`：1 → T04；2 → T12；3 → T11；4 → T01；5 → T05；9 → T07
- 张数不够目标版式：**自动降级**到张数足够的最近版式（不留空框）
- 张数超出：按「推荐等级优先 → 有片段的优先 → 勾选顺序」截断
- T22 特殊：只需 1 个片段（自动对该片段抽 4 帧）

## 5. 文字系统

### 字体
| 用途 | 字体 | 来源 |
|---|---|---|
| 主标题 | **阿里巴巴普惠体 2 115 Black** | 项目已内嵌 `backend/remotion/public/fonts/` |
| 副标题 | **思源黑体**（可变，用 300/400 权重） | 需**新增进项目字体目录**（SIL OFL，可随项目分发；注意体积 ~17MB） |
| 数字/拉丁 | Mona Sans | 已内嵌 |

> 用户确认：「字体按图片字体就行」= 主标题用 mockup 里那个（普惠 115 Black）。

### 字号阶梯（按版式给上/下限，不自由放飞）
| 元素 | 字号 | 行高 | 字距 |
|---|---|---|---|
| 主标题 | 88 / 96 / 104 / 120 / 150（按版式取） | 1.03~1.06 | -0.01em |
| 副标题 | 30~32 | 1.4 | **+.22em** |

### 位置（**可选**，用户点名要的能力）
- **锚点**：九宫（左上/上中/右上/左中/正中/右中/左下/下中/右下）
- **自由微调**：x / y 偏移（以 200px 为安全下限自动钳位）
- **对齐**：左 / 居中 / 右（与锚点独立）
- **承托自动跟随**：锚点在下 → 底部渐层；在上 → 顶部渐层；在左中 → 左侧渐层；纯色栏版式自带承载
- **副标题相对位置**：主标题上方（默认）/ 下方

### 安全区校验（选位后实时提示，可一键回安全位）
| 区域 | 来源 | 规则 |
|---|---|---|
| 右下 400×150 | B 站时长角标 / 水印 | 关键文字不得进入 |
| 右上 | 热门 / 联合投稿实心遮罩 | 同上 |
| 左右各 ~160px | **B 站 16:10 居中裁剪**（主页/排行榜） | 核心信息必须落在中央 1600×1000 内 → **左边距下限 200px** |
| 自查 | 官方建议 | 出图后缩到 **320×180** 与 **200×100** 两档检查可读性 |

### 文字处理（枚举）
| id | 处理 | 说明 | 320px 判定 |
|---|---|---|---|
| `plain` | 普通压底 | 白字 + 渐层 | ✅✅ |
| **`r8`** | **双层重影**（用户选定） | 白字 + 绯色偏移 `offset ∈ 0~8px`（默认 4，**0 = 关闭**） | △ 偏移 >6px 发虚；建议 ≤4 或只用在第一行 |
| `vertical` | 竖排 | `writing-mode: vertical-rl` | △ 仅当标题 ≤6 字 |
| `band` | 色带横贯 | 满宽实色带（主色取自底图）+ 白字 | ✅✅ 最醒目 |
| `clipText` | 图片填充字 | 字内是画面 | ❌ 仅限 ≥120px 的展示位，**不得用于主标题** |
| `knockout` | 挖空字 | 黑带里镂出画面 | ❌ 同上 |

**红线（写进实现校验）**：`楷体 / 重影偏移>6px / 图片填充 / 挖空` 出现在主标题且字号 <120px 时 → 前端阻止提交并说明原因（依据是 320px 判定实测）。

## 6. 素材准备管线

1. 取 `covers/clip/{clipId}-xl.jpg`（无 xl 则退回 `{clipId}.jpg`；都没有 → 该片段标「无封面」不可勾）
2. **裁掉原片内嵌字幕/名牌**：放大 ~1.43× 后取中央 16:9，等于**去掉顶部 10% + 底部 20%**
   （实测：183 顶部有「捏他：北斗神拳——拉奥」、底部有台词；不裁会直接毁掉专业感）
3. **统一调色**（让多张拼图像"一套作品"）：`saturate .88 / contrast 1.06 / brightness .97` + 全图一层 `14%` 冷黑罩
4. 输出中间图到会话目录（复用 `data/recommend-previews/<token>/` 同族做法，或独立的封面工作目录）

## 7. 出图技术选型

| 方案 | 评价 |
|---|---|
| **Chrome headless（选定）** | 今天的 22 套 mockup **就是它渲的**（系统 Chrome + `--headless=new --screenshot --window-size`，零新依赖）。版式用 HTML/CSS 表达最省事，`background-clip:text`、`mix-blend-mode`、`clip-path`、`writing-mode` 全部原生支持 |
| Remotion still | 项目已有，但要把 22 套版式改成 React composition + props 管线，工作量数倍；出图是"一次一张"，不需要逐帧能力。**留作将来做"动态封面"的迁移路径** |
| 纯 Java（ImageIO/Java2D） | 中文排版与 CSS 级效果（mask/blend/clip）做不到，否决 |

**落地形态**：
- 版式模板：`backend/scripts/cover/templates/*.html`（22 个，含 `{{参数}}` 占位）
- 出图脚本：`backend/scripts/cover/render-cover.mjs`（Node，调系统 Chrome）
  - 关键参数：`--headless=new --hide-scrollbars --allow-file-access-from-files --force-device-scale-factor=1 --window-size=1920,1080 --virtual-time-budget=<等字体图片> --screenshot=<绝对路径>`
  - ⚠️ 今天的实测坑：`--screenshot` **只吃 Windows 绝对路径**；字体与图片必须与被渲页面**同源**（跨盘 `file://` 引 `C:\Windows\Fonts` 会被挡 → 字体必须放项目内）
- Java 侧职责：准备素材（裁剪/调色可用 ffmpeg）→ 生成参数 JSON → 调脚本 → 落盘 → 入库
- 配置项：`videotagger.cover-scripts-dir`、复用已有的 `videotagger.render.chrome-path` / `ffmpeg-path`

## 8. 数据与存储

### 文件
- 目录：`data/covers/make/`（**新增子目录**，与 `clip/`、`ep/`、`ext/` 并列）
- 命名：`{id}.jpg`（`id` = DB 主键，天然可复现 / 可覆盖）
- 规格：1920×1080、JPEG q88、目标 ≤1.5MB（B 站上限 5MB）
- 访问：复用既有 `/covers/**` 静态映射（WebConfig）→ `/covers/make/{id}.jpg` 直接可用

### 表（Flyway **V42**，只维护 MySQL 侧，SQLite 已冻结）
```sql
create table cover_asset (          -- 生成过的封面
  id bigint primary key auto_increment,
  title varchar(200) not null,
  subtitle varchar(200),
  template_id varchar(16) not null, -- T01..T22
  config_json text not null,        -- 生成参数（版式+文字+位置+素材），供二次编辑
  file_path varchar(255) not null,  -- covers/make/{id}.jpg
  width int not null, height int not null,
  created_at bigint not null
);
create table cover_template (       -- 用户「常用模板」
  id bigint primary key auto_increment,
  name varchar(80) not null,
  config_json text not null,
  sort_no int not null default 0,
  created_at bigint not null,
  updated_at bigint not null
);
```
内置 22 套版式**不入库**（写死代码）；`cover_template` 只存用户自己攒的组合。

## 9. 常用模板

- 保存：「存为常用模板」→ 填名字 → 存 `config_json`（版式 + 文字处理 + 位置 + 字号 + 素材筛选来源），**不存具体片段**（素材每次重新勾）
- 应用：模板列表（卡片：名字 + 版式缩略图 + 文字处理标签）→ 一键套用参数
- 管理：改名 / 排序 / 删除（删除不影响已生成封面）
- 与现有 `recommend-preset`（推荐草稿/模板）**同族做法**，但**不复用它的表**（语义不同：那个是渲染参数，这个是封面参数）

## 10. 失败兜底

| 情况 | 处理 |
|---|---|
| 勾选张数 < 目标版式 | 自动降级版式并提示（不留空框） |
| 片段无封面文件 | 该片段不可勾（列表里灰显 + 原因） |
| Chrome 不存在 / 启动失败 | 报「封面出图不可用：未找到 Chrome」（复用 `videotagger.render.chrome-path`） |
| 出图超时 | 超时杀进程 + 清理临时目录（复用渲染子进程的看活/超时参数族） |
| 素材被删（跨会话） | 会话目录 per-token，过期即清；生成的成品在 `covers/make/` 不受影响 |
| 并发 | 出图串行（一次一张，前端按钮置灰），不做并发队列 |

## 11. 验收标准

1. **后端单测**：版式选择/降级、张数截断、安全区校验、参数归一化（字号/偏移钳位）、配置序列化往返
2. **真实出图验收**：用真实片段封面把 **22 套版式各出一张**，逐张做三项检查：
   - 缩到 **320×180** 标题仍可读
   - **灰度**下文字与底图不糊成一片
   - **16:10 居中裁剪**后标题完整（不被吃掉首字）
3. UI 链路：勾选 → 参数 → 生成 → 预览 → 存模板 → 套用模板，真实浏览器走一遍
4. `mvn test` 全绿 + `npm test`（remotion 侧，若动到）

## 12. 遗留风险与待你决定

1. ~~入口位置~~ → **已定**：与「导出清单」**合并成一个按钮**（候选库工具栏那一排），点开是弹窗里的两个 tab（导出清单 / 设置封面）。**仅剩按钮标题待定**：`📋 导出` / `📋 清单 · 封面` / 保持 `📋 导出清单`（tab 里再分）
2. **是否要「设为媒体封面」**：出图后一键写进 `media.cover_path`（会进现有封面取值链最高优先级）？——涉及既有链，建议**先不做**
3. **3:4 竖版**（抖音/小红书官方要求横版视频也传 3:4）：本期不做，但要不要现在就把版式定义成"画幅无关"以便将来支持？
4. **破格出血（T14）/剪影填图**要抠图：本期蒙版近似（人物边缘不是精确轮廓）。将来要精确就得上分割模型（rembg / U²-Net / 云 API）——**这是新依赖，需你单独授权**
5. **思源黑体入库**：17MB 可变字体进仓库可接受吗？不行则副标题退回普惠 115（小字号）+ 系统雅黑
6. **封面参数要不要随草稿保存**（草稿 `EditorConfig` 稀疏字段，如 `coverConfig`，零迁移）→ 好处：下次打开弹窗回填上次的选择；代价：会进渲染 props（渲染侧忽略，只是少量字节）。我倾向**存**，但请你点头。
7. **B 站官方规范**我只看到第三方整理（16:10 裁剪、实心遮罩位），**官方《投稿规范》原文未逐条核对** → 安全区规则先按第三方执行，标记为待核对

## 13. 建议分期（写执行计划时按这个切）
