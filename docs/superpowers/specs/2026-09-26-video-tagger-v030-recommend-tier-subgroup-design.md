- 前置事实：等级四档（`强推/推荐/值得一看/一般`）与视觉已在 2026-09-26 上线（`src/tier.tsx`、`docs/rules.md §32`）

## 1. 需求拆解

| # | 需求 | 口径 |
|---|---|---|
| R1 | 一级分组之后**再按推荐等级分组** | 一级保持现有 `groupBy`（不分组 / 按年份 / 按分类 / 按收藏夹），二级固定为**推荐等级**，档序 `强推 → 推荐 → 值得一看 → 一般 → 未分级` |
| R2 | 「本组核心」那一块去掉 | 组首的核心区（`MEDIA_INFO` / 大卡网格 + `★ 本组核心` 题头）整块删掉；第 1 档**靠二级分组本身**排在最前 + 卡片上的彩虹环/「强推」胶囊标识 |

R2 的因果：二级分组把第 1 档单独提到最前一群 → 原来"把核心拉到组首"的目的已由分组达成，再单独给一幕资料卡就是重复强调。

## 3. 设计

### 3.1 分组语义（两级，扁平化展开）

```
一级（现有 groupBy）        二级（新，推荐等级）
2013 年            ──┬── ✦ 强推        2 部
                     ├── · 推荐        3 部
                     ├── · 值得一看    1 部
                     └── （未分级）     0 部 → 不生成空组
2012 年            ──┬── ...
```

规则：

1. 一级分组**完全不变**（含「不分组」）；二级在一级结果内部再切。
2. 档序固定 = `RECOMMEND_TIERS` 顺序，**「未分级」永远垫底**。
3. **不生成空档**；整组全是「未分级」时**不切**（等价于没开二级分组）——保证"没标等级的老草稿"结构零变化。
4. 一级 = 不分组时二级仍生效 → 等效"全片按等级分组"，组名直接是档名。
5. 一级 = 分类 / 收藏夹时同样生效（与等级正交）。

### 3.2 场景层（改动最小路径）

`groupMedia` 内部切完两级后**仍返回一维 `GroupPlan[]`**（组名已带档名后缀），于是：

- 网格切屏、逐屏组头行、档色胶囊、章节页、时长、序号（组内从 1 数）**全部自动跟随，一行不用改**；
- 需要新增两个字段到 `GroupPlan`：`parentName`（一级组名）与 `firstOfParent`（是否该一级组的第一个子组），只为一件事服务 ↓

**章节页口径（建议）**：章节页仍**每个一级组一页**（标题用 `parentName`，即「2013 年」），并只在 `firstOfParent` 的子组前插；档与档之间**不插页**，靠每屏组头行换档。

- 组头行内容：`2013 年 · ✦ 强推 · 共 2 部` + 档位胶囊（该档色；现在是"该屏最多档"，切档后自然等于本档色）。
- 章节页数量与今天**相同**；成片只因为 R2（删核心区）而变短。

### 3.3 R2：删掉「本组核心」

| 项 | 处置 |
|---|---|
| `scene-plan.ts` 组首核心区整块 | **删**（含 `CORE_KICKER` 常量与其场景） |
| `coreFirst`（第 1 档排最前） | **留**（二级分组时是 no-op；一级=不分组 + 关二级时仍需要它保序） |
| `isCore` | **留**（「全片核心回顾」仍用它） |
| 第 1 档的视觉标识 | 卡片上的**彩虹环 + 「强推」胶囊**（已上线） |
| 时长影响 | 每个一级组合计少 0~N 幕 `detailSec` → **成片整体变短**（要在编辑器时长预估里如实体现，它本来就跟着 `buildScenePlan` 走） |

### 3.4 配置与管道

| 层 | 改动 | 备注 |
|---|---|---|
| 编辑器配置 | `EditorConfig.tierGroup: boolean` | `Layout` 组新增开关「按推荐等级再分组」+ 一行说明；位置在「分组方式」下方 |
| 渲染参数 | `RenderParams.tierGroup` ← `resolveParams`（默认真值随开关） | 渲染与编辑器共用一份 |
| 编辑器 → Java | `buildRenderInput` 多写一个 `params.tierGroup` | 需在 Controller / `RecommendVideoService` / `VideoExportTaskService` / config 解析处各透传一次（约 6 行） |
| 预览 | 编辑器预览走 `applyLocalParams`，**即时生效** | 后端没重启也能看到预览 |
| 导出 | 依赖 Java 透传 → **需重启后端一次** | 与 2026-09-26 那次同样的约束 |

### 3.5 兜底与边界

| 情况 | 行为 |
|---|---|
| 全片没有任何等级标注 | 二级分组自动"不切" → 与今天完全一致 |
| 某部媒体 `tier` 缺失 | 归入「未分级」群（垫底） |
| `tier` 值超出四档（脏数据） | 归入「未分级」（不崩、不新增档位） |
| `perScreen = 1` | 子组只有 1 部时仍走 `MEDIA_INFO`（资料卡）——现有分支不变 |
| 一级 = 不分组 + 二级关 | 完全等于今天（单组、无章节页） |

## 4. 验收方案

| 项 | 怎么做 |
|---|---|
| 单测 | `groupMedia` 新增用例：① 年份 × 等级 两级切分与组名；② 档序 + 未分级垫底；③ 全未分级不切；④ 一级 = 不分组时二级仍生效；⑤ `firstOfParent` 只标每级第一个子组 |
| 出帧 | 构造同年 4 档的 props → 帧序列里**同档连续**、组头行档名/档色正确、**无「★ 本组核心」屏**、章节页仍是每年一页 |
| 回归 | `npm run typecheck`、`npm test`（251 用例）、`mvn -o test`（461 用例） |
| 端到端 | 编辑器开开关 → 预览即时变化 → 重启后端后导出验证一次 |

---

## 5. 明确不做（YAGNI）

- 不做任意链式分组（年份 → 分类 → 等级），只做"一级 + 等级"这一层（用户只提了等级）。
- 不做二级维度的配置化下拉（不是"任选二级维度"，就固定为等级）。
- 不动等级名单 / 颜色 / 视觉（2026-09-26 已定稿）。
- 不接「银幕式」（`cinema`）形态：它不消费 `groupBy`，走自己的分幕结构；本次不扩面。
- 不改 `metaFingerprint` / 不涉及素材重取（那是另一条待办：「重新拉取素材未更新」）。
