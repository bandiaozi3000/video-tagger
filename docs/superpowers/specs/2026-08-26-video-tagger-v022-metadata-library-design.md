# v0.22 番剧资料库与片段资产化设计

- **日期**：2026-08-26
- **版本**：v0.22.0
- **状态**：首批垂直切片完成；同步中心 UX 重构设计已确认，待实施与真实验收
- **定位**：大版本；以番剧元信息、作品条目、集上下文为片段能力的上游基础
- **关联计划**：`docs/superpowers/plans/2026-08-26-video-tagger-v022-metadata-library-plan.md`
- **最后更新**：2026-08-29（同步中心与单媒体匹配交互重构）

## 1. 背景与目标

当前 `Media → Episode → Clip` 主要由浏览器网页标题被动归组。AniList/omofuna 历史同步只覆盖有限字段，缺少稳定外部身份、完整简介/别名/题材、具体条目和可靠集级资料。用户可以标记场景，却不能稳定表达片段属于哪个正式作品条目和哪一集，也不能安全地把已有媒体更新到远程最新资料。

v0.22 将 Bangumi 作为首个独立元信息 Provider，借鉴 Animeko 的外部 ID、作品/集资料边界、本地缓存、显式刷新和失败保旧策略，但不依赖 Animeko 自家 Ani API、不复制其 AGPL 代码。

目标链路：

```text
现有媒体页
→ 用户主动同步（指定番剧 / 年份 / 季度）
→ 外部资料预览
→ 一次确认导入或关联
→ Media → MediaEntry → Episode
→ 观看上下文绑定
→ Clip 继续作为本产品的标签/片段资产
```

## 2. 已确认产品决策

1. 普通搜索始终只查本地媒体库；不会因为搜索、列表、详情渲染而联网。
2. 同步入口保留在现有媒体页，不增加首页。
3. 空库通过媒体页同步入口按年份/季度批量初始化；预览后一次确认，不逐部确认。
4. 指定番剧同步实时查询外部候选；用户确认后才写入或关联。
5. 已有关联的媒体点击同步时，直接刷新当前具体条目和其集信息；无外部 ID 时必须先候选匹配。
6. 按年份/季度同步既能发现新作品，也能更新已有关联作品。
7. Bangumi 为 v0.22 首个主 Provider；AniList/omofuna 历史数据保持可读，但不再作为本版主同步路径。
8. 层级为 `Media（系列/用户容器）→ MediaEntry（具体外部条目）→ Episode → Clip`。
9. 关系中的续作、前传、OVA、特别篇、剧场版只保存关系边，不递归导入。
10. 远程新增集自动加入；远程改号/消失的本地集保留并标记异常，不删除 Episode 或 Clip。
11. 外部资料和用户资料严格隔离。同步不得覆盖个人标题、备注、评分、状态、标签、收藏、本地封面选择、视频 URL/指纹或 Clip。
12. 旧数据不凭标题自动写入外部 ID；相似标题只生成候选。历史 `Clip.episodeId` 可为空并继续兼容。
13. 远程视频源发现、下载、播放、裁剪、时间码校准属于 v0.23，不在 v0.22 实现。

## 3. 数据边界

### 3.1 用户实体

- `Media`：用户作品/系列容器和个人字段。
- `MediaEntry`：本地可见的具体条目容器，支持 TV 季、OVA、电影、特别篇等。
- `Episode`：具体条目下的集；旧 `media_id` 保留兼容，新数据增加 `media_entry_id`。
- `Clip`：已有用户标记数据，不因元信息同步重建或改写。

### 3.2 外部缓存实体

- `ExternalWork`：`provider + externalId` 唯一，保存规范化外部标题、简介、封面 URL、题材、格式、年份/季度、播出信息、集数、原始响应和同步状态。
- `ExternalEpisode`：外部集 ID、远程标题/简介/日期/时长、远程季集号、最近看见时间及 `ACTIVE/MISSING/RENUMBERED/CONFLICT` 状态。
- `ExternalRelation`：关系类型和目标外部 ID，仅用于展示和后续发现。
- 同步任务/候选：保存预览、一次确认和重启恢复所需状态。

远程资料存外部表，不覆盖 `Media.title/note/rating/status` 或 `Episode.title/note/url/videoFp`。旧 Episode 默认视为本地覆盖；远程新增 Episode 允许没有 URL 和 videoFp。

## 4. 同步行为

### 4.1 预览

```text
选择范围 → Provider 拉取 → 生成候选快照 → 用户审核
```

预览阶段不创建用户 `Media/MediaEntry/Episode`，也不更新正式外部缓存；只有草稿需要持久化候选快照和审核状态。候选展示外部 ID、标题体系、年份/季度、类型、封面、集数、简介摘要、题材、本地匹配对象和匹配原因。

### 4.2 确认导入

用户一次提交 `CREATE/LINK/SKIP` 决策。确认必须幂等：重复确认不重复创建、不重复关联。唯一外部 ID 冲突必须明确报错。

### 4.3 已有关联刷新

有 `provider + externalId` 时按 ID 获取最新资料；成功后更新外部缓存及当前条目的集映射。失败保留上次成功资料，记录 `lastError` 和 `STALE/FAILED` 状态。

### 4.4 Episode 对齐

优先外部集 ID，其次受控的远程季号+集号。外部集号变化只记录 `RENUMBERED`；远程不再返回的已关联集标记 `MISSING`；任何歧义标记 `CONFLICT`，不移动 Clip。

## 5. 缓存与更新

同步是用户显式操作，不做 v0.22 自动后台刷新。外部表记录：`lastFetchedAt`、`lastSuccessAt`、`payloadHash`、`syncState`、`lastError`。详情接口只读本地缓存。

## 6. API 草案

```text
GET  /api/metadata-sync/providers
POST /api/metadata-sync/tasks/preview
GET  /api/metadata-sync/tasks/{taskId}
POST /api/metadata-sync/tasks/{taskId}/confirm
POST /api/media/{id}/metadata-sync
POST /api/media/{id}/metadata-link/confirm
GET  /api/media/{id}/metadata
```

任务状态：`QUEUED/RUNNING/PREVIEW_READY/IMPORTING/DONE/PARTIAL/FAILED/CANCELLED`。

## 7. 安全与失败边界

Bangumi HTTP 请求使用固定 Provider 端点、超时、响应大小限制、分页/429/5xx 退避和严格 JSON 校验。Provider 只提供元信息，不接收任意视频 URL，不转发 Cookie/token，不做 DRM 或反爬绕过。封面下载沿用受控服务并单独处理失败。

## 8. 验收标准

- 空库能从媒体页按年份/季度预览并一次确认导入。
- 普通本地搜索、列表和详情不产生外部请求。
- 已关联媒体同步更新远程资料；无关联媒体先候选确认。
- 预览取消不创建用户媒体/条目/集。
- 重复确认幂等；失败保留旧资料。
- 外部新增集可展示且不需要视频 URL；改号/消失不破坏 Clip。
- 用户字段、历史 Episode/Clip、标签、收藏和导出物不被同步覆盖。
- MySQL/SQLite 迁移、生产 SQLite 迁移资源和 MySQL→SQLite 工具均覆盖新表。
- v0.23 远程视频获取边界不被本版实现偷偷扩大。

## 10. 同步交互重构背景

首批实现将范围选择、查询、候选审核、直接同步、确认导入和错误反馈塞进同一个弹窗，适合验证链路，不适合真实资料库建设。当前主要问题：

1. 批量建库和完善单个媒体共用同一入口与同一流程，用户无法判断当前操作是“发现新作品”还是“绑定当前媒体”。
2. 按年份/季度查询一次返回大量候选，却没有分页、排序、筛选、跨页选择汇总和候选详情层级。
3. 卡片勾选隐式代表 `CREATE/LINK/SKIP`，用户看不到推荐动作的依据，也无法安全处理多重本地匹配。
4. “直接同步全部”与主确认按钮同级，缺少风险汇总、二次确认和自动模式安全边界。
5. 同步是长耗时网络与数据库任务，但当前以前台单次请求执行，关闭页面、刷新应用和部分失败后的恢复能力不足。
6. 媒体详情中的“同步资料”仍打开批量弹窗，未围绕当前媒体提供专门的搜索、关联、刷新和更换关联流程。
7. 候选列表一次性渲染全部结果，信息密度高且滚动位置、筛选状态和跨页选择不可恢复。
8. Bangumi 上游分页大小可能小于请求值，Provider 不能再用“返回数小于请求数”直接判断最后一页；必须使用响应 `total` 和实际返回数量推进 offset。

本次重构把同步拆成两条同等重要但交互严格隔离的主链路：

```text
全局媒体页入口 → 批量同步工作台 → 发现/审核/确认/后台任务
媒体详情入口   → 完善本媒体     → 搜索关联/直接刷新/添加条目/更换关联
```

## 11. 信息架构与入口

### 11.1 批量同步工作台

媒体页全局“同步番剧”进入 SPA 内独立全屏视图，不再使用弹窗。工作台顶部包含：

- 返回媒体库；
- `新建同步` 页签；
- `任务记录` 页签；
- 当前草稿状态；
- 运行中任务数量。

### 11.2 完善本媒体

媒体详情“同步资料”根据关联状态直接分流：

- 已有主 Bangumi 关联：点击后直接刷新，不展示确认页；成功原地刷新外部资料，失败保留旧资料并显示错误。
- 未关联：在媒体详情“外部资料”区域展开内嵌匹配面板；自动填入本地标题，但必须由用户点击搜索后才访问 Bangumi。
- 已关联但错误：外部资料区提供“更换关联”。
- 需要补充 OVA、特别篇等：外部资料区提供“添加其他条目”，默认一次添加一个条目。

普通搜索、媒体列表和媒体详情读取仍只访问本地缓存，不因页面打开自动联网。

## 12. 批量同步工作台布局

```text
┌ 返回媒体库 ─ 同步中心 ─ [新建同步] [任务记录] ─ 草稿/任务状态 ┐
├───────────────┬─────────────────────────────┬──────────────┤
│ 查询范围/筛选  │ 候选工具栏 + 分页 + 紧凑候选网格 │ 候选详情抽屉 │
│ 年份/季度/关键词│ 总数/当前筛选/当前页选择          │ 完整外部资料 │
│ 状态/类型/题材  │ checkbox + 推荐动作              │ 匹配与动作   │
│ 月份/关键词     │                                 │              │
├───────────────┴─────────────────────────────┴──────────────┤
│ 已选 N · 创建 X · 关联 Y · 更新 Z  [查看已选] [进入确认] │
└────────────────────────────────────────────────────────────┘
```

桌面端使用全屏工作台；窄屏改为单列，筛选器和候选详情使用全屏抽屉。不得出现弹窗套弹窗。

## 13. 查询范围与获取策略

### 13.1 批量发现

支持：

- 按年份；
- 按年份 + 季度；
- 指定作品关键词。

年份与季度均为单选。界面必须把当前范围翻译为明确句子，例如“查询 2024 年全部动画”或“查询 2024 年冬季动画”。

### 13.2 获取全部、前端分页

批量同步一次获取该查询范围内的全部候选，然后由前端分页审核：

- 每页可选 `20 / 50 / 100`，默认 20；
- 记住用户上次选择；
- 页码、筛选、排序只作用于候选快照，不重复访问 Bangumi；
- 跨页选择和动作修改必须保留。

Provider 分页必须：

1. 将 `limit/offset` 放入 Bangumi URL 查询参数；
2. 根据响应 `total` 判断是否结束；
3. 使用实际返回数量推进 offset；
4. 上游未提供 `total` 时，只有空页才能确认结束；
5. 对重复 external ID 去重；
6. 设置最大结果数和最大页数保护，避免异常上游造成无限请求。

### 13.3 完善本媒体搜索

单媒体匹配最多展示前 20 条，不分页。结果过多时提示用户修改关键词缩小范围；不提供直接输入 Bangumi ID。

## 14. 候选卡片与详情

### 14.1 紧凑卡片

批量候选默认只展示：

- 封面；
- 中文标题与原名；
- 类型、播出日期、集数；
- `新作品 / 已有关联 / 标题疑似 / 冲突` 状态；
- 当前计划动作；
- 独立 checkbox。

点击卡片正文打开右侧详情抽屉；点击 checkbox 只改变选择状态，不打开详情。卡片高度保持稳定，不直接展示长简介和完整题材。

### 14.2 详情抽屉

详情抽屉展示：

- 完整标题体系和别名；
- 封面、简介、题材；
- 类型、播出日期、集数；
- Provider 与外部 ID；
- 关系作品；
- 本地匹配对象、匹配原因和风险；
- 当前计划动作。

抽屉允许修改动作：

- 创建新媒体；
- 关联推荐媒体；
- 搜索并关联其他本地媒体；
- 跳过。

翻页或切换筛选时关闭抽屉，但保留选择与动作状态。

## 15. 选择和动作模型

1. 所有候选默认不选中，包括新作品和已有本地匹配。
2. “全选”只选择当前筛选结果的当前页。
3. 勾选候选时采用推荐动作：无匹配建议创建；稳定外部 ID 关联建议更新；单一标题疑似建议关联，但用户可修改。
4. 未勾选等同于跳过，不产生写入。
5. 多重本地匹配标记为冲突并禁止直接勾选；必须在详情抽屉选择具体媒体或改为创建后才允许选中。
6. 跨页选择在固定底栏汇总：`已选 N · 创建 X · 关联 Y · 更新 Z`。
7. “查看已选”展开选择清单，支持移除、修改动作以及定位回原分页。

## 16. 筛选与排序

批量工作台首版提供完整组合筛选：

- 状态：全部、新作品、已有稳定关联、标题疑似、冲突、已选择；
- 类型：TV、OVA、ONA、剧场版、特别篇及 Provider 返回的其他格式；
- 题材：根据本次候选动态生成；
- 播出月份；
- 关键词：中文名、原名、英文名和别名；
- 已选择项目。

默认保持 Bangumi 返回顺序。可主动切换播出日期、标题、本地匹配状态和计划动作排序。所有筛选与排序均在本地候选快照上执行。

## 17. 确认导入

“进入确认”展示数量汇总，并按动作提供可展开作品清单：

- 创建新媒体；
- 更新已有外部 ID 关联；
- 关联到本地媒体；
- 跳过；
- 冲突/不可提交。

点击清单项目可返回审核区定位候选并修改。确认页明确说明同步不会覆盖本地标题、备注、评分、观看状态、标签、收藏、封面选择、视频 URL/指纹和 Clip。

确认后创建持久化后台任务。提交结果页保留当前页面，并提供：

- 任务编号和初始状态；
- 创建、关联、更新、跳过数量；
- 返回媒体库；
- 查看任务进度。

## 18. 高风险自动处理全部

“直接同步全部”不再与主按钮并列，降级为二级菜单中的“批量自动处理全部结果”。执行前必须显示汇总和二次确认。

自动模式只允许：

- 已有稳定外部 ID 关联 → 自动刷新；
- 完全没有本地匹配 → 自动创建。

以下项目全部跳过并进入人工审核清单：

- 只有标题相似匹配；
- 多重本地匹配；
- 外部 ID 冲突；
- 缺少必要身份字段。

自动模式绝不根据标题自行绑定本地媒体。

## 19. 草稿

批量同步只保留一个最新草稿。草稿自动保存：

- 查询模式和查询条件；
- 候选快照；
- 筛选、排序、页码和每页数量；
- 已选择项目；
- 每项计划动作和手工关联对象；
- 当前打开的候选；
- 最后编辑时间。

再次进入同步中心时提示“继续上次审核”或“放弃并新建”。新查询覆盖旧草稿前必须明确确认。成功提交任务后清除草稿；查询失败不得破坏已有草稿。

## 20. 后台任务与任务记录

批量导入确认后转为持久化后台任务；用户可以关闭同步中心或返回媒体库，任务继续执行，不提供中途取消。

任务状态建议：

```text
QUEUED → FETCHING → IMPORTING → DONE
                         ├→ PARTIAL
                         └→ FAILED
```

任务记录页展示：

- 范围与创建时间；
- 当前阶段和处理进度；
- 创建、更新、关联、跳过、失败数量；
- 失败项和待人工审核项；
- 完成时间。

保留策略：

- 无遗留的成功任务保留 30 天后自动清理；
- 含失败、冲突或待处理项的任务永久保留；
- 遗留全部处理完后进入 30 天清理周期；
- 用户可删除已完成任务；运行中任务不可删除。

失败项不能一键盲重试。用户必须先查看作品、失败阶段、错误原因、原动作、本地匹配和上次尝试时间，可修改动作后确认重试。

## 21. 完善本媒体

### 21.1 已关联刷新

已存在主 Bangumi 关联时，点击“同步资料”直接刷新。按钮进入 loading 状态，成功后原地刷新外部资料和集状态；失败显示明确错误并保留旧资料。

### 21.2 未关联匹配

媒体详情外部资料区域展开内嵌面板：

1. 搜索框自动填入本地标题；
2. 用户主动点击搜索；
3. 最多展示前 20 条紧凑单选候选，不默认选择；
4. 点击候选正文在列表下方展开完整详情；
5. 选中候选后点击“关联并同步”；
6. 只允许关联当前媒体，不允许从这里创建新媒体；
7. 成功后面板原地切换为正式外部资料卡。

默认一个主条目；关联完成后可通过“添加其他条目”继续补充 OVA、特别篇或其他条目，每次添加一个。

### 21.3 更换关联

已关联媒体提供“更换关联”。确认前展示：

- 当前主条目；
- 新候选条目；
- 旧关联产生的 Episode 处理清单。

旧集默认全部保留。用户可逐集选择删除；每集必须展示 Clip、本地视频、用户标题/备注、标签和封面状态。含 Clip、本地视频或用户编辑内容的集视为受保护项，需要额外高等级确认才能删除。更换关联不自动移动或删除 Clip。

建议新增：

- 总数及各动作计数；
- processed/failed/pendingReview；

### 22.3 `metadata_sync_task_item`

- taskId、provider、externalId；
- 冻结后的目标动作和 mediaId；
- 状态、阶段、错误；
- attempts、lastAttemptAt；
- 候选快照摘要。

任务提交后冻结动作，后续前端草稿变更不得影响运行中的任务。

## 24. 加载、空态与错误

- 查询中：显示明确范围、已获取页数/候选数和可返回状态，不使用无限假进度条。
- 空结果：保留查询条件，提供修改条件入口。
- Provider 失败：显示 HTTP/网络/解析类型，不清空现有草稿和候选。
- 部分失败：任务继续；完成页区分成功、失败和待人工审核。
- 无本地匹配：明确提示将创建新媒体，而不是笼统显示“新作品”。
- 稳定外部 ID 已关联：明确显示目标媒体名。
- 标题疑似：显示匹配原因，不允许自动模式关联。
- 冲突：必须人工解决后才可提交该项。

## 25. 可访问性与键盘操作

- checkbox、筛选器、分页、动作菜单和详情抽屉均可键盘聚焦；
- 卡片正文与 checkbox 使用不同可点击区域；
- 状态不能只依赖颜色，必须有文字和图标；
- loading、错误和任务完成使用 `aria-live`；
- 工作台返回时自动保存草稿；
- 恢复草稿后焦点回到上次候选或工具栏。

## 26. 重构验收标准

### 批量同步

- 年份/季度可获取完整候选，不因上游单页 10/20 条提前终止。
- 候选一次获取、前端分页 20/50/100；翻页不重复访问 Bangumi。
- 筛选、排序和翻页不丢失选择与动作。
- 所有候选默认不选；全选只作用当前筛选结果当前页。
- 冲突项在人工指定目标前不能选中。
- 确认页按动作分组并可返回定位修改。
- 草稿离开后可恢复；新查询覆盖前有确认。
- 后台任务关闭页面后继续，应用重启后可查询状态。
- 自动处理全部不基于标题自动关联。

### 完善本媒体

- 已关联媒体点击后直接刷新，失败保旧。
- 未关联媒体不自动联网，用户点击搜索后才请求。
- 搜索最多展示 20 条且不默认选择。
- 只能关联当前媒体，不能误创建新媒体。
- 支持添加其他条目和更换主关联。
- 更换关联时旧集默认保留，受保护集删除有额外确认。

### 数据安全

- 预览和草稿不创建 `Media/MediaEntry/Episode`。
- 后台任务重复提交和重试保持幂等。
- 用户字段、Episode 本地内容、Clip 和导出物不被外部同步覆盖。
- MySQL/SQLite 新迁移及 MigrationTool 同步覆盖任务/草稿表。

## 27. 明确不做

- 不新增自动后台发现或定时联网刷新；
- 不提供直接输入 Bangumi ID；
- 不在单媒体匹配中提供创建新媒体；
- 不实现任务中途取消；
- 不根据标题自动绑定本地媒体；
- 不做逐字段资料差异确认；
- 不递归导入关系作品；
- 不引入远程视频源、下载或播放能力。
