# 第一部分：媒体趋势统计（网页图表）

## 1. 目标

在统计页新增「媒体趋势」板块：**对当前筛选命中的媒体集合按首播年份计数**，以折线（或柱状）呈现；点数据点弹出该年**代表作小卡**（按评分筛 Top N）。支持把**多个筛选条件各固定成一条线**做对比（如「异世界 vs 科幻」）——这是原始需求「筛选媒体然后按分组统计数量折线图，直观看出某一类番剧的发展变化」的落点。

## 3. 语义与口径（本部分的核心）

### 3.1 一条线是什么

**一条线 = 一个筛选条件命中的媒体集合，按首播年份计数。**

- 筛选条件 = 媒体页那套参数（状态 / 格式 / 子分类 / 待确认 / 收藏夹 / 标签 / 题材 / 季度 / 关键词 / 年份），**含各维度的 AND/OR 模式**。
- 同维度多选且模式为 AND → 命中集是**交集**（勾「异世界」+「科幻」→ 38 部，2023=3 / 2024=5 / 2025=3 / 2026=2）。
- 多线只能来自**多个筛选快照**（见 §5.2），不来自「媒体的标签个数」。

### 3.2 横轴规则

1. `year` 维度**无勾选** → 横轴 = **全库有效年份范围**（实测 1983–2026，44 个刻度），连续无孔。
2. `year` 维度**有勾选** → 横轴 = **勾选的年份集合**（升序）。
3. 横轴刻度由后端返回，**所有线共用同一份刻度** → 多线天然对齐，前端不做补 0 逻辑。
4. 已知观感：1983–1999 合计仅 3 部，图上是一段贴地的线，**属正常数据表现，不做裁剪、不加起始年控件**（记入 §8 明确不做）。

### 3.3 计数规则

- 缺数据的年份**补 0**，线不断。
- 计数用 `COUNT(DISTINCT a.id)`（防任何 JOIN 放大）。
- 已删除媒体（`deleted_at IS NOT NULL`）**不参与**。

### 3.4 评分的三个口径

| `scoreSource` | 排序依据 | 过滤条件 |
|---|---|---|
| `bgm` | Bangumi 评分降序 | `votes ≥ 100` |
| `personal` | 个人评分降序 | `rating IS NOT NULL`（实测全库仅 23 部 → 某年可能 0 条，小卡显示「该年没有个人评分」） |
| `mixed`（默认） | **个人评分优先，未评分回落 Bangumi** | `rating IS NOT NULL OR votes ≥ 100` |

> 说明：`personal` 口径**不套 100 票门槛**（个人评分是用户主观认定，与冷门无关）；只有 `bgm` 口径套门槛，因为「21 票打 6.1 分」不构成代表作。

## 4. 后端设计

### 4.1 端点一：趋势计数

```
GET /api/stats/media-trend
```

**参数（与媒体页筛选完全同名同类型）**：`status`(List)、`format`、`subcategoryId`、`confirmed`、`collectionId`(List)、`collectionMode`、`tagIds`(List)、`tagMode`、`genres`(List)、`genreMode`、`q`、`season`(List)、`year`(List)。

**响应**：

```json
{
  "years":  [1983, 1984, "…", 2026],
  "total":  547,
  "points": [{"year": 2013, "count": 7}, {"year": 2014, "count": 0}]
}
```

- `years` = 横轴刻度（规则见 §3.2），`points` 与 `years` 等长等序。
- **筛选为空时**：后端**照常返回全库统计**（`total = 5249`，即不套任何条件），**是否显示由前端决定**（决策 13：前端不画）。后端不做「空筛选就报错」这类拦截。

**SQL 形状**（新增查询，复用既有 filter 常量）：

```sql
SELECT a.year AS year, COUNT(DISTINCT a.id) AS count
FROM media a
<where>
  a.deleted_at IS NULL
  -- STATUS_FILTER / YEAR_FILTER / SEASON_FILTER / GENRE_FILTER / TAG_FILTER / COLLECTION_FILTER
  -- 逐字复用 MediaMapper 现有的共享常量，保证与媒体页口径完全一致
</where>
GROUP BY a.year
```

- **刻意复用 `MediaMapper` 现有 filter 常量**：这是「口径合一」的硬要求，禁止另写一套 WHERE（v0.31 刚填过「三套数」的坑）。
- 刻度查询：`SELECT MIN(year), MAX(year) FROM media WHERE deleted_at IS NULL AND year IS NOT NULL`（`year` 有勾选时改用勾选集合）。

### 4.2 端点二：代表作（小卡数据）

```
GET /api/stats/media-trend/refs
```

**参数**：同一套筛选参数 + `year`（必填，单个年份）+ `scoreSource`（`bgm` / `personal` / `mixed`，默认 `mixed`）+ `limit`（默认 5，上限 20）。

**响应**（每项一个卡片）：

```json
{ "id": 3350, "title": "SSSS.电光机王", "year": 2021, "mediaFormat": "VIDEO",
  "coverPath": null, "externalCoverUrl": "https://…", "fallbackCoverPath": "/covers/clip/177.jpg",
  "episodeCount": 12, "clipCount": 1,
  "personalRating": 8.0, "bgmScore": 7.2, "bgmVotes": 3303 }
```

- **封面三字段齐全**，前端必须走 `app.js` 的 `mediaCoverSources` 那一族（显式封面 → Bangumi 封面 → 代表片段帧），**禁止手写取值链**。
- **刻意不复用 `MediaSummary`**：那是**按位映射**的 record（历史上因列顺序错位炸过），为它加字段要同步改 4 条卡片查询。本端点**自带独立 record**，风险隔离。
- Bangumi 分/票数走 `JSON_EXTRACT(ew.raw_json, '$.rating.score')` / `'$.rating.total'`。
- ⚠️ **仅 MySQL 生效**：SQLite 桌面轨道不支持 `JSON_EXTRACT`，该维度在桌面版无数据。这与现有**题材筛选**的限制完全一致（`GENRE_FILTER` 注释已记载），**不新增约束**。

### 4.3 需重启后端

新增端点 + 新增查询属 Java 侧改动 → `AGENTS.md` §4 的规矩适用：**改完必须让用户手动重启 IDEA 实例**才生效。

## 5. 前端设计

### 5.1 新增文件（不再往 `app.js` 里塞）

`app.js` 已 **415KB**，本部分**另开**：

- `static/stats-trend.js`：板块渲染 / 图表绘制 / 交互。
- `static/stats-trend.css`：样式（贴合现有 `app.css` 配色，主色沿用 `#cba6f7` 一族）。
- `index.html`：新增板块容器 + `<script>` 引入 + **版本戳**。
- ⚠️ **版本戳必须提**：2026-10-02 那次「浏览器拿旧 app.js + 服务端换新 index.html → 全站加载失败」的事故是真事，`AGENTS.md`/`application.yml` 里都有血书。

### 5.2 筛选：**维度/取值共用，勾选独立**（2026-10-04 用户澄清后修正）

- 维度集合、取值字典、且/或语义**与媒体页共用**（同一批 `MEDIA_DIMS` / `dimValues` / `renderFilterPop`），
  但**勾选状态各自独立**：统计页用自己的 `trendFilter`，**不把媒体页的筛选带过来**。
- 为何修正：原先两边共用一份 `mediaFilter`（本文初稿的 Q20a）→ 媒体页已勾的条件在统计页就是「已勾上」，
  用户再点一下变成**取消**，表现就是「勾选无效 / 切不了」（2026-10-04 用户报「筛选无法切换」的真因）。
- 实现：`app.js` 的 `renderFilterPop(dims, vals, f, onChange)` / `setDim(key, value, f, onChange)` / `dimLabel(key, f)`
  全部**可注入筛选对象与变更回调**（默认 = 媒体页行为，媒体页一行调用不用改）；统计页传 `trendFilter` + `trendFilterChanged`。

### 5.3 「＋固定为一条线」

1. 用户调好筛选 → 点「＋固定为一条线」→ 弹小输入框（线名，默认取「题材/标签名 + 数量」如「异世界 · 545 部」；可留空自动生成）+ 自动配色（固定调色板按序取）。
2. 每条线保存**筛选条件的快照**（快照即序列化后的 `mediaFilter`），**不是引用**——后续改筛选不会改动已固定的线。
3. 上限 **5 条**（决策 3 / Q14）；可删除、可重命名；**不做拖拽排序**。
4. 线列表支持：图例点击**切换显隐**（Q14 明确要）。

### 5.4 图表

- 两种形态：**折线**（默认）/ **柱状**；**线数 ≥3 时柱状按钮置灰 + `title` 说明原因**（决策 15）。
- 视图切换：**数量 / 占比**（决策 6）。**占比 = 该线当年数量 ÷ 全库当年总量**（分母固定为全库，不随筛选变化——这样对照基准稳定；若实测观感不对，见 §9）。
- 横轴刻度 44 个时**隔年显示标签**（复用 `renderBars` 里的 `labelEvery` 思路）。
- **默认不标数字**（决策 7）：hover 显示该点数值文本；点击数据点弹小卡。
- 空态（决策 13）：未选任何筛选 → 不画图，显示「当前没有筛选条件」提示 + 筛选入口。

### 5.5 代表作小卡

- 点击数据点 → 绝对定位 **popover 小卡**（不做图下方常驻列表）。
- 内容：**Top 5** = 封面 + 标题 + 年份 + **两套评分**（`BGM 7.2（3303 票）` / `个人 ★8.0`，有哪个显哪个）+ 片段数；点条目 → 进媒体详情页（走 hash 路由）。
- 卡片顶部有**评分源勾选**（`Bangumi` / `个人` / `混合`，默认混合，决策 1）。
- 小卡数据**按需请求**：点某年才拉该年 Top5（决策源自 Q-C2），不做「一次全带」。

## 7. 验收口径

**单测 / IT（拿 §0 真值当基线）**：

1. 异世界标签（tag id 417）逐年计数 = 2013:7 / 2016:12 / 2019:25 / 2022:44 / 2023:74 / 2024:73 / 2025:70 / 2026:87，`total = 545`。
2. 「异世界 + 科幻」标签模式 AND → `total = 38`，2023=3 / 2024=5 / 2025=3 / 2026=2。
3. `year` 有勾选时 `years` = 勾选集合（升序），`points` 等长；无勾选时 `years` = 1983…2026 连续。
4. 空筛选 → 后端返回**全库统计**（`total = 5249`），**前端不画**（前半句后端验收，后半句前端验收覆盖）。
5. `refs`：`bgm` 口径全部 `votes ≥ 100`；`personal` 口径全部非空；`mixed` 口径「有个人分的一律排在无个人分之前」。
6. 参数绑定：多值维度的 AND/OR 与媒体页结果一致（同一个筛选条件，`/api/media` 命中数 = 趋势 `total`）。

**前端（真实浏览器验收）**：切页继承筛选、改筛选同步、固定线/删线/改名、图例显隐、折线↔柱状、数量↔占比、点数据点弹小卡并进详情、空态提示。

**回归**：`/api/media` 各条查询**行为不变**（本部分未改任何现有查询与 `MediaSummary`）。

# 第二部分：统计视频（Remotion）

## 1. 目标

把 §第一部分 的统计结果渲染成一支**统计视频**：年份逐年推进，折线/柱状随之生长，末尾定格展示代表作。产出 mp4 落 `data/exports`，在统计页可播放/下载。

| # | 决策 | 来源 |

| 1 | 本轮**就要出视频**（不是只定契约） | Q8c |
| 2 | 视频画面**独立绘制**，与网页 SVG **不共享渲染代码**，只**共享数据契约** | V1b |
| 3 | 时间轴 = **年份逐年推进 + 末尾定格代表作** | V2 |
| 4 | **不进**模板入口 / 草稿 / 导出队列 / 打包 | V3a |
| 5 | **不做** BGM、字幕、配音 | V4 |

| 7 | 折线 / 柱状**都支持**，视频由参数指定 | Q25a |
| 8 | 固定参数（用户「先定死」）：1920×1080 / 30fps / 结尾定格 3 秒 / 画面文字仅年份·数量·线名·代表作标题 / 年份范围跟随网页横轴 | Q26 |

**AI 提议、用户未反对（若否认请指出）**：

- 秒/年边界 **0.25 – 10**，默认 **1.5**，非法值回落默认（信任边界校验，必须做）。
- **代表作只在末尾定格出现**，不做「每一年插一张代表作卡片」（会把节奏切碎，且渲染成本显著上升）。

## 3. 数据与契约

- 视频数据由**服务端组装**，**不走 HTTP**：Java 渲染流程直接调 §第一部分 的 `StatsService.trend()`（**多线 = 循环调用**，一次一条快照）与 `refs()`，结果作为 `inputProps` 传给 Remotion。
- ⚠️ **封面必须先下载再内联成 data URI**（实现中发现，实测依据）：Remotion 的 `<Img>` 会 `delayRender` 等图，
  而 headless Chrome **不吃系统代理** → `lain.bgm.tv` 直接 `ERR_CONNECTION_TIMED_OUT` → 整支视频 28s 超时失败（真的挂过）。
  改成 Java 侧先把 ≤5 张封面用**应用自己的 HTTP 栈**（proxy-aware）下下来转 data URI（实测下得到），
  下不到就**不带封面**渲文字卡 —— 绝不因为一张封面废掉整支出片。
- 代表作只需**末尾定格的那一年**的 Top5（见 §4），**不需要**「每线每年」的全量代表作，也**不需要**给网页接口加「全量模式」。

**`inputProps` 形状**：

```jsonc
{
  "title": "媒体趋势 · 异世界 vs 科幻",
  "chartType": "line",              // line | bar
  "secPerYear": 1.5,                // 0.25–10，非法回落 1.5
  "width": 1920, "height": 1080, "fps": 30,
  "holdSec": 3,
  "years": [2000, "…", 2026],
  "lines": [
    { "name": "异世界 · 545 部", "color": "#cba6f7",
      "points": [{"year": 2000, "count": 1, "ratio": 0.008}] }
  ],
  "refs": [                          // 末尾定格用：横轴最后一年的 Top5
    { "title": "…", "coverUrl": "…", "bgmScore": 7.2, "bgmVotes": 3303,
      "personalRating": 8.0, "clipCount": 1 }
  ]
}
```

## 4. Composition 设计

- **新增** `src/MediaTrendComposition.tsx`（建议落 `src/trend/` 子目录，内含 params 解析与几何计算的独立小模块 + 测试），并在 `src/Root.tsx` 注册 composition id `media-trend`。
- **总帧数** = `(years.length × secPerYear + holdSec) × fps`；「第 N 年」出现在第 `N × secPerYear × fps` 帧（帧数计算单独测）。
- **画面**：标题 + 图表生长动画（折线逐段延伸 / 柱子逐年升起）+ 当前年份大字 + 当前年数量 + 线名图例；**末尾 3 秒**切换到代表作定格（Top5 卡片：封面 + 标题 + 评分）。
- **定格展示的是「横轴最后一年」在该筛选条件下的 Top5**；若该年 0 条 → 显示「该年无代表作」文案，**不跨年补齐**（避免出现「明明看的是末年却混进别的年份」）。
- **不做**逐年代表作卡片（见 §2）、不做音乐/字幕（`bgm.tsx` / `audio.tsx` 不接）。
- 30fps 的依据：`AGENTS.md` 记录的既有约定是「银幕式 24fps、其余 30fps」（`RecommendService.fpsOf`），统计视频不属于银幕式。

## 5. 触发与渲染

- `POST /api/stats/media-trend/video`：请求体 = 线快照 + 图表类型 + 秒/年 + 评分源；返回 `taskId`。
- `GET /api/stats/media-trend/video/{taskId}`：返回 `{ status, progress, outputPath, error }`。
- 渲染实现：**照抄 `RecommendVideoService` 既有的 `bundle → selectComposition → renderMedia` 调用方式**，产物落 `data/exports/`。**不新建渲染管线。**
- 进度状态用**内存态**（`ConcurrentHashMap`），**不落库**（与 V3a「不进导出队列」一致）。
- **并发限制 1**：视频渲染吃 CPU，同时跑多个任务不可接受。

### 5.1 页内预览（2026-10-04 追加，用户问「能预览然后生成吗」→ 选 B）

**为什么**：44 年 × 1.5 秒/年 ≈ 2070 帧，正式渲染 4~8 分钟；改一个参数就等一轮渲太费。

- **做法**：`@remotion/player` 在页面里逐帧实时渲染**同一份 `MediaTrendComposition`** → 所改即所见（只差分辨率/码率）。
- **构建**：`vite.trend.config.ts` → `dist-trend/trend-preview.js`（`npm run build:trend-preview`）；
  `WebConfig` 加 `/stats-trend-preview/**`（照 `/recommend-editor/**` 那套）；未构建时统计页给出构建命令（不白屏）。
- **契约**：`window.VTTrendPreview.mount(el, inputProps)` / `update(props)` / `unmount()`。
- **数据**：线数据直接取前端已有的 `trendState.lines`（**预览零后端新增**）；代表作复用现成 `refs` 接口。
- **改参数实时刷新**：切折线/柱状、改秒/年、换评分口径 → 预览跟着重挂（不重建 root）。
- ⚠️ **封面必须预检**：浏览器加载不到的图**不能**塞给 Remotion（`<Img>` 会 delayRender 等图 → 一张坏图拖死整支片）。
  做法：`new Image()` + 6s 超时，加载不到 → `coverUrl: null`（退化成纯文字卡）。
- ⚠️ **首帧要等**：实测（headless）冷启动 **6.2s**、缓存后 **1.5s** 才画出第一帧 → 提示文案先写「Player 正在画第一帧…」，画出后再换成参数摘要（不给反馈会看着像卡死）。
- 验收：探针实测 `built=true` / 弹层内 `svg` 出现 / 切柱状后 `rect` 44 根（实时刷新生效）/ 控制条 `0:00 / 1:09`（= 44×1.5+3 ✓，与我方算式一致）/ 截图人眼过。
