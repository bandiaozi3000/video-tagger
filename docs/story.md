# Video Tagger 项目故事线

> 每版更新在此追加一段「为什么做 → 做了什么 → 与上一版的延续」，把版本演进串成一条线。
> 功能细节看 [CHANGELOG](../CHANGELOG.md)，每天的工程过程看 `docs/worklog/`，这份只讲故事的脉络。

## v0.1 奠基：从零到「打标能搜回」

一个看番/学习时随手记素材的念头。写了两份设计文档（Java + MySQL + Milvus + Docker 架构 + 17 个任务实施计划），搭起 Spring Boot 骨架 + 三层存储（MySQL 元数据 / Milvus 向量 / 本地封面），打通第一条闭环：**浏览器扩展打标保存 → 片段入库 → 关键词（ngram 全文）+ 向量（Embedding + 余弦）混合搜索 → 扩展浮层里看回**。这一版全是地基，没有花活。

## v0.2 可用化：从「能存」到「好存好找」

第一版能用但糙。补上编辑/删除/追加标签、**连续打标模式**（保存后浮层不关、时间戳跟播放进度走）、快捷标签位（Ctrl+Shift+1~9）、标签补全、重复片段提示、视频时间线视图、相似推荐、统计面板。同时修了三个真问题：Milvus 冷启动竞态（语义搜索永久哑火）、3 秒去重误吞数据、Embedding Key 硬编码泄密。引入 Flyway 管 schema。

## v0.3 番剧三层：散落片段第一次有了「家」

之前存下来的只是一条条片段，越打越乱。这版做核心架构转折——**番剧 → 集(含季) → 片段**三层结构，三层都能打标，按标题正则自动归组，卡片墙/详情页 + 追番状态/评分/作品级标签，三层向量化 + 跨层 RRF 混合检索，收藏夹与筛选器，LLM 后台归组（判断不同季/翻译是不是同番），「看完自动弹」集级打标。从「素材堆」变成「番剧资料库」。

## v0.4 封面体系：每一条标记都有了脸

之前片段只有文字和时间戳，翻起来没画面感。这版给片段**截帧封面**（保存瞬间 canvas 抓当前帧）、给每集**自选高能画面**当集封面（未选则智能取标记最多的片段帧）、番剧封面缺失时用代表性片段帧兜底。全链路（搜索/时间线/相似/集列表/番剧卡片）带缩略图，封面生命周期级联清理。

## v0.5 详情页：点卡片就能钻进去

列表开始有封面了，但点卡片还只能跳回原视频。这版做**片段/集详情页**——大图 + 元信息 + 同集其他片段 + 相似片段，链式跳转 + 视图历史栈逐层返回；列表统一改横排缩略图卡片。浏览体验从「平铺」到「可下钻」。

## v0.6 双图封面 + 集删除：细节补完

截图一次出两档——缩略图（列表）+ 详情大图（悬浮预览、详情 hero）；补上**集删除**及级联清理（片段/标签/封面/向量全带走）。小版本，把浏览和清理的缝隙填上。

## v0.7 媒体格式细分：不只番剧，什么内容都能收

模型上把「番剧」泛化成「媒体」，新增**格式**（视频/图片/文字…）与**子分类**（视频：番剧/电影/电视剧…）两级可维护字典，图片/文字是单层媒体只有视频带集/片段。格式 tab 导航、格式/子分类筛选、管理弹层、统计分布、按域名/标题自动识别。anime→media 全面改名（向量前缀保留免迁移）。资料库从「番剧专用」变成「多形态内容仓库」。

## v0.8 备注 + 搜索增强：搜索从「找片段」到「收集素材」

媒体/集层加**备注**（参与关键词与向量语义检索，变更自动重嵌），搜索命中词**全字段高亮**一眼看出来源，新增**按媒体聚合**（结果按所属媒体分组，顺着一部部收集话题素材）、**时间范围筛选**（近 7/30/90 天）、结果角标。搜索的用途从「找回一条」升级为「围绕主题收集」。

## v0.9 标签补全上下文 + 标签管理页：标签从「随手打」到「可治理」

补全带**媒体上下文**（该媒体已用标签优先 + 全局高频兜底），打标时顺手；新增**「标签」管理 tab**——词库全景 + 按媒体维度，支持**改名**（同步 clips.tag 冗余列 + 引用自动重嵌）、**合并**（高然→高燃）、**删孤儿**（被引用拒绝）。标签第一次有了「词库治理」的入口。

## v0.10 分类树 + 标签池维护增强：组织维度从「扁平」到「树」

子分类改邻接表，**任意层级细分**（番剧 → 热血 → 战斗），筛选/搜索**子树收敛**（选父级连下级一起），管理弹层树化 + 删除保护升级。标签池维护增强：分页、全选本页、批量删孤儿、**新增标签弹层**（实时去重 + 批量入池）。

## v0.11 收藏夹 + 详情标签池：浏览更顺、热度可视化

收藏夹升级为独立 tab（列表 + 内容网格管理视图），卡片**快捷收藏**（♡ 弹出勾选浮层），收藏夹上下文删媒体改「移出收藏夹」防误删。详情页标签展示升级为**标签池**——每标签带引用次数徽标 + **五档分级配色**（越热越暖、金档大号光晕），媒体/集/片段三处统一。同时修了跳转失效（bangumi 路径）与跳转 key 不一致。

## v0.12 渐变环流推荐导出：从「自用工具」到「能产出分享」

打标半年攒了一堆番，想做成漂亮的东西发出去。这版做出**渐变环流推荐导出**——勾选多部番剧 → 生成**自包含 HTML**（深色霓虹、封面围成椭圆轨道自转、自动导览，base64 内嵌封面、单文件无外部依赖，可直接发人/手机打开）→ 用 Node + puppeteer 连系统 Chrome 以录制模式播放导览、CDP 抓帧 + ffmpeg 合成**导出 MP4 视频**（720P/1080P/4K）。项目第一次能「产出分享物」，而不只是自己检索。

## v0.13 推荐导出向导化：导出流程重做成「向导」

v0.12 导出体验不顺（勾选框藏得太深找不到，用户直说「流程不太喜欢」）。这版重做：**独立「推荐」tab 分步向导**——① 勾选要推荐的番剧 → ② 填主题文案（实时预览大标题）→ ③ 生成预览（**弹窗内嵌 iframe 直接看效果**），没问题再**导出视频**（选标题/MP4·WEBM/清晰度/**保存位置**走浏览器保存弹窗，File System Access API）。另修复用户实测反馈：预览弹窗太小（CSS 特异性 bug，一直被 560px 卡着）→ 撑满视口 + 全屏按钮；导出视频卡顿（4K 抓帧掉到 19fps、WebM 软解）→ 抓帧质量与编码参数调优，1080P 帧率稳到 ~59fps。

## v0.14 番剧同步：资料库第一次能「批量进货」

库里多是手工整理的番，用户想按年份批量把历年的番（名称/年份/封面）搬进来。调研一圈数据源（Bangumi 大陆超时、MAL 需 OAuth、jikan 不稳、omofuna 有 JS 反爬），锁定 **AniList**——免认证 GraphQL 直接按首播年份分页拉全量。这版给媒体加上**首播年份 + 原生日文标题**两个字段，媒体 tab 出「**同步番剧**」入口：勾选年份（2000~2026 可多选）→ 一键导入，重复自动跳过、封面异步补全，标题先以日文原名占位、后续可改中文。资料库从「手工一朵朵」到「按年批量进货」，为后面按年代检索/回顾打底。

番剧同步进来的同一天，推荐页的两个新筛选暴露出一个**数据层的断层**：用户打标签一直打在**片段**上，收藏夹/标签筛选却按**媒体**过滤——结果媒体标签全空，标签过滤「无效」不是 bug，是标签没有「长上去」。于是这版补上**标签三级同步**：片段标签自动并集到所属集、再到所属媒体（单向向上、幂等落库、删除不级联由用户手动清），历史数据一键全量同步——「奇幻恋爱」这类词从 `mediaCount=0` 一夜变 `6`，推荐页按标签挑番真正可用了。同一轮还修了收藏夹过滤失败（列表接口缺 `collectionId`）并补上「全选本页」。从「进货」到「货能按标签挑出来」，v0.14 把资料库的入口和出口都打通了。

## v0.15 omofuna 中文源：进货渠道从「日文原名」补上「中文名」

v0.14 用 AniList 批量进货，但标题是**日文原名**占位，要手动改成中文。用户又翻出当初调研时被排除的 **omofuna**（旧结论「maccms+JS 反爬」）——重测推翻旧判断：URL 结构能解析（`show/{分类ID}--------{页码}---{年份}.html`）、**真实浏览器点「继续访问」就能过验证**、封面无防盗链，且给的是**中文标题**，正好补 AniList 的缺口。但 omofuna 详情页没有日文原名，中文标题和 AniList 日文牌对不上号，同番会并存两条（grilling 拍板「新增 + merge 治理」，重复靠既有合并功能手动统一）。这版做出「**⇄ 同步中文番剧**」：勾选年份 → 后端后台任务用 Node+puppeteer 连系统 Chrome 真实浏览器逐页抓取（日漫/动画/剧场，自动过验证、hash 去重、页间限速）→ 中文标题/年份/封面逐条导入。因为要跑 20~40 分钟，顺手做了**异步任务 + 进度轮询**（POST 秒回 taskId、前端轮询已抓页数/条数、刷新可恢复）。资料库的进货渠道从「日文原名」到「中文名」都打通，重复番靠既有合并统一。写抓取时踩了两个坑：验证页点按钮会触发 reload、轮询时 evaluate 抛「Execution context was destroyed」要容错；omofuna 的详情 hash 是 **24 位 hex 不是 32 位**（正则写错一页都导不进）。

## v0.16 推荐 BGM：分享物第一次能「带着音乐出门」

v0.13 的推荐导出能生成自包含 HTML 和视频，但都是「无声」的——用户想加背景音乐，BGM 名称和播放进度也要在页面里显示。这版在推荐向导「设置主题」加「🎵 添加 BGM」：选本地音频（mp3/m4a/wav，≤20MB）→ base64 **内嵌**进单文件 HTML（保持可分享，右下角 BGM 条显示名称 + 播放进度 + ♪ 播放/暂停）；导出 MP4/WEBM 时 ffmpeg 把 BGM **循环混入音轨**（`-stream_loop -1`，导览多久播多久）。视频从「默片」变成「带配乐」，分享物第一次能「带着音乐出门」。实现上 BGM 以纯 base64 走 JSON body，HTML 注入 data URI、视频解 base64 写临时文件再混音，两端复用同一份音频。

## v0.17 推荐导出分组：分享物第一次能「分章讲述」

v0.16 的推荐导出能带着 BGM 出门了，但几十部番挤在一个导览里，别人看的时候像流水账——用户想按**年份 / 分类 / 收藏夹**分组，让推荐有「章节感」。这版在向导「设置主题」加**分组方式**（不分组 / 按年份 / 按分类 / 按收藏夹）+ **分组样式**（流式横幅 / 章节式 / 总览导航式）双选择：导出时按所选维度把媒体分组，每组前有**转场页**（斜切横幅 / 整屏章节页 / 总览选组），组内 Story 带**分组徽标**——分享物从「一串清单」变成「能分章讲述的选集」。分组只影响展示、不落库；勾选多少由用户决定（视频导出保留 30 部上限防超长渲染）。

实现上后端给 SLIDES 注入 `group` 字段（年份「N 年」/子分类路径/首个收藏夹名，空归兜底组）并按组分排序（年份降序、其余按出现顺序），模板按 `groupStyle` 选三套之一（无分组退化为直排，行为不变）。中途还修了总览式样板的显示 bug：组内卡片原本依赖 IntersectionObserver 时序 + 组切换用数字/字符串严格比较 `===` 恒不等——导致切组后卡片一直不显示，改为比较统一转字符串 + 切视图时主动浮现。

## v0.18 推荐导出细化：BGM 多曲 / 副标题 / 封面可调

v0.17 分组后，用户又提了几个导出体验的细节：BGM 想多选几首连续放、主标题下能配副题、开场封面能调大小、视频导出别带自动导览徽标。这版一一落地：**BGM 多曲**——向导可多选，模板内按序连续播放、每首快结束时提示下一首，视频导出多曲用 ffmpeg 按序拼接后混入音轨；**副标题**——主标题下方可配副题，存在则显示、为空则隐藏（替换掉原来写死的副题文案）；**封面大小**——预览三档可调（小/中/大），默认比原来大 15%；**record 模式隐藏自动导览徽标**；**开局代表秀**——推荐正片展示全部勾选媒体，但开场闪回只秀「开场子集」（步骤2 可自定义，默认按评分预选 10 张、无评分随机补足），防止推荐多了开场挤成一团。随后又补了**主题简介（序言页）**——开局后插一屏 PROLOGUE 概括主题；**结尾回顾墙**——正片末把全部封面缩小铺满成「这一季 N 部」+ 致谢收尾，不再戛然而止。分享物从「能分章」到「配乐 / 题字 / 序言 / 谢幕」都能自己调。功能越堆越多，用户把「设置主题」一路拆成向导的独立步骤——**①勾选媒体 → ②内容·主题（标题/副题/简介）→ ③页面·交互（BGM/分组/开局封面/显示时长）→ ④预览导出**，不再一屏堆砌；又给**五个阶段各配了独立停留时长**（开局定格 / 序言 / 章节转场 / 详情 / 结尾），导览节奏完全自己掌握。

## v0.18.1 收藏夹筛选排序：补上「查找与排序」

v0.18 把资料库的「进货」和「对外产出」都打通了，但收藏夹 tab 内容一多就难找——几十上百部番按默认顺序平铺，想快速定位一部、或者按年代回顾收藏，只能翻页硬找。这版给收藏夹内容区加了工具条：**标题模糊搜索**（输入即筛，300ms 防抖）、**首播年份下拉**（只看某一年的收藏）、**排序下拉**（默认 / 首播年份）+ **升降序切换**（按年份排时未知年份垫底）。收藏夹从「只能平铺翻页」到「能搜、能按年代过滤、能排序」。实现上后端 `listByCollection` 补 `sort/order` 参数（与媒体页 `listFiltered` 同款写法），前端复用媒体页筛选区的 `.media-filters` 视觉，改动小、不新增字段。

## v0.18.2 推荐导出「同时展示」+ 勾选回看 + 开场节奏修复

v0.18.1 之后，用户在推荐导出上又踩了几个真实痛点。一是**某年分组媒体太多**时，一部一屏地展示，总时长爆炸——于是加了**「每屏同时展示 N 部」**：一屏网格多卡（1-10 档，默认 1 保持原样），大组几屏就播完；为了网格好看，封面做了**毛玻璃全图**（模糊放大铺底、完整海报居中，宽格子里再也不裁图）、末行**居中**、序号与单部屏同款描边样式、按 N 自适应列数（9 条上5下4、7 条上4下3）。二是**草稿恢复后勾选看不见**——当前筛选/分页跟草稿里的媒体对不上，只见计数不见卡片，于是步骤1加了**「仅显示已勾选」开关**，按 id 圈选、无视筛选，一眼看清上次选了啥。三是**开场节奏不对**——自动播放从 t=0 就抢跑计时，开场不按「显示完全后停留秒数」、序言也被跳过，这是个隐藏挺久的 bug，这版用「开场结束才统一启动自动导览」修掉了。加上左上角角标可配置、结尾平滑过渡。推荐导出从「能播」到「播得紧凑、看得明白、节奏可控」。

## v0.23 片源不再只是一个网址，而是可追溯、可替换的资产

v0.22 让每个 Clip 知道自己属于哪个作品条目和 Episode，但“从哪里播放、下载失败怎么办、换版本后时间码还准不准”仍没有稳定答案。v0.23 把远程片源拆成 Provider 的稳定包与源项，搜索必须由用户显式触发，候选不会默认采用；逐集映射中的冲突、特别篇、缺集都要被解释和确认。远程流、本地原片、下载文件和裁剪结果统一成 VideoAsset，主线路与备用线路只由用户切换，临时 URL 过期也不会抹掉稳定身份。下载进入可恢复任务，Clip 同时保存资产、revision 和毫秒时间；需要长期素材时受控裁剪，换源时用双播放器锚点计算 offset/drift，确认后创建新 Clip 而不是覆盖历史。这样，“我记住的场景”终于不再依赖某个随时失效的网址，而拥有完整来源链路。

## v0.23 Provider、订阅与快捷播放形成完整入口

v0.23 把片源身份、安全策略和资产链路搭好后，继续按同一版本完善真实入口：Jellyfin 作为可选个人媒体库，只同步安全边界内的作品和分集；Mikan、动漫花园和通用 RSS 保存 BT 发布但不假装已有 BT 播放器；声明式 Web Selector 只执行受支持的公开媒体规则。随后加入 Animeko 兼容订阅，把来源配置变成一次性全局管理，并把普通播放改为“Episode → 并行查询 → 自动选择 → 播放”。用户不再需要先采用包和手工建资产；只有固定、下载或剪辑时，临时候选才进入 v0.23 的映射与资产治理链路。

## v0.22 番剧资料先站稳，片段才有真正的上下文

v0.20 把片段编排成了混剪，但片段的上游仍然依赖网页标题和被动归组：作品资料不完整、集的身份不稳定，远程资料更新也缺少安全边界。v0.22 先把地基往前挪——借鉴 Animeko 的资料模型和外部 ID 思路，却不把项目变成播放器。批量建库被拆成独立全屏同步中心：完整候选一次拉回后再本地分页、筛选、跨页审核，确认后交给可恢复后台任务；单媒体完善则留在详情页，未关联时主动搜索并明确单选，已关联时按稳定 ID 原地刷新，还能补 OVA/特别篇。更换错误关联不再是“覆盖一下”：先列出旧集，默认全部保留，Clip-backed 集永远锁定，其他用户编辑过的集也要高等级确认。作品下增加具体条目层，远程集资料独立缓存，新增、改号、消失都不破坏已经打下的 Clip。这样，后续的标签、时间线、检索和片段素材才知道自己究竟属于哪一个条目、哪一集。远程视频源获取留给下一版，先让“我记住的这个场景”拥有可靠的作品上下文。

v0.19 让一个 Clip 可以从时间码变成裁剪视频、截图或录屏兜底，但一部作品里几十个高光仍然散着：想做推荐，得重新找素材、抄时间、用外部剪辑器排序。于是 v0.20 把「片段」提升为可恢复的**制作稿**：从媒体详情进入三栏工作台，按集挑高光、拖成时间线，在项目里微调入出点、标剧透、写短标题、调原声；素材可从本地视频精确裁剪、受控直链或上传准备，草稿和 BGM/导出设置都会回来。导出时不是拿当下草稿碰碰运气，而是先冻结一份快照，再把横竖各异、甚至无音轨的素材标准化为完整前景 + 模糊背景的 16:9 成片，按 FULL 或 SAFE 版混剪，出错/取消也不会毁掉旧成片。资料库从「能找回精彩瞬间」继续走到「能把一部作品的精彩讲成视频」。

## v0.26 媒体级一键推荐视频：用户选内容，系统保成片

v0.20 的高光工作台已经能把一部作品的 Clip 编排成混剪，但流程仍偏向手工剪辑：准备素材、设置参数、导出都需要用户自己推进。v0.26 把入口收敛为“用户勾选片段 → 模板预览 → 确认导出”：第一步已经让单媒体 HTML 模板读取真实作品档案与制作稿片段，通过受控预览 URL 展示片头、跨集章节、片段信息提示和推荐回顾墙。缺源项不再被悄悄吞掉，而是连同原因留在预览中；下一步再让同一份场景计划驱动可用版和正式 MP4。项目继续保留高级调整能力，但不把自己变成专业剪辑器，最终精修仍交给 Premiere 或 DaVinci。

*规律回看：v0.1~v0.6 在搭「存取」的地基，v0.7~v0.8 把「数据模型」拓宽，v0.9~v0.11 把「组织与治理」做厚，v0.12~v0.13 开始「对外产出」，v0.14~v0.15 把「进货渠道」打通并补齐中文名，v0.16 给对外产物加上「BGM 配乐」，v0.17 给推荐导出加「分组讲述」，v0.18 把推荐导出的「配乐 / 题字 / 开场合意」调顺手，v0.18.1 给收藏夹补上「查找与排序」，v0.18.2 让推荐导出「同时展示、看得明白、节奏可控」，v0.19 让瞬时片段产出真实素材，v0.20 则把这些素材组织成可分享的混剪初稿，v0.26 把单媒体混剪收敛成可快速生成的推荐视频。每一步都由上一版的真实使用痛点驱动。*
