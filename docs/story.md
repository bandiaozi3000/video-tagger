# Video Tagger 项目故事线

> 每版更新在此追加一段「为什么做 → 做了什么 → 与上一版的延续」，把版本演进串成一条线。
> 功能细节看 [CHANGELOG](../CHANGELOG.md)，每天的工程过程看 `docs/worklog/`，这份只讲故事的脉络。

## v0.1 奠基：从零到「打标能搜回」

一个看番/学习时随手记素材的念头。写了两份设计文档（Java + MySQL + Milvus + Docker 架构 + 17 个任务实施计划），搭起 Spring Boot 骨架 + 三层存储（MySQL 元数据 / Milvus 向量 / 本地封面），打通第一条闭环：**浏览器扩展打标保存 → 片段入库 → 关键词（ngram 全文）+ 向量（Embedding + 余弦）混合搜索 → 扩展浮层里看回**。这一版全是地基，没有花活。

## v0.2 可用化：从「能存」到「好存好找」

第一版能用但糙。补上编辑/删除/追加标签、**连续打标模式**（保存后浮层不关、时间戳跟播放进度走）、快捷标签位（Ctrl+Shift+1~9）、标签补全、重复片段提示、视频时间线视图、相似推荐、统计面板。同时修了三个真问题：Milvus 冷启动竞态（语义搜索永久哑火）、3 秒去重误吞数据、Embedding Key 硬编码泄密。引入 Flyway 管 schema。

## v0.3 番剧三层：散落片段第一次有了「家」

之前存下来的只是一条条片段，越打越乱。这版做核心架构转折——**番剧 → 集(含季) → 片段**三层结构，三层都能打标，按标题正则自动归组，卡片墙/详情页 + 追番状态/评分/作品级标签，三层向量化 + 跨层 RRF 混合检索，收藏夹与筛选器，LLM 后台归组（判断不同季/翻译是不是同番），「看完自动弹」集级打标。从「素材堆」变成「番剧资料库」。

## v0.4 封面体系：每一条标记都有了脸

之前片段只有文字和时间戳，翻起来没画面感。这版给片段**截帧封面**（保存瞬间 canvas 抓当前帧）、给每集**自选高能画面**当集封面（未选则智能取标记最多的片段帧）、番剧封面缺失时用代表性片段帧兜底。全链路（搜索/时间线/相似/集列表/番剧卡片）带缩略图，封面生命周期级联清理。

## v0.5 详情页：点卡片就能钻进去

列表开始有封面了，但点卡片还只能跳回原视频。这版做**片段/集详情页**——大图 + 元信息 + 同集其他片段 + 相似片段，链式跳转 + 视图历史栈逐层返回；列表统一改横排缩略图卡片。浏览体验从「平铺」到「可下钻」。

## v0.6 双图封面 + 集删除：细节补完

截图一次出两档——缩略图（列表）+ 详情大图（悬浮预览、详情 hero）；补上**集删除**及级联清理（片段/标签/封面/向量全带走）。小版本，把浏览和清理的缝隙填上。

## v0.7 媒体格式细分：不只番剧，什么内容都能收

模型上把「番剧」泛化成「媒体」，新增**格式**（视频/图片/文字…）与**子分类**（视频：番剧/电影/电视剧…）两级可维护字典，图片/文字是单层媒体只有视频带集/片段。格式 tab 导航、格式/子分类筛选、管理弹层、统计分布、按域名/标题自动识别。anime→media 全面改名（向量前缀保留免迁移）。资料库从「番剧专用」变成「多形态内容仓库」。

## v0.8 备注 + 搜索增强：搜索从「找片段」到「收集素材」

媒体/集层加**备注**（参与关键词与向量语义检索，变更自动重嵌），搜索命中词**全字段高亮**一眼看出来源，新增**按媒体聚合**（结果按所属媒体分组，顺着一部部收集话题素材）、**时间范围筛选**（近 7/30/90 天）、结果角标。搜索的用途从「找回一条」升级为「围绕主题收集」。

## v0.9 标签补全上下文 + 标签管理页：标签从「随手打」到「可治理」

补全带**媒体上下文**（该媒体已用标签优先 + 全局高频兜底），打标时顺手；新增**「标签」管理 tab**——词库全景 + 按媒体维度，支持**改名**（同步 clips.tag 冗余列 + 引用自动重嵌）、**合并**（高然→高燃）、**删孤儿**（被引用拒绝）。标签第一次有了「词库治理」的入口。

## v0.10 分类树 + 标签池维护增强：组织维度从「扁平」到「树」

子分类改邻接表，**任意层级细分**（番剧 → 热血 → 战斗），筛选/搜索**子树收敛**（选父级连下级一起），管理弹层树化 + 删除保护升级。标签池维护增强：分页、全选本页、批量删孤儿、**新增标签弹层**（实时去重 + 批量入池）。

## v0.11 收藏夹 + 详情标签池：浏览更顺、热度可视化

收藏夹升级为独立 tab（列表 + 内容网格管理视图），卡片**快捷收藏**（♡ 弹出勾选浮层），收藏夹上下文删媒体改「移出收藏夹」防误删。详情页标签展示升级为**标签池**——每标签带引用次数徽标 + **五档分级配色**（越热越暖、金档大号光晕），媒体/集/片段三处统一。同时修了跳转失效（bangumi 路径）与跳转 key 不一致。

## v0.12 渐变环流推荐导出：从「自用工具」到「能产出分享」

打标半年攒了一堆番，想做成漂亮的东西发出去。这版做出**渐变环流推荐导出**——勾选多部番剧 → 生成**自包含 HTML**（深色霓虹、封面围成椭圆轨道自转、自动导览，base64 内嵌封面、单文件无外部依赖，可直接发人/手机打开）→ 用 Node + puppeteer 连系统 Chrome 以录制模式播放导览、CDP 抓帧 + ffmpeg 合成**导出 MP4 视频**（720P/1080P/4K）。项目第一次能「产出分享物」，而不只是自己检索。

## v0.13 推荐导出向导化：导出流程重做成「向导」

v0.12 导出体验不顺（勾选框藏得太深找不到，用户直说「流程不太喜欢」）。这版重做：**独立「推荐」tab 分步向导**——① 勾选要推荐的番剧 → ② 填主题文案（实时预览大标题）→ ③ 生成预览（**弹窗内嵌 iframe 直接看效果**），没问题再**导出视频**（选标题/MP4·WEBM/清晰度/**保存位置**走浏览器保存弹窗，File System Access API）。另修复用户实测反馈：预览弹窗太小（CSS 特异性 bug，一直被 560px 卡着）→ 撑满视口 + 全屏按钮；导出视频卡顿（4K 抓帧掉到 19fps、WebM 软解）→ 抓帧质量与编码参数调优，1080P 帧率稳到 ~59fps。

## v0.14 番剧同步：资料库第一次能「批量进货」

库里多是手工整理的番，用户想按年份批量把历年的番（名称/年份/封面）搬进来。调研一圈数据源（Bangumi 大陆超时、MAL 需 OAuth、jikan 不稳、omofuna 有 JS 反爬），锁定 **AniList**——免认证 GraphQL 直接按首播年份分页拉全量。这版给媒体加上**首播年份 + 原生日文标题**两个字段，媒体 tab 出「**同步番剧**」入口：勾选年份（2000~2026 可多选）→ 一键导入，重复自动跳过、封面异步补全，标题先以日文原名占位、后续可改中文。资料库从「手工一朵朵」到「按年批量进货」，为后面按年代检索/回顾打底。

番剧同步进来的同一天，推荐页的两个新筛选暴露出一个**数据层的断层**：用户打标签一直打在**片段**上，收藏夹/标签筛选却按**媒体**过滤——结果媒体标签全空，标签过滤「无效」不是 bug，是标签没有「长上去」。于是这版补上**标签三级同步**：片段标签自动并集到所属集、再到所属媒体（单向向上、幂等落库、删除不级联由用户手动清），历史数据一键全量同步——「奇幻恋爱」这类词从 `mediaCount=0` 一夜变 `6`，推荐页按标签挑番真正可用了。同一轮还修了收藏夹过滤失败（列表接口缺 `collectionId`）并补上「全选本页」。从「进货」到「货能按标签挑出来」，v0.14 把资料库的入口和出口都打通了。

## v0.15 omofuna 中文源：进货渠道从「日文原名」补上「中文名」

v0.14 用 AniList 批量进货，但标题是**日文原名**占位，要手动改成中文。用户又翻出当初调研时被排除的 **omofuna**（旧结论「maccms+JS 反爬」）——重测推翻旧判断：URL 结构能解析（`show/{分类ID}--------{页码}---{年份}.html`）、**真实浏览器点「继续访问」就能过验证**、封面无防盗链，且给的是**中文标题**，正好补 AniList 的缺口。但 omofuna 详情页没有日文原名，中文标题和 AniList 日文牌对不上号，同番会并存两条（grilling 拍板「新增 + merge 治理」，重复靠既有合并功能手动统一）。这版做出「**⇄ 同步中文番剧**」：勾选年份 → 后端后台任务用 Node+puppeteer 连系统 Chrome 真实浏览器逐页抓取（日漫/动画/剧场，自动过验证、hash 去重、页间限速）→ 中文标题/年份/封面逐条导入。因为要跑 20~40 分钟，顺手做了**异步任务 + 进度轮询**（POST 秒回 taskId、前端轮询已抓页数/条数、刷新可恢复）。资料库的进货渠道从「日文原名」到「中文名」都打通，重复番靠既有合并统一。写抓取时踩了两个坑：验证页点按钮会触发 reload、轮询时 evaluate 抛「Execution context was destroyed」要容错；omofuna 的详情 hash 是 **24 位 hex 不是 32 位**（正则写错一页都导不进）。

## v0.16 推荐 BGM：分享物第一次能「带着音乐出门」

v0.13 的推荐导出能生成自包含 HTML 和视频，但都是「无声」的——用户想加背景音乐，BGM 名称和播放进度也要在页面里显示。这版在推荐向导「设置主题」加「🎵 添加 BGM」：选本地音频（mp3/m4a/wav，≤20MB）→ base64 **内嵌**进单文件 HTML（保持可分享，右下角 BGM 条显示名称 + 播放进度 + ♪ 播放/暂停）；导出 MP4/WEBM 时 ffmpeg 把 BGM **循环混入音轨**（`-stream_loop -1`，导览多久播多久）。视频从「默片」变成「带配乐」，分享物第一次能「带着音乐出门」。实现上 BGM 以纯 base64 走 JSON body，HTML 注入 data URI、视频解 base64 写临时文件再混音，两端复用同一份音频。

---

*规律回看：v0.1~v0.6 在搭「存取」的地基，v0.7~v0.8 把「数据模型」拓宽，v0.9~v0.11 把「组织与治理」做厚，v0.12~v0.13 开始「对外产出」，v0.14~v0.15 把「进货渠道」打通并补齐中文名，v0.16 给对外产物加上「BGM 配乐」。每一步都由上一版的真实使用痛点驱动。*
