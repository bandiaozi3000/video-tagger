# 疑问清单

### [#1] 「最近观看」和「全部媒体」分别根据什么判定？
- **日期**：2026-08-06
- **模块**：媒体管理
- **疑问**：媒体栏两个 tab「最近观看」和「全部媒体」的收录范围、排序依据是什么？
- **回答**：
  - **最近观看**（`/api/media/recent` → `MediaMapper.listByLatest`）：`LEFT JOIN episode/clips` 聚合，`HAVING latestAt IS NOT NULL`（打过 ≥1 个片段标记才算看过），按 `MAX(clips.created_at)`（最新片段**打标时间**）倒序，取前 100。判据是片段标记时间，非媒体创建时间。
  - **全部媒体**（`/api/media` → `MediaMapper.listFiltered`）：所有媒体（含 0 片段），默认 `ORDER BY a.id DESC`（创建顺序倒序，新创建在前），支持 status/format/subcategory/待确认筛选。
- **验证结论**：正常行为。刚手动创建、未打任何标签的媒体只在「全部媒体」出现，不进「最近观看」——设计如此。
- **备注**：两分支都 `limit=100`，格式/子分类过滤在客户端兜底。

### [#2] 媒体季和集是怎么识别的？识别不到有兜底吗？能编辑吗？
- **日期**：2026-08-06
- **模块**：打标 / 媒体管理
- **疑问**：季/集的识别机制、识别不到的默认值、是否有手动编辑口子？
- **回答**：
  - **识别**：`TitleParser.parse()`（TitleParser.java:38）纯正则从页面标题解析，不调 LLM。季=`第X季`/`Season X`/`SXExx`；集=`第X集/话/章`/`Episode X`/`Ep.X`/`SXEXX`/裸`E123`（E 后须数字）；中文数字转阿拉伯（1~99）。
  - **兜底**：季/集号解析不到存 null（无默认值，排序 `IFNULL(season,0)`，前端显示「本集」）；媒体名解析失败回退去站点后缀的原始标题（mediaTitle 保证非空）；媒体归属前缀命中复用、否则新建 confirmed=0 待确认；子分类默认「番剧」。
  - **编辑口子**：无。`PUT /api/episodes/{id}` 仅备注（`EpisodeUpdateRequest` 只有 note）；媒体层 rename/merge 只改媒体标题；前端只读展示 `S1-Ep2`/`第X集`/`本集`。设计注释预留「后续可扩展标题等」。
- **验证结论**：识别+兜底符合设计（正常行为）；「无季/集编辑口子」是能力缺失 → 已转需求 feature-requests #3（手动编辑 + 默认 S1E1，用户确认采用）。
- **备注**：2026-08-06 用户确认采用 S1E1 兜底策略，副作用已知（多集解析不到会都变 S1E1，靠手动编辑修正）。
