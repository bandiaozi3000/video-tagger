# 语义检索质量评估 · 完整流程

> 日期：2026-08-06
> 状态：基线已跑出（Recall@10 73.3%），数据量小（5 条片段向量），结论看**缺口形状**而非绝对值。
> 关联：v0.9 检索质量优化前置评估；工具链在 `docs/eval/`（golden set / 脚本 / 结果存档）。

---

## 1. 背景与目标

对当前 `/api/search` 的**语义检索质量**做一次可量化的体检，回答四个问题：

1. **召回**：该搜到的搜到了吗 → Recall@K
2. **排序**：相关的排前面吗 → MRR
3. **拒绝**：无关乱搜能挡吗 → 空返回率（0.45 阈值校验）
4. **层级**：media / episode / clip / mixed 四维度各自质量

评估结果作为 **v0.9 检索质量优化的基线**，用数据决定"改哪里、改完有没有效"。

## 2. 评估对象（当前检索链路）

```
用户查询
  ├─ 关键词路：MySQL LIKE（媒体/集） / FULLTEXT MATCH...AGAINST（片段，已 BM25）
  └─ 向量路：text-embedding-v4 (1024d) → Milvus ANN（clip_embeddings_v2）
        └─ 阈值 min-cosine-score = 0.45（配置化，ENV 可覆盖）
  ↓ RRF 融合（K=60） → 结果（media/episode/clip）
  ↓ 后置过滤：format / subcategory / from-to 时间范围
```

向量文本：MEDIA=`标题+别名+备注+标签`，EPISODE=`标题+备注+标签`，CLIP=`标签+备注`（均很短）。

## 3. 方法论

### 3.1 评测集（golden set）

文件：`docs/eval/search-golden-set.json`，当前 51 条。每条：

```json
{ "query": "查询词", "dim": "mixed|media|episode|clip", "expected": ["应命中字段子串"], "shouldEmpty": false, "category": "类别" }
```

- **expected**：应出现在 top-K 结果的 `title / mediaTitle / tag / note` 任一字段的子串（大小写不敏感，命中任一即该条召回）。
- **shouldEmpty=true**：负样本（乱搜），校验阈值能否正确挡掉无关查询。
- 覆盖 6 类：字面/标签命中、近义/语义召回、描述性查询、媒体级、集级、乱搜拒绝。

**构造原则**：expected 标的是「**一个好的搜索应该召回什么**」（正确标签），而非「当前系统召回了什么」——这样 FAIL 条目才是真正的缺口。

### 3.2 指标口径

| 指标 | 定义 |
|---|---|
| **Recall@K** | 期望命中数 ÷ 期望总数（正常条目平均，K=返回上限 10） |
| **MRR** | 首个期望命中的 `1/rank`（排序质量，正常条目平均） |
| **空返回正确率** | 负样本中正确返回空的占比（阈值拒绝能力） |
| semanticEnabled | 每次查询的向量是否生效（全 true 才算语义评估有效） |

## 4. 工具链用法

```bash
# 前置：后端已起 + 已配 EMBEDDING_*（否则 semanticEnabled=false，评估仅供参考）
node docs/eval/run-search-eval.js                        # 默认 golden set + localhost:8080 + K=10
BASE_URL=http://localhost:8080 K=5 node docs/eval/run-search-eval.js
node docs/eval/run-search-eval.js > docs/eval/results/YYYY-MM-DD-baseline.txt   # 存档
```

脚本逐条打真后端 → 算指标 → 输出汇总 + 逐条明细（含 top5，肉眼复查"为什么没搜到"）。

## 5. 基线结果（2026-08-06）

### 5.1 汇总

| 指标 | 值 |
|---|---|
| Recall@10（45 条正常查询） | **73.3%** |
| MRR | **0.722** |
| 空返回正确率（6 条负样本） | **100%** ✓ |
| semanticEnabled 全 true | 是 |

### 5.2 分类表现

| 类别 | 结果 |
|---|---|
| 字面/标签命中（10） | **全过**（关键词路稳） |
| 近义/语义召回（12） | **过半失败**（主要缺口） |
| 描述性查询（8） | 部分失败 |
| 媒体级（8） | 基本全过 |
| 集级（6） | 1 条失败（`乱马1/2 第一集` 无对应集） |
| 备注/复合命中（1） | 过 |
| 乱搜拒绝（6） | **全过** |

### 5.3 失败明细与根因

**① 近的近义词召回，远的全空**
- 过：`太空`→宇宙、`宇宙空间`→宇宙、`小可爱`→可爱杉浦
- 挂：`萌`/`治愈`→可爱、`搞笑`/`出丑`/`尴尬`/`坏笑`/`丢脸`→狼狈，**全部返回 0 条**

**根因**：返回 0 而非返回错结果 → **0.45 阈值把"较远但合理的语义查询"直接挡掉**，不给低置信结果。阈值是按 text-embedding-v4 无关查询 baseline（~0.2~0.4）校准的，但对合法近义查询同样偏严。

**② 备注在向量里的作用有限**
- 查 `哭` 返回了集结果，而 note 含「哭唧唧可爱」的片段没排上来 → 向量文本 `标签+备注` 的备注信息没顶起来。

**③ 集级 `乱马1/2 第一集` 挂**
- 该媒体的集标题是「12/13_哔哩哔哩_bilibili」（无作品名），纯数据形态问题，非检索缺陷。

## 6. 局限（务必注明）

- **数据量极小**：仅 4 媒体 / 5 片段向量。73.3% 这个数会随数据增长大幅变动，**看缺口形状而非绝对值**。
- golden set 是静态标注，数据增删后标注会过时，需定期维护。
- 匹配按子串，`expected` 需与真实字段内容对齐，否则误判。

## 7. 对 v0.9 的指导（数据说话）

| 优化项 | 预期补的缺口 |
|---|---|
| **阈值校准/降档**（0.45 → 动态/更宽容） | `萌`/`治愈`/`搞笑` 这批"返回 0"的 |
| **同义词/查询扩展** | `萌`↔`可爱`、`搞笑`↔`狼狈` 这组近义 |
| **上下文增强**（父层信息+备注拼进向量文本） | 备注没顶上来（查「哭」） |
| 数据量增长后复跑 | 校验上述结论 |
