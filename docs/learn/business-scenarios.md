## 保存识别与手动映射（合并即记住别名）

### 业务场景
库里已有媒体 **A**，但保存片段时，视频标题看似不同、实际是同一部（如不同播放源的标题变体），导致识别建了一个**不同名的媒体 B**。库里明明存在 A，却识别不到 → B 与 A 其实是同一个媒体。

### 痛点
- 目前只能靠**手动合并** B→A 来纠正。
- **合并过一次，下次再保存还要再合并**——B 的识别名没被记住，同标题再次保存会反复重建 B，永远合不完。
- 要么「边存边合并」反复劳动，要么「等全部片段存完再合并一次」——都在等、都在重复。

### 方案细节（合并即记住别名）
**核心**：合并 = **搬内容 + 记住别名**。手动合并 B→A 的那一次，系统顺手把「B 的识别名」记为 A 的别名（标题映射），之后保存自动受益。

- `MediaService.merge(B→A)`：合并时自动存标题映射 `TitleParser.parse(B.title).mediaTitle() → A`（幂等 upsert；B 标题为空则跳过）。
- **保存识别流程不变**，归属判定优先级：**用户勾选 > 标题映射 getByTitle > URL 指纹 > 标题前缀匹配 > 新建**。
- 效果：下次保存「B 第X集」→ 解析出系列名 B → 映射命中 A → 片段直接挂到 A，**不再新建 B、不再重复合并**。

### 特殊场景：多别名
- 同一部有多播放源 / 多标题变体（A 站叫「甲」、B 站叫「乙」）→ 两次保存分别误建 B1(甲)、B2(乙)。
- 处理：分别合并 B1→A、B2→A → 映射「甲→A」「乙→A」两行**累积**，都指向 A → 之后两站保存分别挂到 A。
- 管理：媒体详情页「别名」区展示该媒体全部别名，可逐个 ✕ 解除。

### 关键决策
- **默认记住别名**（合并时自动存映射，不加勾选选项）。
- 合并 = 搬内容 + 记别名，**一套完整流程**。
- **保留「保存识别已存在」（标题直匹配）**：它管常态自动归位（标题一致时），别名管例外兜底（同部不同名时），互补不重复——删掉直匹配会导致正常标题每次保存都新建重复媒体。
- 映射键 = `TitleParser` 解析出的系列名（与保存识别同一口径）。

### 涉及改动
- 后端：`MediaService.merge` 注入 `TitleMappingService` 存映射；`TitleMappingService.listAliasesByMedia(mediaId)`；`GET /api/title-mappings/aliases?mediaId=`。
- 前端：媒体详情页「别名」区（展示 chip + ✕ 删除，为空自动隐藏）。
