# 产品规划审视（待办参考）

> 日期：2026-08-10　性质：资深产品经理视角的产品缺口分析，**是否实施待用户决定**。
> 已实现的功能底子很扎实，本文聚焦「把已有数据变成资产」的方向，不做功能堆砌。

## 产品定位

**个人二次元资料库**——核心闭环「采集 → 组织 → 检索 → 回看 → 产出」已打通：
- 采集：浏览器扩展打标 + AniList/omofuna 同步
- 组织：媒体/集/片段三层、标签池、分类树、收藏夹
- 检索：关键词 + 向量语义 + 按媒体聚合
- 消费：详情页、时间线、一键跳回原视频
- 产出：推荐导出（HTML/视频，分组/配乐/题字/序言/谢幕）

---

## 一、最该补的缺口（按优先级）

### P0 数据安全——最致命的盲区 ⚠️
当前**完全没有备份/恢复机制**。数据分散在：MySQL（媒体/标签/收藏夹）+ Milvus（向量）+ 本地封面 + `data/exports`。重装/换机/数据库损坏 → 全部心血蒸发。

- **为什么急**：本地私有工具的生死线，积累越久越危险
- **怎么做**：① 一键备份（SQL dump + 封面文件 + Milvus 导出）；② 恢复入口；③ 数据导出（JSON/CSV 兜底）
- **成本**：中等，价值是「保命」

### P1 年度回顾报告——被浪费的情感资产
已有最值钱的数据：每部的打标时间/评分/追番状态/标签/打标数。但统计页只是干巴巴的柱状图。

- **为什么值得**：B站年度报告式「今年看了 47 部番、标记了 320 个片段、最爱 XXX、标签热度最高『热血』」——数据全有，情感价值拉满，契合「给每一帧热爱打上印记」的定位
- **怎么做**：复用统计接口做「年度/月度回顾」页，跑马灯式展示
- **成本**：低（数据现成）

### P1 主题素材导出——从「收藏」到「产出」
推荐导出证明「对外产出」走得通，但那是给番剧做导览。还缺：**围绕话题收集素材**。

- **场景**：写「燃系打斗名场面」文章，现在只能一条条翻。若能「搜索『爆种』→ 勾选片段 → 导出成带图带备注的素材笔记/清单」→ 从追番工具变学习工具
- **怎么做**：搜索结果批量导出（复用推荐导出渲染管线，换模板）
- **成本**：中高，是从「资料库」到「生产力工具」的跃迁

### P2 移动/异地访问（可选）
纯本地 + 回环绑定，地铁上翻不了。可做「只读分享链接」/局域网访问。隐私敏感，优先级低。

## 二、已有功能还能完善的

### 1. 搜索质量（最该投）
- **标签规范化**：TODO 里「高燃/热血」分裂 = 搜索结果漏召回。近义标签合并/别名表应提优先级
- **搜索记录/常用检索**：没人记搜过什么，二次搜要重新打
- **检索质量评估**：Recall@10 73.3%，提升空间大

### 2. 统计深化
现在只有「总量 + Top 标签 + 分布」。可加：追番完成度（看完/弃番占比）、按年份追番史、评分分布、标签热度随时间演变。

### 3. 收藏夹
- 手动排序（现在按 id）
- 备注/说明（为什么建这个收藏夹）
- 「按标签自动进收藏夹」的规则收藏夹

### 4. 推荐导出
- **导出模板复用**：一次满意的配置（标题/BGM/分组/时长）存成模板，下次一键套用
- 预设主题（情人节/生日/年度总结一键风格）

### 5. 打标效率
- 批量给「整集」打标
- 打标模板 / 常用标签分组

---

## 三、如果只选三件事（价值/成本比）

1. **数据备份**（P0，保命）
2. **标签规范化 + 搜索质量**（核心功能的核心体验）
3. **年度回顾报告**（低成本高情感价值，最能体现产品调性）

> 结论：项目缺的不是「更多功能」，是「把已有数据变成资产」——备份、回顾、素材导出。
> 这三件做完，从「好用的工具」变「有温度的个人资料馆」。
