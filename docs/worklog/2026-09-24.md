## 增量一：番剧同步加地区筛选 + 标题直查 + 单项同步

### 需求（用户原话，两轮收敛）

> 分析番剧同步除了年份，季度外，还有其他筛选条件，比如地区这些
> 接，把 bangumi 支持的过滤条件都加上，下拉框形式，另外支持标题查询，可单个同步
> 算了，本次只加地区 / Q1：动画暂时写死 / Q2：不是本地过滤，你直接拿标题去查 Bangumi，然后返回一条。我只同步该条就是了。另外同步过来吧日期评分什么的和本地媒体能关联的也同步过来

### 先查证：Bangumi 到底能筛什么（决定"都加上"的边界）

官方 `open-api/v0.yaml`（`POST /v0/search/subjects`）**只有这些**：
`type / meta_tags / tag / air_date / rating / rating_count / rank / nsfw`，外加 `sort ∈ {match, heat, rank, score}`。
条件之间是**且**，`type` 内部才是**或**。

**没有 region / area 字段** —— 地区只能落在标签体系里。于是查本地已存数据（317 条 `external_work.raw_json`）：

| 探针 | 结果 |
|---|---|
| infobox 有 `地区` 键 | **仅 1 条**（`青春有害健康`=中国，且是「其他」格式，不是动画） |
| 动画（type=2，n=275）的 `meta_tags` | 日本 238 / 中国 22 / 美国 6 / 空 2；另有 TV 226 / WEB 26 / OVA 8 |
| 同批的 `tags`（用户标签） | 日本 251 / 中国 24 / 美国 8 / 欧美 6 |
| 全库 `meta_tags` 去重值 | 日本 285、TV 265、漫画改 163 …、欧美 3 |

**结论**：地区走 `meta_tags`（公共标签，人工维护，比用户标签可信）→ 白名单 `日本 / 中国 / 美国 / 欧美`。

> 踩坑：SQL 里用 `char(0x5730,0x533A using utf8mb4)` 拼中文做 `LIKE`，结果**恒为 0**，差点误判"库里没有地区"。
> 探针 `select hex(char(0x4E2D,0x6587,0x540D using utf8mb4))` 返回 **NULL** 才露馅。
> 正确姿势：`cast(col as binary) like concat('%', unhex('E59CB0E58CBA'), '%')`。

### 改动（本次范围：只加地区 + 标题查 + 单项同步）

| 层 | 文件 | 内容 |
|---|---|---|
| 后端 | `SyncRangeFetchRequest` | 加 `region`（可空 = 不限） |
| 后端 | `MetadataProvider#discoverRange` | 签名加 `region` |
| 后端 | `BangumiMetadataProvider` | `REGIONS` 白名单 + `normalizedRegion()` → `filter.meta_tags:[region]`；非法值 422 且**不发请求** |
| 后端 | `MetadataSyncService#discoverRange` / `MetadataSyncController` | 透传 `region` |
| 前端 | `index.html` | ① 地区 `<select>`（不限/日本/中国/美国/欧美）② 「标题查询」输入框 + 查询按钮 |
| 前端 | `bgm-sync.js` | `pick.region` 进 localStorage；标题查询打 `/preview`（`mode=WORK`）；**行尾「同步」按钮**（`commit([item], append=true)`，`preventDefault` 拦住 `<label>` 连带勾选）；标题结果默认只勾第一条 |
| 样式 | `bgm-sync.css` | `.bgm-select` / `.bgm-input` / `.bgm-row-sync` |
| 测试 | `BangumiMetadataProviderTest` | +3：发 `meta_tags`、region 空则不发、非法 region 422 且零请求 |

**后端零新增接口**：单项同步复用既有 `/api/metadata-sync/commit`（本就逐项独立事务），标题查询复用既有 `/api/metadata-sync/preview`。

### 验证（实测）

- `mvn -o test`：**445 passed / 0 failures / 0 errors**（92 个 suite）；新增 3 条 region 测试在 surefire 报告里确认跑过。
- 隔离实例（`--server.port=18099`，只读端点）打**真实 Bangumi 接口**：

| 请求（2024-04-01 ~ 2024-05-01） | 结果 |
|---|---|
| 不带 region | `total=111` |
| `region=日本` | `total=74`（前三条与全量一致，是真子集） |
| `region=中国` | `total=17` → `小兵传奇 / 反派初始化 / 虚无边境`（全 WEB，国漫命中正确） |
| `region=火星` | `422 地区无效: 火星` |

- 标题查询实测：`{"mode":"WORK","keyword":"上低音号"}` → 20 条，带 `matchType/targetMediaId/recommendedAction`（行尾「同步」靠这三个字段）。

### 未验证 / 留给用户

1. **页面交互未实测**：地区下拉、标题查询、行尾「同步」按钮都只是 `node --check` + id 存在性检查过，**没在浏览器点过**（后端 8080 是 IDEA debug 实例，改 Java 需你手动重启；静态资源我已 `cp` 到 `target/classes/static/`，刷新即可见）。
2. **单项同步未实测**：那条路径会**写库**（建 media/集），我不擅自跑。后端 `/commit` 逻辑本身是旧的、没改。
3. **地区覆盖率缺口**：2024-04 有 20 条被 AND 掉（111 − 74 − 17）——`meta_tags` 不带地区的条目会漏，属标签体系固有，不是 bug。

### 待拍板：`日期/评分` 同步进本地媒体（**本次未动代码**）

用户要求"能关联的也同步过来"，查证后发现**落点不存在**：

- `media.rating` 是**个人评分**（UI 文案「个人评分 0~10」，`index.html` 的 `#media-rating`；后端只有人工改媒体接口 `MediaService:415` 会写它），且建表时是 **`DECIMAL(2,1)`（V3）—— 装不下 10.0**。写 Bangumi 评分进去 = 语义串台 + 溢出。
- 本地 `media` 表**没有** `air_date` 列；放送日期在 `external_work.air_date`，媒体详情页（`v022-media-metadata.js` 的 `md-facts`）**已经在显示**。

建议（等用户选）：候选列表里**显示**Bangumi 评分/收藏数（前端，不落库）；真要落库就在 `external_work` 加列（Flyway 新版本），**别动 `media.rating`**。

- provider 从不发 `filter.nsfw` → 按官方文档默认**包含** R18；本库 `nsfw=true` 为 0 条，暂未暴露。
