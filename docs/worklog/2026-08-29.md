## v0.22 Bangumi 同步查询固定 10 条修复（2026-08-29）

- **根因**：Bangumi `/v0/search/subjects` 的 `limit/offset` 必须放在 URL 查询参数；旧实现误放在 POST JSON，Bangumi 使用默认 `limit=10`，分页逻辑随后因 `page.size() < pageSize` 提前结束。
- **修复**：改为请求 `/v0/search/subjects?limit={pageSize}&offset={offset}`，筛选条件仍保留在 JSON body。
- **回归**：Provider 测试增加请求路径断言；`BangumiMetadataProviderTest` 通过。
- **注意**：已运行的 8080 后端需重启后才加载修复；页面前端本身已传 `limit=1000`。

## v0.22 同步中心 UX grill-me 定稿（2026-08-29）

- **现状诊断**：确认当前同步弹窗混合批量建库、单媒体关联、直接同步、审核和错误反馈，缺少分页、完整筛选、跨页选择、冲突处理、草稿和后台任务；候选卡信息密度与危险操作层级也不合理。
- **产品决策**：批量建库与完善已有媒体同等重要但流程隔离；批量同步改为全屏工作台，媒体详情未关联时使用内嵌搜索面板，已关联时直接刷新。
- **批量审核**：一次获取全部候选，前端分页 20/50/100；默认保持 Bangumi 顺序；提供状态/类型/题材/月/关键词/已选择筛选；所有候选默认不选，全选只作用当前页；独立 checkbox、紧凑卡片、右侧详情抽屉、跨页已选清单。
- **安全边界**：冲突候选禁止直接选择；自动处理全部降级二级高风险入口，只自动创建无匹配项和更新稳定 external ID 关联，标题疑似与冲突全部跳过；不根据标题自动绑定。
- **任务与草稿**：唯一草稿自动保存；确认后创建持久化后台任务，可离开页面继续，不支持取消；成功任务保留 30 天，失败/待处理永久保留；失败项先查看和调整再重试。
- **单媒体流程**：搜索框预填本地标题但不自动联网；最多显示 20 条、不分页、不默认选择，只允许关联当前媒体；支持添加其他条目和更换关联；更换时旧集逐项处理且默认全部保留。
- **文档**：同步更新 v0.22 唯一主 spec 与唯一 plan，新增设计第 10~28 节和实施阶段 G7~G13；明确 `V24/v06` 已删除旧任务表，本次需通过新迁移重新引入 draft/task/task_item。
- **验证**：主 spec/plan 章节索引检查和 `git diff --check` 通过。
- **实施状态**：本轮按用户选择只完成设计与计划，未开始同步中心 UI 重构。工作区中此前中断的 Bangumi 分页代码修正需在 G7 首先补齐测试和验证后再继续。
