## 浏览器探测三层增强 + 重新打包

**背景**：用户反馈"不同的机器 Chrome/Edge 路径不一样"，要求提高探测覆盖率并重新打包。

### 现状分析（三层漏点）
1. **用户级安装**（非管理员装 Chrome/Edge）只写 `HKCU\Software\...\App Paths\`——现有 `queryAppPath` 只查 `HKLM` 两个视图 → 漏
2. **运行中的浏览器**（用户正用着，路径常非标准）没查进程 → 漏
3. **绿色版/自定义目录/精简系统删 Edge** → 自动探测无能为力，需要手动兜底

- **queryAppPath 加 HKCU 视图**：`HKCU\Software\Microsoft\Windows\CurrentVersion\App Paths\`
- **findChromePath 加进程探测**：`findChromeByProcess()` 用 PowerShell `Get-Process chrome,msedge` 拿运行中浏览器真实路径（输出强制 UTF-8 防中文路径乱码）
- **resolveBrowserPath 统一入口**：显式 env → 手动存档(data/settings.json) → 自动探测 → 全 miss 弹系统选择框（`dialog.showOpenDialogSync` 让用户选 chrome.exe/msedge.exe，选完存 data/settings.json 的 browserPath）→ 兜底默认
- startBackend 的 `RENDER_CHROME_PATH` 改走 `resolveBrowserPath()`，探测链全覆盖

## omofuna 抓取他人机器卡死 + 加固（问题 #9）

**背景**：分享桌面版给他人机器，omofuna 同步前端**进度条不动**，后端日志停在「启动 omofuna 抓取」后无输出，任务 RUNNING 卡 60min 才被强杀；**本机复现不了**。

### 根因（读码验证，非配置问题）
1. **`omofuna.js` 的 `page.evaluate`（isVerifyPage/countCards/extractCards）无超时保护**——puppeteer 对页面同步 JS 阻塞/死循环**无法中断**；他人机器网络不稳/渲染差异触发站点 JS 异常分支 → evaluate 无限挂起 → fetchPage 不返回 → node 无进度输出卡死（本机网络好从未触发）
2. `puppeteer.launch` 无显式超时（低配机/profile 锁/老 Chrome 可能卡启动）
3. **后端 reader 丢弃 node 非进度输出** → Java 日志看不到抓取过程（诊断盲区，误以为"无日志=卡死"）
4. 后端 `p.waitFor(3600s)` 总超时太长，卡死空等 60min

### 修复（纯加固，不动抓取逻辑）
- **`omofuna.js` 进程级 watchdog**：3 分钟无新进度行 → `console.error` + `process.exit(1)`。关键：evaluate 挂起**不阻塞 node 事件循环**，`setInterval` 仍触发 → 超时自爆，任务变 ERROR 而非永远 RUNNING
- **`puppeteer.launch` 包 `Promise.race` 60s 超时**
- **fetchPage 每步打 `[omofuna] dbg` 阶段日志**（goto/verify/passVerification/cards/extract）——卡住时最后一条日志即卡点，不再靠猜
- **后端 reader 把非进度行转发到 Java 日志**（`[omofuna-node]` 前缀）——消除诊断盲区
- **后端「无进度超时」**：最后进度超 5 分钟 → `destroyForcibly` + ERROR「抓取无进度超时…」（不再空等 60min）

### 验证
- `node --check omofuna.js` ✅；`mvn -q compile -o` ✅
- 待打包发布（backend jar + 桌面版）后他人机器生效

### 遗留
- 他人机器具体卡点（evaluate vs launch）需等新包在他人机器上跑一次，靠 `[omofuna-node]` dbg 日志确认
- 生产 jar 169MB 超 Gitee 100MB 托管阻塞项仍待定（见上段）
