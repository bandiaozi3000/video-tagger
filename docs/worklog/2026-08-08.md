## v0.15 omofuna 番剧同步（中文标题源，补充 AniList）

**需求缘起**：v0.14 的 AniList 同步标题是**日文原名**占位，要手动改中文。用户再次提出当初调研被排除的 **omofuna**（记忆「maccms+JS 反爬」），给 URL `show/1-----------2026.html` 要求「按年份×页码」判断可否同步。实测推翻旧结论：URL 结构可解析、真实浏览器过验证、给中文标题——可同步，且正好补 AniList 缺口。

### 可行性实测（agent-browser 真实浏览器，先验证再动手）
- **URL 纠错**：`show/{分类ID}--------{页码}---{年份}.html`。用户以为第 1 段是页码，实测是**分类 ID**（1日漫/2国漫/3美漫/4特摄/5动画/24剧场）；页码在第 8 段（`--------` 后）；年份末段且**筛选生效**（2025 页实测卡片全 2025）。
- **反爬可过**：MaccMS「系统安全验证」页，点「继续访问」→ AJAX → reload 放行；纯 curl 带 cookie 也拦，必须真实浏览器。
- **数据字段**：卡片 `a.lazyload[href^="/anime/"]`，`title` 属性=中文标题、`data-original`=封面 webp；每页 72 个 anime 链接 = **36 部×2**（同一番双元素，一个带 lazyload）；每类每年 ~5~6 页；「共检索到 6640 条」是静态假计数。
- **详情页无日文原名** → 「中文反填 AniList 日文占位」无法精确命中，拍板退化为「新增+merge 治理」。

### 拍板决策（AskUserQuestion 两轮）
1. **数据源**：omofuna **补充** AniList（中文标题是 AniList 补不了的缺口）。
2. **重复处理**：**新增 + merge 治理**——omofuna 中文 title 用 `selectByTitleOrOriginal` 精确查重命中跳过；AniList 日文牌不动；同番重复靠既有 merge 手动合并。
3. **范围**：**日漫(1) + 动画(5) + 剧场(24)**，不要国漫/美漫/特摄。
4. **分类标签**（后宫/校园/热血…）：**先不导入**。

### 实现
- **spec**：`docs/superpowers/specs/2026-08-08-video-tagger-omofuna-sync-design.md`（可行性实测证据 + 决策表 + 架构 + 各组件设计）。
- **抓取脚本**：`backend/scripts/omofuna.js`（puppeteer-core 连系统 Chrome）——验证页自动点「继续访问」（点后 `location.reload()`，waitForNavigation + waitForCards 轮询）；按 URL 翻页（0 卡片 break / 全重复 hash break / MAX_PAGES 上限）；`Set<hash>` 去重；页间限速；stdout 进度行 + 每 5 页 JSON checkpoint。`package.json` 加 `omofuna` script。

### 测试与验证
- **单测**：`OmofunaSyncServiceTest`（5 例：新增字段断言/originalTitle 留空/查重跳过/缺封面补下/空 title 忽略/cover 空不下载）+ `OmofunaSyncControllerTest`（5 例：POST 建任务+verify execute/空 years 400/404/current）。`mvn -o -Dtest=...` 全过。
- **CLI 实抓**：`node omofuna.js --years 2026` → 3 分类 14 页、**355 部唯一作品**、失败页 0、年份全 2026、JSON 结构正确。
- **端到端/幂等/merge 联动**：待起后端后走前端弹层验证（勾 2026 → 进度递增 → DONE → loadMedia；重跑幂等 added=0；AniList 日文改中文后重跑命中跳过）。

### 关键 gotcha（都曾实锤踩到）
1. **URL 页码位置**：`show/1-----------2026.html` 的第 1 段是**分类 ID** 不是页码——照用户说法遍历页码会抓到 27 个分类。真实翻页 href：`show/1--------2---2026.html`（页码第 8 段）。
2. **验证页点击触发 reload → context destroyed**：点「继续访问」后 `location.reload()`，reload 中 `page.evaluate` 抛「Execution context was destroyed」被误吞成页面错误。修复：`countCards` try/catch 返回 -1 视为未就绪 + `waitForNavigation` 先等导航完成 + 轮询卡片。
3. **hash 正则 32→24**：omofuna 详情 `/anime/{hash}.html` 的 hash 是 **24 位 hex** 不是 32 位——正则 `{32}` 不匹配导致 extract 全 0（countCards 有数、extract 为空，最隐蔽）。
4. **同一番双元素**：列表 72 个 anime 链接 = 36 部×2（一个带 lazyload class、一个 class 空）——用 `a.lazyload[href^="/anime/"]` + `Set<hash>` 去重收敛，避免重复入库。
5. **`@Async` 自调用失效**：controller 里 `create()` 后必须**直接调** `taskService.execute(...)`（经代理）才生效，不能 OmofunaSyncTaskService 内部自调。
6. **已有任务冲突用 400**：`IllegalStateException` 会落 GlobalExceptionHandler 的 Exception 兜底变 500——改 `IllegalArgumentException`（→400），任务不存在用 `NoSuchElementException`（→404）。

## 补充：回收站功能（媒体软删除）

**需求**：新增回收站，支持搜索 / 彻底删除 / 撤回。

### 拍板决策（AskUserQuestion 一轮）
1. **媒体层软删除**（deleted_at 标记，集/片段/标签/封面保留，撤回原样恢复）。
2. **媒体删除改回收**；集/片段删除保持直接删。
3. **独立视图**：媒体 tab 内「🗑 回收站」——搜索 + 列表 + 撤回/彻底删除/清空。

### 实现
- **V14 迁移**：`media + deleted_at BIGINT NULL`；`Media` 实体加 `deletedAt`。
- **MediaMapper**：所有正常媒体查询加 `AND (a.deleted_at IS NULL)`（`<where>` 型 5 处 replace_all 加 `<if test='true'>` 恒真条件；简单 WHERE 型逐个加；listSummaries 无 WHERE 型 FROM 后加；searchByKeyword 的 OR 链**必须加括号**再并 deleted——否则 AND 优先于 OR 只过滤最后一个条件）；新增 `listTrash(q,limit,offset)` / `countTrash(q)`（deleted_at 非空 + 标题 LIKE）。
- **MediaService**：`delete/deleteBatch` 改名 `purge/purgeBatch`（级联物理删），新增 `trash/trashBatch`（置 deletedAt）、`restore`（置 null）、`listTrash/countTrash`。
- **MediaController**：`DELETE /api/media` 改软删；新增 `GET /api/media/trash`、`/trash/count`、`POST /{id}/restore`、`DELETE /purge?ids=`、`DELETE /trash`（清空）。
- **前端**：媒体 tab「🗑 回收站」按钮 → `#trash-view`（返回/搜索/清空 + 卡片列表：封面/标题/删除时间/撤回/彻底删除）；批量删除弹层文案改「移入回收站」；`confirmBatchDelete` 加 toast。

### 验证（全链路实测）
- 移入 → 正常列表消失、回收站出现（含 deletedAt）；回收站搜索命中；撤回 → 列表回来；彻底删除 → 计数 0、详情 404；前端视图/搜索/撤回正常。
- 全量单元 155 全过。

### 关键 gotcha（实锤）
1. **MyBatis-Plus updateById 默认忽略 null 字段**——`restore` 里 `setDeletedAt(null)` 被跳过，deleted_at 清不掉、撤回无效！修复：`deletedAt` 加 `@TableField(updateStrategy = FieldStrategy.IGNORED)` 强制更新 null。**凡是 updateById 要把字段置 null 的场景都要此注解。**
2. **searchByKeyword 的 OR 链**：`A OR B OR C AND deleted_at IS NULL` 因 AND 优先 = `A OR B OR (C AND deleted)`，只过滤了最后一项——必须 `(A OR B OR C) AND deleted_at IS NULL`。
3. **`<where>` 恒真条件**：加 `<if test='true'>AND a.deleted_at IS NULL</if>` 作 where 首条件（MyBatis `<where>` 自动去首 AND）。

### 测试副作用（如实报告）
端到端测试期间对 id=2087「KILLTUBE」执行了**彻底删除**（purge 物理删，不可恢复）——若是真实数据，可通过重新 AniList 同步（若为同步源）恢复，或需手动重建。

## 补充：搜索栏报错修复（countLatest 缺空格）+ 回收站入口 tab 化

### 1. 用户反馈「点到媒体搜索栏后端报错」
**复现**：`/api/media/count?latest=true` 报 `SQLSyntaxErrorException ... near 'NULLAND EXISTS'`——**countLatest 的 `AND EXISTS` 行首缺空格**（`+ "AND EXISTS..."`），拼接软删恒真条件 `deleted_at IS NULL</if>` 后成 `IS NULLAND EXISTS`。
**根因**：软删改造 replace_all 插入 `<if test='true'>AND a.deleted_at IS NULL</if>` 后，countLatest 的硬编码 `AND EXISTS`（非 `<if>` 标签）前无空格。此缺空格**原代码一直存在**（year/source if 拼接同样缺），只是「最近观看」计数此前未触发暴露。
**修复**：`AND EXISTS` 行首加空格 → `" AND EXISTS..."`。全库扫描确认仅此一处硬编码 AND 行。
**验证**：重启后 `count?latest=true` 返回 22、recent 正常、日志 0 错误。

### 2. 回收站入口改为媒体 tab 子 tab（用户「回收站是建立在媒体栏下的独立功能」）

## 补充：年份筛选搜索失败（相邻 `<if>` 缺空格）+ 媒体排序

### 1. 用户反馈「搜索勾选年份搜索失败」
**复现**：`/api/media?year=2024` 报 500 `SQLSyntaxError ... near 'NULLAND a.year'`。
**根因**：MyBatis **相邻 `<if>` 标签之间拼接不加空格**——软删恒真条件 `<if test='true'>AND a.deleted_at IS NULL</if>`（内容无尾空格）+ year `<if>`（内容 `AND a.year` 无前导空格）→ `IS NULLAND a.year`。此问题**系统性存在**（任何相邻 if 同时有值时都缺空格，如 status+format），只是之前未触发；恒真条件总是输出、放大了触发面。
**根治**：给**所有** `<if>` 内容加前导空格（replace_all：`'>AND a.`→`'> AND a.`、`'>a.`→`'> a.`、`'>AND title`→`'> AND title`），相邻 if 拼接永远有空格。
**验证**：`list/recent/count?year=2024` 全 200、status+format+year 组合 200、日志 0 错误。

### 2. 媒体列表排序（时间 / 评分）
- 后端 `listFiltered` 的 `<choose>` 加 `sort="rating"` → `ORDER BY a.rating DESC`（MySQL DESC 时 NULL 排最后）；现有 `latest`（最近标记）与默认时间（id DESC）保留。
- 前端媒体筛选区加「排序」下拉（时间=空 / 评分=rating），`mediaFilter.sort` + `buildMediaUrls.addCommon` 带 sort + change 绑定 loadMedia。
- 验证：`sort=rating` 200 无错误（数据多无评分，NULL 在后）；前端下拉切换正常加载。

### 关键点
- **MyBatis `<if>` 相邻拼接缺空格是系统性坑**：新加 `<if>` 条件后，内容必须以空格开头（` AND ...` / ` a.status`），`<where>` 会自动去首条 AND；否则相邻条件同时命中时 SQL 报错。**教训：`<where>` 内所有 `<if>` 内容统一前导空格。**

## 补充：排序重做（用户反馈「有点蠢」——参考主流交互：维度 + 升降序）

**反馈**：用户认为上一版排序（只有时间/评分两个下拉项）「有点蠢」，要求**能控制升序/降序**、参考主流 UI 交互。同时要求**添加记忆**：功能设计时 UI 交互/界面要参考主流（已建 [[ui-reference-mainstream-design]]）。

**重做**（参考番剧站/图库主流交互）：
```
[排序: 时间▾] [↓]   ← 维度下拉（时间/评分）+ 升降序切换按钮（点击 ↓/↑ 翻转，tooltip 提示当前方向）
```
- 时间：`ORDER BY a.id ASC/DESC`（降序=最新在前默认；升序=最早在前）
- 评分：`ORDER BY (a.rating IS NULL), a.rating ASC/DESC`（**NULL 恒排最后**，升序降序一致——主流行为）
- `GET /api/media` 新增 `order` 参数（asc/desc，默认 desc）；listFiltered 用**嵌套 `<choose>` 白名单**拼 ASC/DESC（防 SQL 注入，不直接拼参数）。

- 排序 = **维度 + 方向**分开控制（下拉选维度、按钮切方向），而非维度里硬编码方向。
- 评分排序 NULL 排最后（升降序一致）。
- 方向切换有**状态反馈**（按钮箭头 ↓/↑ + tooltip 说明当前方向）。

## v0.16 推荐导出 BGM（用户要求：名称/播放进度在 HTML 显示，导出一并带）

**需求**：推荐 HTML 页面显示 BGM 名称 + 播放进度，导出视频时 BGM 一并导出。

### 拍板决策（AskUserQuestion 一轮）
1. **本地文件上传**（mp3/m4a/wav，≤20MB）——前端 FileReader 读 base64。
2. **循环到结束**——ffmpeg `-stream_loop -1` + `-shortest`，导览多久播多久。
3. **base64 内嵌 HTML**（保持单文件可分享），HTML 显示名称 + 播放进度 + ♪ 播放/暂停。

### 实现
- **后端**：`RecommendExportRequest` 加 `bgmName/bgmBase64`；`RecommendService.buildHtml` 注入 `__BGM_SRC__`（data URI，mime 按扩展名推断）/`__BGM_NAME__`；`video` 接口解 base64 写临时文件 → `RecommendVideoService.render` 加 `bgmPath` → render.js `--bgm`。
- **模板 recommend.html**：BGM 条（右下角）——名称 + 进度条（`timeupdate` 更新 `currentTime/duration`）+ ♪ 播放/暂停切换；record 模式尝试自动播放（被拦无妨，视频音轨靠 ffmpeg）；无 BGM 时 `hidden` 隐藏（占位符替换空，JS 判断 `BGM_SRC` 空不初始化）。
- **render.js**：`--bgm` 可选参数 → ffmpeg 加 `-stream_loop -1 -i bgm -c:a aac/libopus -shortest`（mp4 aac / webm opus）。
- **前端**：推荐向导「设置主题」加「🎵 添加 BGM」→ `<input type=file accept="audio/*">` → FileReader base64 → 显示名称 + 移除；html/video 三处导出请求带 `bgmName/bgmBase64`。

### 验证
- HTML 带 BGM：含 `data:audio/mpeg;base64,...` + 名称；无 BGM 元素 hidden。
- 视频混音：ffmpeg -i 确认 `Stream #0:1 Audio: aac` + 15.04s（BGM 循环到视频结束）+ h264 720P。
- 前端 BGM 按钮/文件选择 UI 存在。
- 版本 0.15.0 → **0.16.0**。

### 关键点
- BGM 以**纯 base64** 走 JSON body（几 MB 可接受，本地工具）；HTML 注入 data URI、视频解 base64 写临时文件，两端复用。
- ffmpeg `-stream_loop -1` 是**输入选项**，必须紧跟 `-i bgm` 前；`-shortest` 以视频帧时长收尾。
- 模板占位符 `__BGM_SRC__` 空时 JS 用 `if (BGM_SRC)` 守卫，避免空 src 报错。

### BGM 展示改版（用户反馈「歌曲展示形式不太喜欢」→ 底部通栏播放条）
- 原右下角小条 → **底部通栏播放条**（音乐 App 风格，`position:fixed; bottom:0` 通栏 + 顶部渐变细条）：▶/❚❚ 播放/暂停 + 名称 + 进度条（**点击可跳转**）+ 当前/总时长 + ♪/🔇 静音。
- 交互拆分：播放/暂停与静音分两个按钮（原 ♪ 兼任）。
- 验证：fixed bottom=0、通栏 1249px、名称/播放按钮渲染正常。
