# 2026-08-16 工作日志

## 桌面版修复：中文编码兼容 + Chrome 探测增强 + 重新打包

**背景**：用户把桌面版 zip 发给别人，对方电脑上：① 视频渲染报 `Browser was not found at the configured executable Path (C:/Program Files/Google/Chrome/Application/chrome.exe)`；② 早前有中文乱码问题。

### 排查过程（先质疑后执行）
1. **Chrome 报错**：`desktop/main.js` 的 `findChromePath()` 只探测 3 个常见路径，对方机器 Chrome 不在候选 → 落到**兜底默认值**（写死的第一条路径），puppeteer 找不到。报错路径恒为默认值，不是真实探测结果。确认是**探测覆盖不足**，不是"读取路径"本身错。
2. **依赖澄清**：视频导出 + omofuna 同步共用 `videotagger.render.chrome-path`（yml `${RENDER_CHROME_PATH:默认}`），puppeteer-core 只需 **Chromium 内核**，不必非 Chrome——**Win10/11 预装 Edge 可兜底**。AniList 同步走纯 HTTP，不依赖浏览器。
3. **乱码修复状态**：源码已改（`application.yml` 加 `spring.sql.init.encoding: UTF-8`；`main.js` 加 JVM `-Dfile.encoding=UTF-8`），但 **release zip 是修复前打的**——实测 zip 内 jar 的 application.yml 无 encoding 修复、app.asar 无 -Dfile 修复，发出去的包乱码原样还在。

### 改动
- **`desktop/main.js`** `findChromePath()` 升级：
  - 新增 `queryAppPath(name)`——注册表 App Paths 查 `chrome.exe`/`msedge.exe`（HKLM 64 位 + WOW6432Node 32 位），reg query 解析按 `REG_SZ` 类型取路径（兼容中文 locale "(默认)" 本地化）
  - 顺序：环境变量 → 注册表 Chrome → 常见路径 → **Edge 回退**（注册表 + 标准路径）→ 默认兜底
  - 本机验证：注册表命中 Chrome + Edge，中文系统解析正常
- **`backend/src/main/resources/application.yml`**：`spring.sql.init.encoding: UTF-8`（前置已有改动，本次一并提交）
