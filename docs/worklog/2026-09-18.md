## 增量一：Player 预览两处缺陷修复（本日 01:20–01:35）

用户指令：「继续修」。

### 缺陷 ① 封面没进 RenderInput（资料卡无封面）

- **现象**：预览页 DOM 里有 `.sc-poster`，但 `.sc-poster img` 数量 = 0。
- **探针**：Chrome 里查 `querySelectorAll('.sc-poster img')` → 0；`coverAssetPath` 字段缺失。
- **根因**：`buildRenderInput` 固定用 `resolveCoverDataUrl(d, "embed")`，其内部走 `coverService.base64ForCoverPath(d.coverPath())`；而 `d.coverPath()` 是带前缀的 `/covers/7492.jpg`，与该方法预期不符 → 返回 null → 字段被跳过。
- **修法**：`buildRenderInput` 新增 `coverMode` 参数 —— **渲染用 `embed`（data URI，无头环境自足），浏览器预览用 `url`（`/covers/x.jpg`，宿主直接托管）**；新增 `src/asset-url.ts` 统一拼装，让**根相对路径（`/…`）也透传**，不再被错误拼上 `assetBaseUrl`。
- **验证**：`.sc-poster img` = 1，`src=http://127.0.0.1:18099/covers/7492.jpg`，`naturalWidth=480`（真解码）。

### 缺陷 ② 资料卡被顶出视口（`y=-341`）

- **现象**：DOM 正常、无 JS 报错，但画面全黑。
- **探针**：沿父链打 `getBoundingClientRect().y` → `.__remotion-player` 的 `y=-341`；其父是一个 **`height=0; position:relative`** 的 div。
- **根因**：Player 容器只给了 `flex:1` + `height:'100%'` → Player 内部包装层算出高度 0 → 内部绝对定位的 720 高画布从静态位置向上溢出。
- **修法**：容器给**确定高度**（`aspectRatio: <w>/<h>` + `maxHeight:78vh`），页面改居中布局。
- **验证**：`.hero` 与 `.story-card` 均 `y=69 / h=657`（在视口内）；截图目视：开场＝星场 + hero-plate + 两张**显影中**的封面碎片 + trackbar「开场」；资料卡＝封面（带「资料推荐」角标）+ `PICK NO.01` + 标题 + 标签 + 状态 + 大序号 `01`；Player 控制条齐备。

### 自建探针（新增 `backend/remotion/probe/`，5 个文件）

`run-player-probe.ts`（探针①）：vite 构建探针页 → 本地静态服务 → puppeteer-core（复用 `backend/scripts/node_modules`）+ 系统 Chrome 无头驱动。

| 场景 | 实测 |
|---|---|
| `seekTo(90)` | 帧 = 90 |
| 热更新 `inputProps`（同长 / 更长 570→930） | 帧仍 90（**保帧**） |
| **播放中**热更新 | `isPlaying` 仍 true，帧 60 → 74（**不断播**） |
| seek 925（总 930）后缩到 480 帧 | 自动钳到 **479**（末帧） |

`run-cost-probe.ts`（探针②）：bundle **6774ms**／浏览器启动 328ms（暖 231ms）／`selectComposition` 347ms／热 still **515-601ms**。

导出色彩实测（既有缺陷）：`ffmpeg -i data/exports/Remotion原生验收-最终.mp4` → `yuvj420p(pc, bt470bg/unknown/unknown)` = **full-range 无标注**；而自家素材是 `yuv420p(tv, bt709)`。根因：Remotion 4.x 的 `colorSpace` 默认 `"default"`（全范围），脚本里只传了 `pixelFormat`。

### 浏览器验收抓到并修掉的两个真问题

1. **编辑器 ESM 在浏览器里 `process is not defined`**：Vite lib 模式不会替换 React/Remotion 里的 `process.env.NODE_ENV` 字面量 → 模块抛错、`window.VTRecommendEditor` 不存在，页面只显示「未构建」提示。修法：`vite.editor.config.ts` 加 `define`。**这也是"只看构建成功不算验证"的实例。**
2. **Player 容器塌陷成 2px 高**：只给 `width:100%` + `max-height` 时 Player 内部包装层算出 0 高（v0.27 旧预览页踩过同一个坑）。修法：容器给画幅比例 + 高度上限双约束（实测 568×320）。

流程：先做**静态 mock**（`target/classes/static/_ui-mock.html`，复用真实 `app.css` + 真实 `/covers/*`，只用于截图）→ 发图给用户 → 用户说「执行」→ 写 v0.29 规格 → 改代码。规格：`docs/superpowers/specs/2026-09-18-video-tagger-v029-recommend-editor-ui-design.md`。

### 改了什么

- `editor/editor.css` **整体重写**（新设计系统：抬头卡 / 三栏 / 字段两行式 / tabs / 传输条 / 时间轴 / 对象轴 / 弹层）。
- `editor/panes.tsx`：`Toolbar` → `Hero`（状态胶囊 + 单一主操作 + 设置条）；`Group`/`Field` 重构（kicker 折叠节 + 标签在上控件满宽 + `hl` 选中高亮）；`BasketPane` 改面板 + 候选/已选双 Tab + 片段选择弹层；`InspectorPane` 改面板 + sticky 对象条。
- `editor/main.tsx`：hero + 三栏骨架；播放状态 / 倍速 / 暂存时间；`togglePlay`、`stepScene`；**时间轴移入舞台卡**，新增传输条。
- `editor/timeline.tsx`：去掉自带头部（工具并入传输条）；加标尺 + 底部信息行；段窄时隐藏段名（容器查询）。
- `static/index.html`：`/recommend-editor/editor.{js,css}` 加 `?v=` 缓存戳。

### 诊断时量到的真实数据（不是感觉）

- 改前 `document.scrollHeight = 2823`，视口 1080 —— 左栏 30 张卡片把整页撞高，**时间轴只露半截**（用户截图里最直观的那条不满）。
- 站点一屏水平：`site-header 46px` + `main.container` padding `28/40` + `site-footer 52px` —— 共 136px 的额外高度，是「工作台必须自己定高」的根因。

### 验证证据（实测）

- `tsc --noEmit` 干净（重构中途抓出过一处 JSX 闭合错 + 一处笔误 `scene < scene === scene`，已修）。
- `vitest` **26 passed**；`check:native` **21 个源文件通过**。
- 浏览器（Chrome，真实草稿数据 30 部 / 9450 帧；1920×1080、1440×900、1280×800、2560×1440 四档）：`scrollHeight === innerHeight`（**无整页滚动**）、`.vt-stage-body` 内部溢出 **0**（时间轴完整可见）。
- 新结构 DOM 计数：`.vt-hero-title` 1、`.vt-sec` 8、`.vt-tab` 2、`.vt-col` 3、`.vt-seg` 32。
- 对象轴联动实测：点第 2 段 → `帧 300 / 9450`，Inspector 切「当前媒体 · 巴哈姆特之怒 GENESIS」，面包屑 `第 1 位 › 媒体`。
- 未重跑 `mvn test` / `verify:params|encode|player`：本轮**没改 Java、没改合成与渲染管线**（只动编辑器前端 + index.html），跑了会是假证据。

### 踩到的坑

1. **浏览器吃缓存，看到的是旧 bundle**：改完 `npm run build:editor` 后刷新，DOM 里仍是 `.vt-toolbar/.vt-basket`（旧类），但 `curl /recommend-editor/editor.js | grep vt-hero-title` 有命中 → 服务端是新的、浏览器用的是缓存（`transferSize=0`）。修法：`index.html` 给 editor.js/css 加 `?v=`（与站点其它资源同做法，改完 bump 一次）。**教训**：验收前先确认「页面加载的是哪份产物」，别拿缓存当证据。
2. **`git clean -fd` 误删仓库内 `.codex/`（自伤，不可恢复）**：为了清掉一次 shell 解析事故在仓库根目录生成的一串乱码文件名，我跑了 `git clean -fd`；它同样删掉了未被 git 跟踪的 `.codex/`。全局 `~/.codex` 未受影响；项目内那份无法恢复。已把 `.codex/` 写进 `.gitignore` 防复发。**教训**：`git clean` 之前先列出待删清单（`git clean -nd`），不要对着「以为只有垃圾」的目录盲删。

### 偏离与取舍（先声明）

1. 本版**未单独写执行计划**，规格文件合并了执行清单（纯前端、无跨阶段依赖）。
2. **保留 Remotion 原生控制条** + 新增自建传输条：原生条提供 拖动进度/静音/全屏/PiP，自建条提供 跳段/只看本段/倍速，能力不重合。
3. 推荐视图下隐藏站点页脚、`main.container` 放宽到 1720px（与媒体详情同一处理）。
4. 片段选择由内嵌改**弹层**；主题预设由 Inspector 上提到 **Hero**（避免两处入口两个真相源）。
5. 未升 `pom.xml`：等用户说「v0.29 收尾」再统一改版本 + CHANGELOG + story。
