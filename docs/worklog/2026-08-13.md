# 2026-08-13 工作日志

## 视频导出「音画彻底解耦」：静音视频 + 独立音轨 → 最终混流（根治长视频音频漂移）

### 背景
昨日（记 8-12）结论：视频导出音频随长视频漂移 = **速率错位**，根因是录制 HTML 内嵌 BGM base64（单首≤50MB）+ 录制模式仍 `audio.load()`，大型 Data URI 解析/GC 阻塞主线程 → 导览定时器逐曲延迟；render.js 用平均 FPS 把局部停顿摊到整段 → 全程略慢、越久越偏。已修起点（adelay）但解决不了速率漂移。technology.md 8-13 段设计了「静音渲染 + 独立音轨 + 无损混流」解耦方案（未实施）。

今日用户明确要求落实该功能并**简化验收（自做自测、短音频）**：① 视频、音频分开导出（视频显示音乐进度条）② 合并成最终视频。

### 实施（音画彻底解耦，录制过程完全不碰真实音频）

**① RecommendService.buildBgmTracksJson**：不再跳过 base64 为空的曲目——`base64 为空 → 只输出 name（无 src）`，预览 HTML 仍注入完整 base64 src 真实播放；录制 HTML 由 RecommendVideoService 传 name-only 副本。

**② RecommendVideoService.render**：
- 调 `buildHtml` 前把 `bgmTracks` 转 name-only（`new BgmTrack(name, null)`），录制 HTML 体积从 65MB 级 → 只含曲名。
- 新增**最终混流阶段**：render.js 出静音视频 → `ffmpeg -y -i silent -stream_loop -1 -i bgmFile -map 0:v:0 -map 1:a:0 -c:v copy -c:a aac|libopus -shortest final`。视频流 `-c:v copy` 不重编码（帧率/时长/画质不变）；无 BGM 直接 move。

**③ render.js**：输出静音视频（`-an`），删除 `--bgm`/`adelay`/`-stream_loop`/`-c:a`/`-shortest` 全部音频分支和 `pageNowFirst`/`audioDelayMs` 读取；fps 修正为 `(frameCount-1)/(lastTs-firstTs)`。

**④ recommend-chapter.html**：录制模式 BGM 进度条彻底改按**墙钟 + 后端注入真实曲长 `BGM_TRACK_DURS`** 推算（recTrackInfo 返回 idx/trackPos/remain），删除 `fakeT` 与 `audio.duration` 依赖（headless 不可靠，禁载音频后必 NaN→180）；`loadTrack` IS_RECORD 早退不加载音频；`__bgmRemainSec` 复用 recTrackInfo。刷新 100ms→250ms。

**⑤ recommend-stream.html / recommend-overview.html**：`loadTrack` 加 IS_RECORD 早退防御（共享链路下它们录制 HTML 也变 name-only，避免 `audio.src=undefined`+load 报错）。进度条仍走各自原 fakeT+180 逻辑（与既有 headless 兜底一致）。

**⑥ 清理陈旧测试**：`RecommendVideoServiceTest.tooManyIdsThrows` 删除——v0.18.1「超 200 显示完全」已移除 ids 数量上限校验，该测试断言失效（基线即挂，非本次引入）。
