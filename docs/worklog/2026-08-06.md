## 跳转修复两处（v0.11，先质疑后动手）

用户报告「同片段追加标签后根据时间跳转会失效」，判断原因而非盲修。

### 调查结论：追加标签「背锅」，真正根因是跳转链路两处
- **① buildJumpUrl 只认 `/video/` 路径**：`bilibili.com/bangumi/play/...` 等 URL 不在白名单 → 返回原样、不拼 `t` 参数 → 扩展 poll 到的是无时间戳 URL，跳转静默失效。追加标签数据写入完整（PUT 校验非 null），与跳转失效无因果关系。
- **② JumpQueue key 不一致**：扩展 `normalizeUrl(location.href)`（只去 `t`）put 的是 `location.href` 原始串；后端 `pending(url)` 原样存/取——URL 细节（query 顺序等）对不上时匹配失败。

### 修复（对应两个「先质疑」澄清）
- **为何不能盲目拼接所有 URL**：时间参数格式按站点不同（YouTube `t=1018s` vs B 站纯秒 `t=1018`），未知站点不识别 `t=`。故**按域名选格式**（`youtube.com/watch` → 秒后带 s；`bilibili.com` 全部 → 纯秒；其余不拼），`URL.searchParams.set` 覆盖已有 `t` 防双参数。
- **归一化**（用户问）：把 URL 抹平到唯一规范形——去掉 `t` 等**追踪参数** + 参数排序。`VideoFingerprint.normalize()`（TRACKING 集含 `t`）与扩展 `normalizeUrl` 此前实现不一致 → 后端 `JumpController.put/poll` **统一走 `VideoFingerprint.normalize()`**，两端口径收敛。
- 验证：node 直测 buildJumpUrl 4 例（bangumi→`&t=807`、b 站 p→`&t=300`、youtube→`t=1018s`、已有 t 被覆盖）；JumpControllerTest 5 例全过。
