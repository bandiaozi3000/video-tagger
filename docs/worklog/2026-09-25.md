### 先查证：分类到底能不能推给后端（可复现探针）

本机直连 api.bgm.tv 不通（`curl` exit 28），但项目自己配了代理（`application.yml` 的 `videotagger.http-proxy` → `127.0.0.1:7890`），走它即可：

```bash
P="--proxy http://127.0.0.1:7890"
U="https://api.bgm.tv/v0/search/subjects?limit=20&offset=0"
curl -s -m 30 $P -X POST "$U" -H "Content-Type: application/json" \
  -H "User-Agent: video-tagger/0.29 (probe)" \
  -d '{"keyword":"","filter":{"type":[2],"air_date":[">=2025-04-01","<2025-07-01"],"meta_tags":["TV"]}}'
```

**两条硬结论**：

1. `TV / WEB / OVA / 剧场版 / 动态漫画` **都是** Bangumi 公共标签，能服务端过滤，且与「地区」共用同一个 `meta_tags` 数组做**且**运算 —— 「日本的 TV」= 一个请求。
2. `其他` 是 Bangumi **站点自己的兜底项，不是公共标签**；且**未知标签不报 422，静默返回 0 条** → 白名单是**必须**的，否则打错一个字的效果是"拉了 0 条候选"，而不是报错。

### 踩坑

#### 踩坑一：凭注释推断接口能力，没实测（本次最大的错）

- **现象**：我断言"分类推不到后端"，用户拿 Bangumi 网页截图反驳。
- **根因**：把 `BangumiMetadataProvider` 里**描述"两个地区叠加"**的注释，外推成了"`meta_tags` 不能做分类"。注释写的是 `meta_tags` 的**且关系**，而"分类"恰好**就是**要用且关系（日本 且 TV）。
- **教训**：**代码注释描述的是一个具体场景，不是接口能力清单**。涉及"外部接口支不支持 X"的判断，必须打真接口。这次只要 4 行 curl 就能证伪。

#### 踩坑二：`mvn spring-boot:run` 在离线模式起不来

- **报错原文**：`No plugin found for prefix 'spring-boot' ... -> NoPluginFoundForPrefixException`
- **再试 FQ 名**：`org.springframework.boot:spring-boot-maven-plugin:run` → `PluginVersionResolutionException: Error resolving version for plugin ... Plugin not found in any plugin repository`
- **根因**：离线模式（`-o`）下前缀/FQ-无版本 都要靠本地仓库的 `maven-metadata.xml` 解析版本，而**本地仓库里没有该元数据**（用户日常用 IDEA 直跑 main，从没用过 `mvn spring-boot:run`）。插件本体 `3.3.4` 其实**在**本地仓库里。
- **解**：**显式带版本** → `mvn -o org.springframework.boot:spring-boot-maven-plugin:3.3.4:run`
- **附带一坑**：必须在 `backend/` 目录下跑，否则 `Goal requires a project to execute but there is no POM in this directory (D:\learn\myLearn\video-tagger)`（我第一次就在仓库根跑的）。

#### 踩坑三：`ClipTrendSqlIT` 是"每天 00:00–08:00 必挂"的既有 flake（已修，一行）

- **报错原文**：`ClipTrendSqlIT.趋势查询按天分组_在MySQL上不报语法错:55 自己的 2 条（毫秒时间戳 /1000 后）应归到今天 ==> expected: <2> but was: <0>`
- **现象时间**：本机 00:30（UTC+8）。
- **根因**：断言拿**两个不同的时钟**比：期望值 `LocalDate.now(systemDefault)`（JVM 时区 UTC+8），实际值 `DATE(FROM_UNIXTIME(created_at/1000))`（**MySQL 会话时区**；Testcontainers 的 `mysql:8.0` 没设 TZ，容器跑 UTC）。本地 00:00–08:00 这段，UTC 还是前一天 → 恒不相等。
- **决定性实验**（不是推断）：同一份代码、只给 JVM 换时区，`mvn -o test -Dtest=ClipTrendSqlIT -DargLine="-Duser.timezone=UTC"` → `Tests run: 1, Failures: 0` ✅。**证伪了"本次改动引入"**。
- **修复**：`ZoneId zone = ZoneOffset.UTC;`（两边统一钉 UTC）+ 注释说明。**一行，且不属于本次需求，可单独回退。**
- **旁证**：`docker-compose.yml` 里真库容器显式设了 `TZ: Asia/Shanghai`，而测试用的 Testcontainers 容器没有 —— 差异就来自这里。

## 增量二：关闭交互重做（取消/X/后台）+「上次同步结果」+ 删「只选 TV」

### 需求（用户原话）

> 这个只选tv可以去掉了，另外发现一个问题，就是点击取消后，页面关闭但是仍旧在拉取。改下交互，点击取消，如果当前再拉取数据会取消拉取，如果是在同步会取消同步。右上角来个x关闭按钮。点击X，若在拉取数据直接取消。若是在同步会进入后台同步。
> 当下还有个问题就是我再次点击后怎么知晓上次同步结果
> 3没必要，当前已有TV筛选项 其他按你的来

**用户发现的真问题**：点「取消」只是 `modal.hidden = true` —— 弹窗关了，**底下的 `for` 循环还在继续跑**。拉取白跑（可重来），同步白写（不可逆）。这是设计缺口，不是 bug。

### 先摸清技术边界（决定了"取消"能做到什么程度）

| 操作 | 实现形态 | 能怎么取消 |
|---|---|---|
| 拉取候选 | 前端 `for` 逐**段** `await fetch`（只读） | `AbortController` 掐断在飞请求，段间 `break` |
| 同步 | 前端 `for` 逐**批**（`BATCH_SIZE=12`）`await fetch('/commit')`（**写库**） | **只在批次边界停**，永不 abort |

### 决策（已与用户确认）

| 入口 | 空闲 | 拉取中 | 同步中 |
|---|---|---|---|
| 左下「取消」 | 关闭 | 中断拉取 + 关闭 | **中断同步**（当前批跑完即停）+ 关闭 |
| 右上 × / Esc / 点遮罩 | 关闭 | 中断拉取 + 关闭 | **转后台** + 关闭 |

## 增量三：把「停」和「关」拆开（增量二的设计错误修正）

### 需求（用户原话）

> 点取消为何会关闭面板？

**这是我的错，不是 bug**。增量二里我把 `#bgm-sync-cancel` 写成 `closeModal('cancel')` = **停操作 + 关面板**。原因是：原代码里这个按钮就是 `modal.hidden = true`，而用户那条指令（"点击取消，如果当前在拉取会取消拉取，如果是在同步会取消同步"）**只描述了忙碌时取消什么**，我为了少改动把"关闭"叠了上去，没确认。

### 改法（用户选 A）

底部左侧**一个按钮，文案随状态变** —— 让按钮自己说清楚它要干什么：

| 状态 | 文案 | 点击 |
|---|---|---|
| 空闲 | **关闭** | `closePanel()` 关面板 |
| 拉取中 | **停止拉取** | `stopCurrent()` 只停拉取，**面板留着** |
| 同步中 | **停止同步**（按过 → 「停止中…」+ 禁用） | `stopCurrent()` 只停同步，**面板留着** |

× / Esc / 点遮罩不变（拉取 → 取消并关；同步 → 转后台并关），忙碌时点遮罩仍忽略。

代码上拆成两个函数：`stopCurrent()`（只置 `cancelRequested` / abort）与 `closePanel()`（负责 `modal.hidden`），`updateCancelButton()` 在 `setBusy` 里同步文案。

### 踩坑：取消**随机失效**（两个任务都有，真 bug）

**现象**：对 2026 全年任务发取消，DB 里确实变成 `CANCELLED`，但 **4 秒后自己变回 `RUNNING`**（直接用 SQL 盯 `status` 列看到的），任务一路跑到 4/4 段 DONE。

**根因**：循环里用 `jobMapper.updateById(job)` 写进度，而 MyBatis-Plus 会把内存行里**非空字段全部写回** —— 包括 `status=RUNNING`，于是把用户刚设的 `CANCELLED` **覆盖掉**。窗口只有几秒，所以表现为"随机失效"。

**修法**：
1. 循环内改用**只 set 进度字段的 `LambdaUpdateWrapper`**（`saveProgress`），**绝不碰 `status`**；
2. 收尾**再读一次 DB**，晚到的取消也要认（`stop = cancelled || DB 里是 CANCELLED`）。

**上一次为什么"看起来能取消"**：对账那次取消恰好落在两次覆写之间的空窗里 —— **运气**，不是代码对。

### 增量五 · 补：断点续跑 + 修掉「取消后立刻再起会卡死在 PENDING」

用户问：「中间断了如何继续？目前功能支持从中断继续吗？还是要自己根据进度自己选择」

**答案：支持，而且是自动的，不用你挑。**

**① 全量同步：按「段」续跑（本次补的）**

依据：`done_ranges` **只在整段跑完时才 +1**，而段的顺序由 `SyncRangePlanner` 按筛选条件确定 —— 所以「前 k 段已完成」是**精确**的，从第 k+1 段继续是安全的。

- 新建任务时查**同筛选条件**且状态 ∈ `INTERRUPTED`/`CANCELLED`/`FAILED` 的最近一条 → 取它的 `done_ranges` 作起点
- **`DONE` 不复用**：跑完过还想再跑 = 想拿 Bangumi 的新增，这时跳过任何段都是错的
- message 会写「（续跑：跳过上次已跑完的前 k 段）」，phase 显示「续跑（跳过前 k/n 段）」

**实测**：任务 9 在「段 2/4」被取消 → 任务 11 同条件再起，日志显示直接从 **`第 3/4 段：2026 夏（7–9月）`** 开始，只处理后两段共 **49 条**（而非重跑 113 条）✓

**② 对账：本来就天然续跑**

它只扫「未关联」的 media —— 已关联的离开了集合、已删的不存在了 → 再跑一次只处理剩下的。⚠️ 唯一注意：live 前必须跑一次**新的** dry（收紧后的前置条件）。

**③ 顺手修掉一个真洞：`queueCapacity=0` 会让任务卡死在 PENDING**

复测续跑时发现任务 10 永远停在 `PENDING`。根因：`mediaBatchExecutor` 是单线程 + **`queueCapacity(0)`** → 单线程还忙着（上一个任务刚被取消、当前批还没跑完）时提交新任务会被**直接拒绝**，`@Async` 方法压根没跑，任务行就永远不动了。

改成 `queueCapacity(8)`（单线程仍保证串行），并让拒绝时不再静默。复测：取消一个 TV 任务后**立刻**提交同条件任务 → 新任务正常进入 `RUNNING 第 1/4 段` ✓

顺带修：`flush` 里 `saveProgress(..., null)` 会让 `phase` 在批次间闪成空 → 改传当前 phase。

`mvn -o test`：461 / 0 failures / 0 errors。

### 增量十五 · 序号组内化 + 核心区移到组首 + 豪华动效（A+C+D 升级）

用户：①「数量排怎么一会 500 一会几十，什么原因」②「重点不太突出，能不能分组后开局把核心的几个展示出来，设计一下展示 UI 风格交互」
③「只是展示，有相关交互吗？比如动态特效，视觉效果更强烈点」→ 拍板：**1 豪华 2 按我推荐 3 序号确认**。

**① 序号 bug（展示语义错）**：`PocMedia.order` 是 Java 按**请求 ids 顺序**编的**全局**号（1..N），画面却是按 `groupBy` **重排**的 ——
第 1 组 `01…87`、第 2 组 `88…159`、**全片回顾里 `03/128/402` 满天飞**。
→ 新增 `Scene.numberFrom`（本地序号起点），组内从 1 数、回顾按回顾顺序数；组标签行改报「共 N 部」。

**② 核心区移到组首**（原组尾逐部资料卡**删除**，同一批不展示两次）：
`[组章节页] → [★ 本组核心] → [群像（核心带★）]`；核心 **≤2 部走逐部满屏**（MEDIA_INFO）、**≥3 部走一屏大卡**（MEDIA_GRID + 金色题头）。
`groupMedia` 里 **featured 优先排序**（核心必落在第一屏）。

**③ 豪华动效**（全部帧驱动，`animation.ts` 硬禁 CSS 过渡/keyframes）：
金色**扫光**过题头 → 卡片 **spring** 弹入（0.94→1，回弹）→ 封面**显影**（grayscale/blur，与开场暗房显影同语言）
→ ★ **弹性落位**（延迟+反向旋转）→ 驻留期**慢推镜** + ★**呼吸微光**（sin 驱动）→ 退场整幕 `scale→0.94` 交棒。
**④ 转场音**：`stingTimeline` 原先**只认银幕式 TITLE 幕**（chapter 无 sting 挂点）→ 加 `kicker === CORE_KICKER` 条件，
金色扫光 + ★ 弹入与音效**同帧**落下。
