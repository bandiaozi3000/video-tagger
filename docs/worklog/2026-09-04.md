### 场景 2 根因（先修）
- 换绑链：`linkMedia`(REPLACE) → `replacePrimary`（解绑旧主条目）→ `importRecord` → `syncEpisodes` 给新条目建本地 `episode`。

- 实证：`data/logs/video-tagger.log` 2026-09-03 20:39 两次 `DataIntegrityViolationException`（堆栈 `linkMedia → importRecord → syncEpisodes`，间隔 12s = 用户连续试两次）。现场：media 5907「魔法少女小圆」主条目错绑为外传 159690，正确本传 9717 反成附加条目。

## 换绑语义升级：推倒重建 + 用户数据保护确认（同日续）

### 决策（用户拍板，按我的建议）
- 换绑（REPLACE）＝ 删除旧主条目同步链路（本地集 + 片段 + 标签 + 封面 + 片源映射等），成功后按新主条目校准 media 并清旧封面；附加条目保留。
- 刷新（metadata-refresh）＝ 只更资料与集索引，不动本地集（现行为未改）。
- 保护：旧集含用户数据（clip/标签/note/本地视频/片源映射/watched_at/封面）时，必须 confirmProtected=true 二次确认，否则拒绝。

### 后端改动
- MetadataSyncService.replacePrimary 重写为全删语义：
  - 旧集清单 = primaryLinkedEpisodes(work)（external_episode 桥接反查，无桥接回退 entry 下全部集）。
  - 先 unbind 全表对将删集的桥接（防附加条目悬空）→ deleteByWorkId 旧索引 + deleteByWork relations → 逐集删片源映射 + episodeService.delete 级联 → detachFromMedia 解绑旧 work。
  - assetEpisodes>0 且无 confirmProtected → 抛错拒绝。
- 新增 recalibrateMedia：换绑成功后按新条目刷新 media.title/year/season/aliases，删旧封面文件并 clearCover（展示走新条目远程封面）。
- episodeProtection 资产判定补 watched_at / 片源映射。
- 关键坑：MyBatis-Plus updateById 跳过 null → 全部改 mapper 原生 SQL：ExternalWorkMapper.detachFromMedia、ExternalEpisodeMapper.unbindByEpisodeIds/deleteByWorkId、VideoSourceEpisodeMapMapper.deleteByEpisode、MediaMapper.clearCover（lambda wrapper 在无容器单测会炸，原生 @Update 更稳）。
