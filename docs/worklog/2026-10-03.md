### 推荐「资源视频」上传（用户在推荐里给某部媒体挂一段视频资源）

**需求演进（三次收窄，值得记）**：①「媒体级资源池 + 可上传可下载」→ ②「推荐里给某媒体挂一个视频展示」→ ③「用法和现有片段一样，挂几个看用户上传几个，上传时可勾选开头结尾」。收到 ③ 时结论就明确了：**这就是片段模型本身**（`clips.timestamp_sec/end_sec/video_fp` 就是干这个的，且 `episode_id` 本来就可空），所以一个字段都不用加。

**落点判断（决定了工作量）**

| 事实（实测/读码） | 后果 |
|---|---|
| 渲染侧唯一视频通道 = `media.clips[]`（`scene-plan.ts:276`、`cinema/plan.ts:207` 都是 `media.clips.find(clipId)`） | 走片段通道 → **渲染/预览/导出零改动**；另开 `media.resources[]` 要动场景计划+指纹+分块，成本差一个数量级 |
| `LocalVideoResolver` 读 `data/videos/{videoFp}.{ext}`（fp 白名单 `[A-Za-z0-9_-]+`） | 上传文件按指纹命名入池即可被 `prepareOne` 命中 |
| `MaterializationService.resolveC1` / `reusableArtifact` 的 by-assetId 分支**不含 episode 依赖** | 素材求值/准备天然支持"无集片段" |
| `clips.episode_id` 可空（`V3:30`），但 `ClipMapper.listByMedia` 是 `JOIN episode` | 无集片段**存得进、看不见** → 不必修那条 SQL，只需给 `loadClips` 加按 id 兜底 |

**实现（5 处）**

- 新增 `ClipUploadService`：文件按内容 SHA-256 命名落 `data/videos/{fp}.{ext}` → `MediaProbe.durationSeconds` 探时长 → 插一条 `episode_id=NULL` 的片段行（`url=upload://{fp}`）。**不走 `ClipService.save`**（那条路会 `ensureEpisode` 按标题自动建集，正把资源塞进正片集）。
- `ClipController` 新增 `POST /api/clips/upload`（multipart：file/title/startSec/endSec）。
- `RecommendClipSourceService.loadClips`：本体找不到且无 `sources` 时，按 id 直查，`episode_id` 为空即视为可用（**唯一一处推荐侧改动**）。
- `LocalVideoResolver` 加兜底：白名单找不到时按 `{fp}.*` 扫目录（用户拍板"格式不限制"，否则 m2ts 这类会报**假故障**"找不到本地源视频"）。
- 编辑器（`backend/remotion/editor/`）：媒体卡「＋ 片段」上方加「⬆ 资源」按钮 + 上传弹窗（本地 `<video>` 预览 + 开头/结尾秒数 + 标题）；`ClipPicker` 加「资源」一行（否则已挂的资源在候选里没有、取消不掉）；`addResource` 顺手把媒体加入 `config.ids`（与拖拽入篮同款，否则 plan 过滤掉 = 静默无效）。

**归属不存库**：资源挂在哪部媒体 = 草稿 `mediaClips[mediaId].order`，库里不存 `media_id`。

**收尾补的一刀**：草稿只存 clipId，重开编辑器后本次会话上传的本地表就没了，标题会退化成 `#1` → `ClipPicker` 对「候选里找不到、本地表也没有」的 id 按 `GET /api/clips/{id}` 补一次（只在 id 集合变化时触发），「资源」行判定收紧为 `episodeId == null`（借来的片段不会被误列）。
