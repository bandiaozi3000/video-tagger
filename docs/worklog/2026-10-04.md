### 媒体档案信息卡加「Bangumi 评分」（小改动，无规格/计划）

**需求**：媒体详情右侧「档案信息」卡补一行 Bangumi 社区评分。用户选 A 方案（前端解析，不重启后端）；tip 方案被否 → 票数/排名**直接同行展示**。

**改动（只碰静态资源，2 个文件）**
- `static/app.js`：
  - 新增 `parseBangumiRating(rawJson)`（挨着 `parseMetadataList`，同一套「JSON 串就地解析」惯例）；
  - 档案信息卡 `profile` 数组在「个人评分」后插 `Bangumi 评分`：分数正常字重，` · N 票 · 排名 #R` 用内联小号灰字（复用 `--text-dim` 变量，不新增 CSS）。

- `cp` 到 `backend/target/classes/static/`（跑着的 IDEA 实例吃 target/classes）。

**口径（关键，别踩）**
- 数据源 = 详情接口已经返回的 `external_work.rawJson` 里的 `rating{score,total,rank}`，**没加 DB 列**。
- **`score > 0` 才算有评分**：无票数时 Bangumi 返回 `score=0` 而不是 `null`，`!= null` 判定会把冷门条目显示成「0.0」。此口径与后端 `MediaMapper.BGM_SCORE` 的 `> 0` 注释一致。
- 未关联 Bangumi / rawJson 缺失 / 解析失败 → 显示 `—`（与「个人评分：未评分」同风格）。

**为何前端解析而不是后端加字段（B 方案被否）**
- `rawJson` 本来就在 `/api/metadata-sync/media/{id}/metadata` 响应里（整实体序列化），前端解析零后端改动；
- 后端那条 `JSON_EXTRACT` 路子**仅 MySQL 有值**（`TrendRef` 注释已写明），而 rawJson 下发在 SQLite 桌面版一样有值；
- 省掉「改 Java class → 用户手动重启 IDEA 实例」这一步。

**踩到的坑（都留了可复现探针/命令）**

### 「筛选无法切换」真因找到并修掉：统计页筛选改为**独立一份**

**用户澄清**：「筛选和媒体一致，但是勾选还是在统计这勾选吧。不把媒体筛选带过来」→ 一句话点中最可能的真因。

**真因**：统计页与媒体页**共用同一份 `mediaFilter`**（我按规格 Q20a「复用媒体页那一整块筛选」实现过头了）。
后果：媒体页已经勾了「异世界」，进统计页它**已经是勾上的**状态 → 用户再点一下就是**取消** → 表现就是「勾选无效 / 切不动」。
（其实第一轮探针就扫到过这个现象：`trend_pick chips= live=0`，当时我误判成"探针自己的问题"，**是我判断错了**。）

**改动**
- `app.js`：`renderFilterPop(dimsHostId, valsHostId, f = mediaFilter, onChange = null)`、
  `setDim(key, value, f = mediaFilter, onChange = null)`、`dimLabel(key, f = mediaFilter)`、`dimActive(key, f = mediaFilter)`
  —— 筛选对象与变更回调**可注入**，默认值 = 原来的媒体页行为（媒体页调用点一行没改）。
- `stats-trend.js`：新增 `trendFilter`（形状与 `mediaFilter` 同构，**初始全空**）+ `trendFilterChanged()`；
  实时线 / 固定线快照 / chips / 清空 / refs / 预览 / 视频**全部改吃 `trendFilter`**；
  删掉对 `onMediaFilterChange` 的订阅（不再跨页联动）。
- 版本戳 → `trend5`。

**验证证据（探针 `.tmp/probe-independent.mjs`，跑在用户 8080 实例上，events: []）**
```
① 媒体页勾「标签 异世界」        → mediaFilter.tagIds=["417"]

③ 统计页勾「异世界」             → 标记 ☐→☑（是勾上），live=535；mediaFilter 仍 ["417"]

⑤ 统计页「清空」                 → 只清统计页；媒体页 chip 与条件照旧
```
