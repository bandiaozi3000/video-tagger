## 媒体筛选题材｜手动添加「常驻」（纯前端，后端零参与）

### 用户要求

1. 「媒体筛选题材目前是固定，能不能手动添加常驻，无需后端参与」
2. 我给了两条路：**A** = 直接扩白名单（41 → ≥30 次命中那 112 项，需重启后端）；**B** = 前端 localStorage 常驻词 + 加删 UI。
3. 用户回「**B**」→ 开工。小改动，按项目约定**不写设计规格、不写执行计划**，想清方案直接做。

### 先验证的关键假设（不是推断，实测）

「无需后端参与」能不能成立，取决于**查询侧是否校验白名单**。读码 + 真库探针结论：

- 白名单 `MediaService.GENRES` 只出现在 `MediaMapper.listGenreCounts` 的 `IN (...)`（**只生成选项列表**）；`MediaService.genresJson()` 只是把传来的词拼成 JSON 数组，SQL 是 `JSON_OVERLAPS` —— **不校验**。
- 拿真实运行中的后端（用户 IDEA 实例，:8080）直接探：

| 词 | `GET /api/media/count?genres=<词>` | 说明 |
|---|---|---|
| （空） | 5248 | 全量 |
| 轻改 | **788** | 白名单外，查询照常命中 |
| 漫画改 | **2225** | 同上 |
| 偶像 | 218 | 白名单内，对照 |
| 厕纸 | 272 | 用户吐槽类，能查但不适合当选项 |
| 不可能存在的词xyz | **0** | → 死选项探测可用 |

- `genres_json` 的值分布（真库）：**2180 个不同值**，其中 ≥30 次命中 **112** 个，白名单只种 **41** 个 —— 说明"手动加词"真有东西可加，不是空功能。

### 实现（改动面：`app.js` + `app.css`，零 Java、零 Flyway）

| 位置 | 内容 |
|---|---|
| `app.js` 字典声明后 | `CUSTOM_GENRES_KEY = 'vt-media-genres'`、`customGenres()/saveCustomGenres()`、`probeGenreCount()`、`addCustomGenre()` |
| `app.js` `dimValues('genres')` | 常驻词排最前（`custom: true`），后端字典同名词去重 |
| `app.js` `renderFilterPop()` | 常驻项渲染 `.fp-val-row` + 右侧 × 删除；题材维度底部多一行 `＋ 常驻` 输入（Enter 也可提交） |
| `app.js` `fillMediaFilterDict()` | 加载字典后为已有常驻词重探媒体数（否则刷新后不显示数字） |
| `app.css` | `.fp-val-row / .fp-del / .fp-add / .fp-add-input / .fp-add-btn / .fp-add-hint` |

**拒收规则**：`probeGenreCount` 返回 `0` → 不落盘并提示「库里没有这个题材（0 部），没添加」；返回 `null`（请求失败）→ 放行、计数未知。

**顺手行为**：删除常驻词时，**若它正被选中就同时取消该条件**（否则会留下一个列表里看不见的筛选项）。

### 用户报的现象 / 我踩的坑

- **`open` 命令超时 120s，但页面其实已经开了**：`agent-browser --session vt open ...` 被打断后，按 `AGENTS.md` 的纪律先用最轻命令探活 → `get url` **秒回** `http://localhost:8080/?bust=...` → 属"慢"不是"死"，**没有重跑 open、没有杀进程**，接着 eval 一切正常。这条纪律今天又救了一次时间。

### 遗留风险与待用户决定

- **只在这台浏览器常驻**（localStorage）。换机/换浏览器/清缓存即失效；要跨端必须落库（需后端 + Flyway）。**已明确接受**。
- **没做「添加后直接选中」**：现在加完只入列表，还需再点一下才筛。要不要加完就筛？**待用户决定**（一句话可改）。
- 同义词/繁简/大小写不会命中（字面量必须与库内一致），靠 `0 → 拒收` 兜底，**不做模糊匹配**（2000+ 原始值上做模糊匹配是另一个坑）。
- 未验证：常驻词在**回收站/收藏夹 tab**下的表现（同一 `addCommon` 路径，推断一致，**未实测**）；Firefox/移动端未测。
