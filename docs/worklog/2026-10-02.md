## 媒体筛选题材｜手动添加「常驻」（纯前端，后端零参与）

### 用户要求

1. 「媒体筛选题材目前是固定，能不能手动添加常驻，无需后端参与」
2. 我给了两条路：**A** = 直接扩白名单（41 → ≥30 次命中那 112 项，需重启后端）；**B** = 前端 localStorage 常驻词 + 加删 UI。
3. 用户回「**B**」→ 开工。小改动，按项目约定**不写设计规格、不写执行计划**，想清方案直接做。

### 先验证的关键假设（不是推断，实测）

「无需后端参与」能不能成立，取决于**查询侧是否校验白名单**。读码 + 真库探针结论：

- 白名单 `MediaService.GENRES` 只出现在 `MediaMapper.listGenreCounts` 的 `IN (...)`（**只生成选项列表**）；`MediaService.genresJson()` 只是把传来的词拼成 JSON 数组，SQL 是 `JSON_OVERLAPS` —— **不校验**。
- 拿真实运行中的后端（用户 IDEA 实例，:8080）直接探：

| 词 | `GET /api/media/count?genres=<词>` | 说明 |
|---|---|---|
| （空） | 5248 | 全量 |
| 轻改 | **788** | 白名单外，查询照常命中 |
| 漫画改 | **2225** | 同上 |
| 偶像 | 218 | 白名单内，对照 |
| 厕纸 | 272 | 用户吐槽类，能查但不适合当选项 |
| 不可能存在的词xyz | **0** | → 死选项探测可用 |

- `genres_json` 的值分布（真库）：**2180 个不同值**，其中 ≥30 次命中 **112** 个，白名单只种 **41** 个 —— 说明"手动加词"真有东西可加，不是空功能。

| 位置 | 内容 |
|---|---|
