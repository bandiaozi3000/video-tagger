## 去底/回顶「智能导航」单按钮（右下角双钮 → 屏幕右缘垂直居中单钮）

### 需求（用户反馈，grill 确认）
1. 原右下角只有「回到顶部」（`#back-top`）。加「去底部」做成双圆钮（↑/↓）→ 用户吐槽**回底箭头在页面最底部时显示没意义**（已在底，点它没反应）。且进一步要求：**下拉/上拉统一为一个 button、放页面中间、相关场景统一样式**。
2. grill 确认：位置 = **屏幕右缘垂直居中**；交互 = **智能方向切换**（箭头指向「还远着的那端」）。

### 实现（替代双钮；单按钮全局 fixed → 所有场景天然统一）
- **index.html**：删 `#back-top` / `#back-bottom`，改为单 `#back-nav`（位于 `<script>` 之前，避免 getElementById null 中断脚本）。
- **app.css**：`#back-nav` 右缘 `top:50%` **垂直居中**；浮现动画改用 `translateY(calc(-50% + 10px)) → translateY(-50%)`（保留淡入位移且不破坏居中）；毛玻璃圆钮样式（blur/border/hover 渐变）不变。
- **app.js**：scroll 监听按位置切箭头（`NEAR_EDGE=800`）：
  - 距底 < 800 → `↑`（回顶）；距顶 < 800 → `↓`（去底）；其余 → `↕` 双向。
  - 点击：单向箭头直达目标；中间 `↕` 去**更远那端**（`y > max/2` → 回顶，否则去底）。
  - `scrollY > 400` 才显示；无滚动条（max≤0）不显示。
- cache-bust `20260811f→i`（含中间 g/h 版本），已复制 `target/classes/static`。

### 验证（浏览器 E2E，收藏夹「有印象的」max=29578）
- **位置**：右缘垂直居中（`getBoundingClientRect` 中心与视口中心误差 <6px）。
- **方向**：顶部(0) 不显示 / 近顶(500) `↓` / 中间(15000) `↕` / 近底(29578) `↑`。
- **点击**：近底点 `↑` → y=0；近顶点 `↓` → y=29578（到底）；中间点 `↕`（distTop 15000 > distBottom 14578 → 距顶更远）→ 回顶 y=0。

## 详情页返回：恢复列表滚动位置

### 需求（用户反馈）
从列表（媒体/收藏夹）点卡片进详情，返回时列表从最顶部开始，希望**回到离开前停留的滚动位置**。

### 根因
`pushView` 进详情不记录滚动位置；`goBack` 返回时列表异步重新渲染（`loadCollections`/`loadMedia`），scrollY 丢失落回顶部。

### 实现（app.js）
- `pushView`：入栈条目加 `scrollY: window.scrollY`（进详情前列表位置）。
- `goBack`：返回媒体/收藏夹/推荐（`SCROLL_RESTORE_VIEWS` 集合）且 `scrollY > 0` 时调 `restoreListScroll(scrollY, view)`。
- `restoreListScroll(y, viewName)`：**先清空目标网格容器**（避免返回瞬间 section 残留旧列表被 poll 误判「已渲染」），再按 viewName 限定容器轮询（50ms）等渲染稳定（`scrollHeight` 不再增长且有卡片/分组），再 `scrollTo` 恢复；~6s 超时兜底。
- cache-bust `20260811k→l`，已复制 `target/classes/static`。

### 验证（浏览器 E2E）
- 收藏夹**分组**：滚动 15000 → 详情 → 返回 **y=15000**；滚动 20000 → 返回 y=20000。
- 收藏夹**平铺**：滚动 2000 → 返回 y=2000。
- **媒体页**：滚动至 max（clamp）→ 返回 y=max（恢复正确）。
- 修复过程两次迭代：① 全局 `querySelector` 匹配到 hidden 其他视图旧卡片误判 → 改按视图容器限定；② 返回瞬间旧列表残留被 poll 当「已渲染」提前恢复 → 恢复前先清空容器。
- 期间一次偶发「加载失败：后端未响应」（残留服务网络抖动），重测正常，与改动无关。

### 3. 视频导出：当前 BGM 播完再结束录制（无上限）

**需求（grill）**：结尾落在一首歌中途时延长录制到该曲播完（无上限）；BGM 比视频短（后半段）本次不管——实测 render.js `-stream_loop -1` 音频本就循环铺满，无静音问题。

**机制**：录制由模板 `data-tour-ended` 驱动（render.js 检测到即停，`--duration+120s` 仅兜底）。故延长 = 模板 finishAuto 多等当前曲目剩余。

**实现**：
- 后端 `RecommendVideoService`：ffprobe（本机没装）回退 `ffmpeg -i` 解析每曲时长 → 注入模板 `__BGM_TRACK_DURS__`（post-process 替换 `const BGM_TRACK_DURS = [];`）；`--duration` 传 `durationSeconds + maxTrackDur + 5` 放宽兜底上限。
- `RecommendService.buildHtml`：`__BGM_TRACK_DURS__` 默认注入 `[]`（HTML 导出/预览无时长）。
- 模板：`__bgmRemainSec` = 墙钟 elapsed % 总时长定位当前曲 → 返回该曲剩余；finishAuto 录制模式 remain>0.01 时 `setTimeout(remain*1000+800)` 再置 tourEnded。**不用 `bgmAudio.duration`（headless 下不可靠，循环重载后尤其）。

**验证**（9010 测试实例实机导出，3s/15s 正弦 BGM）：
- 无 BGM 对照 11.36s；3s BGM → **12.34s**（循环场景，边界收尾）；15s BGM → **15.35s**（整曲播完）。
- 关键 gotcha：① headless 下 `bgmAudio.duration` 对循环重载后的音轨不可靠（旧 trackStartTs 方案 3s 场景失败 +0.10s）→ 改后端注入时长 + 墙钟；② 阈值 0.3 太高——实测 tour 结束恰落在曲尾 0.25s 处被挡（现场 bgmRemainAtFinish=0.25）→ 降到 0.01；③ 页面加载→录制起点偏移 ~0.5s（offset=elapsed−output≈0.46s）→ 缓冲提到 800ms 保证不掐尾。

**遗留**：8080 IDEA 实例仍是旧 Java 类，需**重启**才加载新代码（否则旧 buildHtml 不替换 `__BGM_TRACK_DURS__` 占位符，导出 JS 报错）。cache-bust `20260811m→20260812a`，已同步 target/classes。

## 推荐页卡顿根因 + 修复（草稿保存排除 BGM/背景图）

### 问题（用户反馈）
推荐分组页操作一会儿很卡。

### 根因分析（浏览器实测）
- **主因**：草稿保存序列化**65MB config**（含 **57MB BGM base64** + **8.6MB 背景图 bgImages**）→ 每次保存主线程卡 **365ms** + 上传 65MB。「单勾选立即存」改动后每次操作都即时保存 → 每点一下都卡。
- **次因**：仅显示已勾选取消勾选会整页重渲染（322 卡，冷缓存封面图慢，实测 ~6.9s 含网络）。

### 修复（app.js，cache-bust 20260812h→i→j，用户拍板「草稿不存 BGM/背景图」）
`collectRecommendConfig()` 构建后 `delete cfg.bgmTracks; delete cfg.bgImages;`——草稿/模板只存勾选+设置（2.3KB），刷新恢复勾选和配置，BGM/背景图由用户导出时现场重传。

### 验证
- 保存耗时 **365ms → 1.2ms**（300 倍），体积 **65MB → 2.3KB**。
- 草稿 API 实测：334 ids、config 2201 字符、无 bgImages/bgmTracks ✓；勾选+设置正常保存恢复。

### 教训
把大体积素材（BGM/背景图 base64）塞进「每次改动自动保存」的草稿是性能反模式——草稿应只存轻量状态，素材按需上传。
