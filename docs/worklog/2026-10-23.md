### 媒体列表收藏夹「排除所选」（小改动，无规格/计划）

**用户要求**：媒体页想勾一个收藏夹、看**它之外**的媒体。给了三个方案，用户拍板 **A**（收藏夹维度加第三档模式 `排除所选`，而不是值级三态 / 另开视图）。

#### 一、现状核实（读码，非推断）

| 位置 | 现状 |
|---|---|
| `app.js` `mediaFilter.mode` | `{ genres: 'OR', tagIds: 'AND', collectionId: 'OR' }`，浮层里渲染成「全部匹配 / 任一匹配」两档 |
| `app.js:mediaFilterParams` | 拼 `collectionId=1,2&collectionMode=OR`，媒体页列表/计数、统计页趋势、清单导出**共用** |
| `MediaMapper.COLLECTION_FILTER` | 一个 MyBatis 常量，被 **8 条查询**引用（列表/计数/最近观看/趋势/refs/年度头像/导出等），且各方法都已声明 `collectionMode` 参数 |
| `media_collection.media_id` | V8 迁移里 `BIGINT NOT NULL` → `NOT IN` 子查询不存在 NULL 陷阱 |
| 运行实例 | 8080 在跑（IDEA debug，无 devtools 热更，**改后端 class 必须用户重启**） |

#### 二、改动

1. `MediaMapper.java`：`COLLECTION_FILTER` 加 `<when test="collectionMode == 'NOT'">` → `AND a.id NOT IN (SELECT media_id FROM media_collection WHERE collection_id IN (...))`。8 个引用点 + 导出路径自动同口径。
2. `app.js` `renderFilterPop`：模式段对收藏夹多给一档「排除所选」（`hasNot` 只认 `collectionId`，标签/题材不加）。
3. `app.js` `dimLabel`：排除档显示 `不在 A 或 B`（连接词用「或」——「不在 A 且不在 B」才是本意，写成「且」会读成集合交集）。
4. `index.html`：`app.js?v=20261023-favnot`（no-cache 已开，版本戳是双保险），并 `cp` 到 `target/classes/static/`。

#### 三、验证证据

- `node --check app.js` → OK；`mvn -o -DskipTests compile` → EXIT=0。
- SQL 语义（直连真实 MySQL 探针 `.tmp/SqlProbe.java`，只 COUNT 不写）：
```

in(11)               1559      ← 与 /api/media/count?collectionId=11 一致
not_in(11)           3668      ← 1559 + 3668 = 5227 ✔
in(11,10)            1559
not_in(11,10)        3668
null_media_id_rows   0
collection_11_raw    1560      ← 含 1 部已软删媒体，故比接口多 1
```
  → 证明「未归入任何收藏夹的媒体」被算进"之外"，且 `NOT IN` 无 NULL 黑洞。
- **未验证**：`collectionMode=NOT` 走 HTTP 的实机结果 —— 用户 8080 实例仍是旧 class，
  `curl '/api/media/count?collectionId=11&collectionMode=NOT'` 现在返回 **1559**（等于 IN），
  说明**未重启**（这是预期，不是 bug）。重启后该值应为 3668。
- **未验证**：浮层三档按钮与 chip 文案的实机外观（后端未重启时点「排除所选」结果会误导，故不请浏览器）。

### 媒体爱心改为「悬停即开」（小改动，无规格/计划）

**用户要求**：收藏夹爱心现在必须点击才弹浮层，太麻烦 → 悬浮上去就弹出。

#### 一、现状（读码）

- 爱心两类：卡片 `.media-fav-btn`（`opacity:0`，卡片 hover 时显现）、列表视图 `.row-btn.fav`；两者原来都只挂 `click → openFavPicker(id, btn)`。
- 浮层 `.coll-pick` 挂在 `document.body`（`position: fixed`），定位在按钮下方 6px；已有「点外面 / 滚动即关」。

#### 二、改动（`app.js`）

- 新增 `bindFavTrigger(btn, mediaId)`：`mouseenter` → 150ms 后开；`mouseleave` → 220ms 后关；`click` 仍可开（触屏/键盘），**已开则不关了重开**（`favAnchorBtn === btn`）。
- `openFavPicker` 里给浮层挂 `mouseenter/mouseleave` 同样的 220ms 缓冲 —— 按钮与浮层之间那条 6px 缝隙靠它跨过去。
- `closeFavPicker` 清掉两个定时器与锚点。两处渲染点（卡片 / 列表行）改调 `bindFavTrigger`。
- 版本戳 → `app.js?v=20261023-favhover`，静态已 `cp` 到 `target/classes/static/`。

### 组间顺序对**所有分组维度**都支持 ↑/↓（追加到上一条）

**用户要求**：不止年份，组间顺序也要能升降序。

#### 一、语义（我定的，用户要的是"能切"，没指定每个维度的方向）

每个维度保留**原来的天然序 = 默认（↓）**，按 ↑ 时整体反转 —— 这样默认外观和改之前完全一致，不制造惊喜：

| 维度 | ↓（默认，= 改动前的样子） | ↑ |
|---|---|---|
| 年份 | 2026 → 1983（未知年份恒在最后） | 1983 → 2026（未知年份仍在最后） |
| 季度 | 冬 → 秋 | 秋 → 冬 |
| 状态 | 想看 → 弃番 | 弃番 → 想看 |
| 收藏夹 | 名称 A→Z | Z→A |
| 题材 / 标签 | 组内条数多 → 少 | 少 → 多 |

#### 二、改动（`app.js`）

`mediaGroupOrder(dim)` 重写：年份仍走 `yearGroupOrder(order)`（保留"未知年份恒在最后"）；
其余维度先取天然序比较器 `natural`，`order === 'asc'` 时返回 `(a,b) => -natural(a,b)`。
收藏夹视图（只能按年份分组）上一轮已显式传 `yearGroupOrder(collFilter.order)`，无需再动。
版本戳 → `app.js?v=20261023-grporder`，已 `cp` 到 `target/classes/static/`。

#### 三、验证证据（真实浏览器探针 `.tmp/probe-group-dims.mjs`，逐维度切 ↓/↑ 读组 key 顺序）


- 组内卡片顺序同样跟随 ↑↓（后端 SQL 的 `order`），所以 asc 时"组间由小到大、组内也由旧到新"，两者方向一致 —— 这是刻意保持的，不是 bug。
