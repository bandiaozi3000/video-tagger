## 增量一：预览 BGM「同一小段反复重放」根因与修复（用户指令：「改」）

### 现象（用户原话 + 我的复述）

- 用户原话：预览页里，音乐播放时"假如歌词是 12345，他会 12 12 然后 23 23 这样播放"。
- 复述：同一小段被**反复重放**，且重放的位置逐次前移 —— 不是简单的整曲循环，是"往回倒一小截"。

### 复现与探针（真实编辑器页 + 无头 Chrome）

- 加载物：`data/recommend-previews/cd882d81-27c0-4d40-b042-2858ff586db5/bgm-0.flac`（4:32.90，272.9s，44.1kHz 立体声，内嵌 mjpeg 封面流）；编辑器草稿：ids `[7130,7338,6917]`、时长 10/5/5/10/5、perScreen 1、style chapter、**无片段**（`mediaClips {}`）。
- 采样方法（页内，每 100ms 一条，避免 puppeteer 往返误差）：`{performance.now(), 播放器帧(读 .vt-transport 文本), audio.currentTime}`，跑 10–12s，统计**帧钟速率**、**音频推进速率**、**currentTime 倒退次数**。
- **实测（修复前基线）**：帧钟 **19.9 fps = 0.664× 实时**；音频 0.70×；**回跳每 ~2s 一次，每次 −0.55~−0.60s**，且表现为连续 6 个采样点各退 ~0.1s（即一串小倒退，不是一次大 seek）。
- **实测（排除项，全部否掉）**：
  - 纯 `<audio>` 播同一 URL（无 Remotion）：`duration=272.9`、单调前进 12.5s/12.5s、**0 回跳** → 不是文件/HTTP/Range（`Range` 请求返回 206 + `Accept-Ranges: bytes`）。
  - 摘掉草稿里的背景图后：20.0 fps（0.667×）、回跳照旧 → 不是背景图。
  - **无 BGM 空跑**：20.1 fps（0.672×）、无音频元素 → 帧钟本身就慢，**不是音频引起的**。
  - `audio.playbackRate = 1`、`preservesPitch` 默认、页面 rAF **60fps**（空白页 57.7 / 编辑器页 60.3）、ducking 窗口 **0**（本次无片段）、page errors 仅 favicon 404。

### 根因（一行）

`backend/remotion/editor/main.tsx` 的 `<Player inputProps={{ input: rendered.input }} />` —— **每次渲染都是新对象字面量**；而编辑器在 `frameupdate → setFrame`（`main.tsx` 帧游标 effect）下**每帧重渲染**。Remotion 侧 `actualInputProps = useMemo(() => inputProps, [inputProps])` → `config` 反复重建 → `use-playback.js` 的播放循环 `useEffect`（依赖数组含 `config`）**每帧重启一次**（`startedTime = performance.now(); framesAdvanced = 0`）→ 时钟每次只能前进"自上次重启以来"的帧数 → **帧钟塌到 ≈ 编辑器重渲染频率（~20fps，0.65× 实时）**。

`<audio>` 元素是按**真实时间**走的 → 相对画面每秒超前约 0.33s → 越过 Remotion 的同步容差（`DEFAULT_ACCEPTABLE_TIMESHIFT_WITH_AMPLIFICATION = 0.65`，见 `use-media-playback.js`）→ 触发 `seek-due-to-shift`，把音频**往回拖 ~0.6s** → 听感就是"刚听过的那一小段又重放一遍"，如此往复。

### 对照实验（隔离探针，同一合成 + 同一 FLAC，证明因果）

探针：`backend/remotion/probe/bgm-probe.tsx`（`?churn=<ms>` = 父组件每 N ms 重渲染，`&stable=1` = 候选修复）。驱动：`.tmp/bgm-probe-run.mjs`。

| 场景 | 帧钟 | 音频推进 | 回跳 |
|---|---|---|---|
| 父组件不重渲染（对照） | 30.0 fps（0.999×） | 1.000× | 0 次 |
| 父组件每 100ms 重渲染 | 23.2 fps（0.774×） | 0.762× | 22 次 |
| 父组件每 50ms 重渲染 | 19.4 fps（0.648×） | 0.637× | 34 次（每组连续 6× ~0.1s） |
| 同上 + `inputProps` 用 `useMemo` 稳定引用 | **30.0 fps（1.000×）** | **0.999×** | **0 次** |

### 修法

1. `backend/remotion/editor/main.tsx`：`inputProps` 提为稳定引用（带注释说明为什么不能用字面量）
   ```tsx
   const playerInputProps = React.useMemo(
     () => ({ input: rendered?.input as MultiMediaPocInput }),
     [rendered?.input],
   );
   // <Player ... inputProps={playerInputProps} ... />
   ```
   `rendered` 可空：`Player` 只在 `rendered !== null` 时渲染，故用 `as` 断言占位。
2. `backend/src/main/resources/static/index.html`：缓存戳 `v=20260918-v029ui8` → `v=20260919-v029fix1`（否则用户浏览器吃旧 `editor.js`），并 `cp` 到 `backend/target/classes/static/index.html`（本机 8080 从 `target/classes` 取静态资源）。
3. `backend/remotion` 下 `npm run build:editor`（`dist-editor/` 走 `file:` 资源 handler，**不需要重启后端**）。
