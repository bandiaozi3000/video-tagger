### 背景图连踩 4 坑（用户实测逐个暴露）
1. **`key` 保留字**：MyBatis-Plus 生成 `SELECT key,value ...` 语法错误 → 500。V16 迁移把列改名 `skey`（V15 已执行不能改 checksum，只能加迁移）。
2. **transferTo 相对路径**：`data/site/bg` 相对路径下 `MultipartFile.transferTo` 落到 Tomcat 临时 work 目录，与 createDirectories 不一致 → FileNotFoundException。修复：siteDir 构造器转绝对路径。
3. **被 bg-fx 特效盖住**：`.bg-fx::before` 不透明深色渐变（`linear-gradient(#0c0c1a,#07070f,#0a0a17)`）全屏盖壁纸。Chrome 负 z-index 又被 body/canvas 背景挡。最终层级：site-bg(z-index:1) 盖 bg-fx(0)，main/footer(2) 在壁纸上，未设壁纸时 site-bg display:none 默认霓虹照常。
4. **透明度失效**：遮罩放在容器 `backgroundColor`，被子元素壁纸盖住。改 `::after` 伪元素遮罩 + `--mask-opacity` 变量（z-index 2 在壁纸上）。puppeteer 像素验证 opacity 0.3/0.6/0.9 → 亮度 70/130/190 递增。

### 视频导出 OOM（用户实测 node 退出 134）
- 根因：`render.js` 把所有抓帧 base64 缓存内存数组、最后统一写盘 → 素材多/视频长时（上万帧 × 200KB）撑爆 node 堆（~2GB）。
- 修复：**流式写帧**——`screencastFrame` 事件里边收边写盘（`f-%05d.jpg` 顺序落盘），内存 O(1)。实测 3 部 10s 720P 渲染成功（596 帧 59.6fps 产物 806KB）。

### 其他修复
- **@Async 自调用失效**（视频导出卡死）：`VideoExportTaskService.create()` 内 `this.runAsync()` 同类自调用绕过代理 → 渲染同步阻塞 POST 30s。注入 `@Lazy @Autowired self`，改 `self.runAsync(...)`。坑与 OmofunaSyncTaskService 注释一致。

## 修复：多曲 BGM 不会播放下一条（audio loop 挡住 ended）

**问题**（用户报告）：推荐导出选多首 BGM，只播第一首，不会播放下一条。

**根因**：模板 `<audio id="bgmAudio" **loop**>` —— `loop` 属性让当前曲自动循环，**`ended` 事件不触发**，而多曲顺序播放靠 `ended → bgmIndex++ → 下一首`，永远跑不到。

**修复**（三套模板）：去掉 HTML `loop` 属性；`ended` 按曲数处理——多曲切下一首（`bgmIndex = (bgmIndex+1) % length`），单曲 JS 循环（`currentTime=0; play()`）。录制模式走定时器模拟切曲不受影响。

**验证**：curl 带 2 曲生成 HTML——`<audio>` 无 `loop`、`BGM_TRACKS.length > 1` 多曲分支 + 单曲循环就位。模板运行时读取，**无需重启后端**，已复制 target。

## 修复：多曲「即将播放」提示不显示（scheduleNext 排不准）

**问题**（用户反馈）：修复 loop 后能切下一首了，但「即将播放：下一首」提示不显示。

**根因**：原 `scheduleNext` 用 `loadedmetadata` 时的 `duration` 算 `setTimeout(duration*1000-4000)`——但 data URI 音频的 `duration` 常**迟就绪**（loadedmetadata 触发时可能为 0），`scheduleNext` 开头 `if (!(duration>0)) return` 直接放弃，之后无人补排。

**修复**（三套模板）：改为 `timeupdate` **实时检测** `updateBgmHint()`——每帧算剩余时长，剩 ≤4s 显示「即将播放：下一首」+ `.next` 高亮，否则恢复当前曲名/移除高亮。不依赖 duration 就绪时序。

## 修复：点击生成预览不生效（`let` 声明在 init 调用后的 TDZ 中断整个脚本）

**问题**（用户报告「点击生成预览不生效」）：点生成预览按钮无反应（status 空、弹窗不开）。排查：`generateRecommendPreview` 函数本身 OK（eval 直调能出预览），但**按钮的 `addEventListener` 绑定没执行** → 脚本在底部绑定前就**中断**了。

**根因链**（TDZ）：给速度滑块加「拖拽即时重算总时长」时，`bindPreviewSlider` 的 `upd()` 里加了 `updateRecommendDuration()`（读 `recommendPreviewStructure`）。而 `initRecommendBgm`（加载时调用）内部会 `bindPreviewSlider(...)` → `upd()` → `updateRecommendDuration()` → 读 `recommendPreviewStructure`。该 `let` 声明在 `initRecommendBgm()` 调用（5351 行）**之后**（5355 行）→ **TDZ：`Cannot access 'recommendPreviewStructure' before initialization`** → 脚本在 5351 中断 → 后面所有绑定（消息监听 5357、生成预览 5433、导出 5434…）全部失效。

**定位方法**：逐段验证底部绑定哪些活——wizard 步骤绑定活（JS `.click()` 能推进）但消息监听不触发、生成预览按钮临时加监听能触发但原绑定不触发 → 二分出中断在 init 调用段；逐个 `window[fn]()` try/catch → `initRecommendBgm` 抛 TDZ。

**修复**：`let recommendPreviewStructure = null;` **移到所有 init 调用之前**（带注释警示）。验证：点生成预览 → 弹窗开 + 时长 5:51 显示 ✓。

**教训**：**`let`/`const` 声明必须放在引用它的所有 init 调用之前**，否则加载时经 init→工具函数→读该变量的链路会 TDZ 中断整个脚本（这类间接引用 grep 直接找"函数内引用"找不到）。
