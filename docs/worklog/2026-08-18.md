## Web 连 MySQL 的方言修复（标签添加 / 标题搜索）+ @MapperScan 找回

**现象**：用户 IDEA + MySQL profile 跑 web，标签添加报 `SQLSyntaxErrorException`（`INSERT OR IGNORE`），标题搜索无效。

**根因**（三类，读码+字节码+git 历史验证）：
1. **`INSERT OR IGNORE`（SQLite 语法，MySQL 不认）**：9 处（Tag/ClipTag/MediaTag/EpisodeTag/MediaCollection mapper）→ 标签添加炸。
2. **`||` 拼接（SQLite=拼接，MySQL=逻辑 OR）**：25 处（Clip/Media/Tag/Episode mapper）→ `LIKE '%' || #{q} || '%'` 在 MySQL 变 `LIKE ('%' OR q OR '%')` → 搜索无效。
3. **`@MapperScan` 在 commit `0e61af8`（7-21）被删**：mybatis-plus 3.5.7 自动扫描**只认 @Mapper 注解**（字节码实锤 "Searching for mappers annotated with @Mapper"），mapper 无 @Mapper 靠自动扫描注册一直悬着，某次构建后彻底不注册 → 应用起不来（`No qualifying bean ClipMapper`）。**恢复 `@MapperScan("com.videotagger.mapper")` 后秒好**（测试注释也印证主类本该有）。

**修复**：
- 新增 `config/MybatisConfig.java`：`VendorDatabaseIdProvider`（SQLite→sqlite / MySQL→mysql）；mybatis-plus 3.5.7 auto-config 确认支持该 bean（反编译看到 `setDatabaseIdProvider`）。
- 5 个标签 mapper 的 `INSERT OR IGNORE` 改 **`@Insert(databaseId="sqlite"/"mysql")` 双语句**（SQLite=INSERT OR IGNORE / MySQL=INSERT IGNORE）。**不用 `<script>`**——测试发现 `<script>`+`_databaseId` 方案疑似破坏 mapper 注册，`databaseId` 属性更干净。
- `||` 改 **`CONCAT()`**（sqlite-jdbc 3.45 支持 CONCAT，两库通吃，无损）。
- `VideoTaggerApplication` 恢复 `@MapperScan("com.videotagger.mapper")`。

**验证（双库端到端，全绿）**：
- SQLite（8800 scratch 库）：标签添加 `{"id":1}`、重复幂等 400、搜索无报错 ✅
- MySQL（docker vt-mysql 隔离库 `video_tagger_test`，8801 + Flyway V1~V19）：标签添加 `{"id":1}`、重复幂等、**标题搜索 `q=方言` 命中 `{"id":2,"title":"方言测试番剧2"}`** ✅
- 测试库已删、测试后端已停、临时文件已清
- **顺带发现**：`POST /api/media` 不传 status 会 NPE（`STATUSES.contains(null)`，MediaService.apply:335）——测试请求问题，UI 总会带 status，未修

## 重新打包 0.1.1 完成（内置 Chrome 版）+ 重要洞察

**结果**：`release/video-tagger-desktop-0.1.1.zip`（478,426,975 字节，3959 条），zip 内 `VideoTagger\resources\chrome\chrome.exe` 已确认在包（chrome.exe 本体 3MB 压缩，大体积在 chrome.dll/locales 等）。比 0.1.0（509MB）还小——内置 chrome 内容压缩率高 + 0.1.0 含冗余 data。`mvn package` 用的是含 omofuna watchdog 加固 + 日志的新 jar。

**打包踩坑**（已入记忆 desktop-pack-bat-run-gotchas）：git-bash 跑 pack.bat 用 `MSYS_NO_PATHCONV=1 cmd /c "绝对路径"` + `< /dev/null`；`cmd //c pack.bat` 找不到文件（cwd 不生效）、`cmd /c "cd /d..."` 的 `/d` 被 MSYS 转换搞坏。

**重要洞察（用户提问：视频导出成功但同步超时，差异在哪）**：
- 两者 launch 机制完全相同（同 chrome 路径、同 headless=new、同 --no-sandbox）
- **差异 = 超时 watchdog 不对称**：omofuna launch 有独立 **60s 硬超时**（omofuna.js `LAUNCH_TIMEOUT_MS=60_000`）；视频导出**无 launch 级 watchdog**，只有总渲染超时 **40min**（RecommendVideoService `RENDER_TIMEOUT_SECONDS=40*60`）
- 慢机器 launch 61~90s → 同步 60s 就放弃报"Chrome 启动超时"，视频导出会等到成功 → 两者同时成立
- 次要差异：同步 launch 后 goto 外网+反爬验证页（卡住报"无进度超时"），导出 goto 本地 file://（秒开）
- 内置 Chrome 131 launch 实测秒开 → 这条不对称基本消失；**可选加固：LAUNCH_TIMEOUT_MS 60s→120s**（待用户拍板）
